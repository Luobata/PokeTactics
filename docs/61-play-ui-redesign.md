* **棋盘永远是主舞台**：1280×760、1440×900、390×844、844×390 下，棋盘、备战席和开战按钮都在首屏内（实测：笔记本备战席底边 759/760；手机 `scrollHeight` = 844，改版前 6260）。
* **HUD 贴着棋盘**：回合/阶段、生命、金币、等级+经验（含 `约 N 金升级`）、人口、连胜/连败；地形、指令、模拟、选秀等状态芯片放在棋盘顶条（横屏手机整条顶条移到棋盘右侧的场景区，见 docs/68），点击芯片直接打开对应面板。
* **入口坞**：桌面竖排在最右侧、紧贴抽屉外沿（docs/68，原先在棋盘左侧），横屏手机是右侧竖栏，竖屏手机是固定在底部的标签栏。每个入口带徽标：
  | 入口 | 面板内容 | 徽标 |
  |------|---------|------|
  | 商店 | 商店卡、锁定/刷新/购买经验、按属性定向刷新 | 买得起的卡数 |
  | 背包 | 战利品、定向组件补给、道具（装备/合成/拆解/出售） | 待领组件 `N!`（强调）或道具数 |
  | 强化 | 待选技能强化列表、海克斯 / 技能学习 / 本局研习 / 挑战成长、联动检查、图鉴入口 | 待选海克斯 + 待选技能强化 `N!` |
  | 羁绊 | 羁绊列表、深度断点、羁绊任务（含上一战触发情况） | 已激活羁绊数 |
  | 对手 | 开战威胁预测（首个目标、前 5 秒承伤、倒下次数、说明）、训练家排行、全场阵容入口 | 可能倒下 `N!` / 被 ≥3 名敌人锁定 `⚔N` |
  | 指令 | 地形说明、战术指令（每项附本轮提示）、模拟对战与结果 | 剩余模拟次数 |
  | 战报 | 上轮战果、本局战报、生涯小计、日志、重开 | 已记录战报数 |
  | 开始战斗 | 有待选海克斯时变为橙色并打开「强化」面板 | — |
* **面板**：桌面是入口坞左侧的抽屉（与棋盘并排，抽屉打开时仍可拖拽、点选棋盘）；761–960px 宽的平板为悬浮抽屉；手机是底部弹层，有 `peek / half / full` 三档，拖动把手或点 ⌃ 切换，下滑到底关闭，Esc 也可关闭。弹层不加遮罩，打开时仍能操作棋盘。
* **商店**：桌面抽屉里一行一张卡；手机弹层默认 `peek` 高度，按「备战席底边 → 标签栏顶边」实测计算，商店卡横向滑动，购买后无需关闭即可点备战席、再点棋盘上场。
* **选秀**：待选时自动弹出（桌面居中卡片，手机底部弹层，8 个选项一屏放下）；「稍后再选」本轮不再自动弹出，棋盘顶条的「选秀待选」芯片可随时重开；未选择时开战仍按规则自动拿第一项。
* **选中操作条**：点精灵后在棋盘上方出现操作条（名字、星级、角色、射程、装备、威胁/前 5 秒承伤），按钮直接复用原有 `data-*` 动作：`详情`、`技能强化 N`、`设为/取消核心`、`卸装`、`出售 +N`、`×`。选中商店卡时显示「招募 · N 金」或「还差 N 金」；选择装备后提示「点选精灵装上」。

## 3. 场地视觉

* 地面：格子用 CSS 渐变做出棋盘格明暗、细小斑点纹理和凸起倒角（内侧高光 + 底部阴影）；敌方半场暖砂色，我方半场冷青色，中线是发光的金色分隔线和 VS 徽章。
* 排标签：我方 `前排/中排/后排`，敌方 `后/中/前`（敌方第 2 行贴近中线，是前排）。
* 地形（`state.depth.terrain.id` + `cells`，只作用于我方格）：
  * `highland` 高地：灰色石台，抬高 5px 并带崖面阴影，空格显示 ▲；
  * `mana_spring` 魔力泉：蓝色发光水面 + 涟漪动画；
  * `brambles` 荆棘：深绿底 + 四周刺状边缘 + 红色浆果点；
  * `sanctum` 圣域：金色地面 + 旋转的圆环符文微光；
  * `swamp` 沼泽：泥色地面 + 掠过的油光与气泡；
  * `embers` 余烬：橙红发光 + 上升火星动画。
  所有动画在 `prefers-reduced-motion: reduce` 下关闭。
* 场景边框：沿用原森林 SVG（树、灌木、岩石、花）作为棋盘外围，加暗角，棋盘本身是带木/石边框的「擂台」。
* 选中我方棋盘上的精灵：按曼哈顿距离（与战斗一致，`sim/combat.py`）高亮敌方射程内的格；同时根据 `state.depth.threat` 用红色虚线箭头连出「开战首先攻击它」的敌人。鼠标悬停 / 键盘聚焦敌方精灵时显示它的首个目标；「对手」面板里有「在棋盘上显示全部连线」开关（触屏无需悬停）。
* 棋子标记：左上星级（金色描边）、上方核心皇冠 ♛、右下装备圆点 ◆、左下角色色点（红攻 / 蓝防 / 绿辅）、右上 `⚔N`（被几名敌人首攻）、底部前 5 秒承伤条（≥50% 橙、可能倒下红色并带 `!`）、待选技能强化 `?`。
* 拖拽时所有可放置的空格与空备战席显示虚线高亮。

## 5. 手机与触屏准则

1. `viewport-fit=cover`，标签栏、弹层、战斗弹窗都加 `env(safe-area-inset-*)`。
2. 触控目标 ≥ 44px：入口坞按钮 50px、弹层按钮 44px、操作条按钮 40px 高、HUD 芯片和工具按钮用透明 `::after` 扩大到 44px 命中区。（例外：手机棋盘格约 51×40px，见第 8 节。）
3. 不依赖悬停：所有 `title` 信息都有可点击的替代——选中操作条、详情弹层、对手面板的威胁列表和「显示全部连线」。
4. 手机格子宽高分离（`--tile-w`/`--tile-h`）：宽度按屏宽，高度按「首屏还要留给备战席和 ~200px 商店弹层」计算，因此棋盘、备战席、开战按钮和打开的商店能同时出现在一屏。
5. 横屏手机（高 ≤ 520px）：场景内 HUD，详见 `docs/68-scene-layout.md`。
6. 战斗弹窗在手机上全屏（无圆角、无外边距），画布占满宽度，「下一轮」所在的底栏吸底；横屏时隐藏比分栏，画布按高度缩放。
7. 吐司提示在手机上从顶部出现，避免挡住标签栏和弹层。
8. 安装为网页 App（全屏）、防熄屏、震动、音频解锁与真机 E2E 见 [docs/72](72-mobile-pwa-preview.md)。

## 7. 如何新增一个入口 / 面板

1. 在 `play.html` 的 `#drawer-body` 里加一个 `section.drawer-panel`：`data-panel="xxx"`、唯一 `id`、`hidden`；需要的内容直接写静态 DOM，并给需要渲染的容器起 id。
2. 在 `#stage-dock` 里加一个按钮：`class="dock-button" data-open-panel="xxx" aria-controls="stage-drawer" aria-expanded="false"`，内含图标 `<svg><use href="#i-…"/></svg>`、文字 `<span>`、徽标 `<b class="dock-badge" data-badge="xxx" hidden></b>`。新图标加到页首的 `<symbol>` 库。
3. 在 `play_layout.js` 的 `PANELS` 里登记标题；如需徽标，在 `renderBadges()` 里调用 `setBadge("xxx", 值, 是否强调)`（`0`/空值自动隐藏）。
4. 渲染逻辑放在拥有数据的脚本里（经典规则放 `play.js`，arena_v2 深度内容放 `play_depth.js`），用 `data-*` 属性 + 文档级委托处理点击，不要在布局层调用 API。
5. 任何地方都可以用 `<button data-open-panel="xxx">` 或 `PlayLayout.open("xxx")` 打开面板；手机上默认 `half` 高度，商店为 `peek`。
6. 在 `tests/frontend/play_layout_presentation.js` 的 `PANELS` 列表和相关场景里补断言；如果新 id 由脚本通过 `$("…")` 查找，`ids` 场景会自动检查它存在于页面。

## 8. 验证与已知限制

* 测试：`tests/test_play_layout.py`（新，8 个前端场景 + 离线/安全区静态检查）、`tests/test_play_page.py`（新增资源 MIME 检查）、`tests/test_portal.py`、`tests/test_battle_report_presentation.py`、`tests/test_battle_playback_presentation.py`、`tests/test_core_build_catalog.py`、`tests/test_animation_preview_frontend.py`。
  已知失败与本次无关：`continuous_forward_playback`（main 上即超时）；`battle_report_presentation.js metrics`（main 上同样失败：断言仍期待 `/demo/sprite/…`，而 docs/60 后默认 PMD 缩略图）。
* 手机端到端流程（390×844，新开局）：选海克斯 → 打开商店 → 预览并从操作条招募 → 再点卡片购买 → 点备战席 → 点棋盘上场 → 开始战斗，全程 `scrollY = 0`，每个点击目标都在视口内。
* 已知限制：
  * 手机竖屏棋盘格约 51×40px，高度略低于 44px 触控建议（为了让商店弹层与备战席同屏）；更高的手机会自动变大。
  * 手机上没有触屏拖拽（HTML5 拖放在触屏不可用），布阵用「点精灵 → 点格子」。
  * 平板（761–960px）抽屉是悬浮层，会盖住棋盘右侧一部分。
  * 「追加 10 场」判断依赖客户端签名，刷新页面后第一次按钮可能显示「模拟对战」但服务端仍会追加样本。
  * 选中精灵时操作条覆盖棋盘顶条（对手名、芯片、全场阵容），取消选择即恢复。
