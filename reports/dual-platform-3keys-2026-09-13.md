# 方向修正 · 双端同源与三键约束 · 2026-09-13

**需求变更**（用户补充）：核心设计增加 Web + 设备（ESP32）**两端同步调试**与
**渲染保持同步**；输入只有 **ABC 三键**。本报告记录由此推翻与新增的设计条款。

## 推翻了什么

- 初版宪法硬约束「不进 ESP32（三键做不了摆位交互）」——**作废**。
  重新评估后自走棋对三键反而友好：战斗阶段零输入纯观战，操作全部集中在
  准备阶段，而单机模式可用「C 确认开战」推进、不限时。
- 初版里程碑 M4「表现层选型（Web Canvas 先行）」——改为**双端架构落地**：
  同一份 C 内核编译为 ESP-IDF 固件与 Web 同源预览（M4/M5 拆分见头脑风暴 §11）。

## 继承的 PokeWalk 成熟方案（不重新发明）

1. **固件同源预览**（PokeWalk docs/12）：浏览器 → 本地 server → native 进程
   编译真实固件 C 代码 → LCD 替身收 RGB565BE 字节流 → Canvas.putImageData。
   浏览器不自行计算布局/字体；一致性用 RGBA SHA-256 逐帧对账（848 次对照先例）。
2. **三键六事件体系**（directional-controls-2026-09-10）：A=上、B=下
   （长按 600ms 返回）、C=确认；PRESS/RELEASE/CLICK/DOUBLE/LONG/END 六事件，
   Web 侧 A/B/C 与 ↑/↓/Enter 双映射。
3. **解算器参考实现惯例**（PokeWalk sensing.py）：Python 写法需可移植到
   C（定长状态、免动态分配、慎浮点）。

## 本轮落地

1. **宪法重写**（docs/01-constitution.md）：新增双端目标、240×320/无整帧缓冲
   （棋盘 ≤7 列）、三键六事件、C 可移植、单机 vs 7 bot 模式五条硬约束；
   新增条款 2.5 同源渲染验收（像素对账）、2.6 渲染同步契约（事件流）。
2. **事件流契约进代码**（sim/combat.py）：`Battle.events` 输出
   `(t, deploy|move|attack|cast|die|end, ...)`；`sim/prototype.py` 增加
   `-v` 事件时间线打印与**同种子确定性自检**（当前通过）。
   事件流字段即双端接口，后续变更需同步两端（宪法 2.6）。
3. **头脑风暴新增 §9/§10**：双端架构图与屏幕适配账（7 列×32px=224px≤240px，
   当前 sim 棋盘 7×6 恰好兼容；素材候选 GSC 菜单图标约 32×32，尺寸待核对）；
   三键页面模型表与棋盘 2D 光标三方案（倾向 γ：单击上下/双击左右/C 拿起放下）。
4. **模式裁定**：设备无对战网络 → 单机锦标赛（玩家 + 7 机器人训练家），
   机器人买入 AI 从平衡工具升级为玩法内容（M2 验收标准随之提高）。

## 顺带发现

- 贪心寻路震荡：远程单位会在射程边缘来回抖动（示例局比比鸟在 (0,0)/(0,1) 间
  往返）。S1 定稿换 BFS 或加入「在射程内不再移动」的滞回，已列入 S1 议题。

## 验证

```sh
python3 sim/prototype.py --games 300 -v   # 确定性自检通过 + 事件流时间线可见
```
