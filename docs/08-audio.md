# 08 · 音频系统（概念定稿，2026-09-13）

状态：**概念定稿稿**。音频是当前体验层最后一个空白（美术/布局/节拍表已定稿于
docs/02）。本文回答四个问题：事件流怎么变成声音、音乐用什么曲子、混音与设置
怎么管、双端怎么共用同一个混音器。系统编号由 systems/README 主线统一登记，
本文不占用 Sxx。

**总纲一句话：音频 = 事件流的另一个回放器**（宪法 2.6 同源逻辑的延伸）。
解算器吐事件，渲染端画画，音频端出声——三者挂在同一条事件游标上。
同种子 → 同事件流 → 同画面 → **同音序触发序列**，可离线对账。

方法论与工程先例全部继承 PokeWalk 音频链（docs/systems/S13-audio.md、
firmware/main/audio.c + audio_settings.c、assets/music_sources.json），
本文只做裁定与增量设计，不重复论证已验证结论。

## 1. 路线裁定：实时 chiptune 合成，不是采样播放

ESP32-C3 **无内置 DAC**，且实测可用堆仅 ~231KB（宪法 §1）——两条路都指向
PokeWalk 已验证的结论：**CPU 实时合成 GB 风格四通道（方波×2 / 波表 / 噪声），
输出 22050Hz 单声道 PCM16，I2S + ES8311 通路**。

| 项 | 音序数据 | PCM 采样 | 依据 |
|---|---|---|---|
| 11 条音效 | **164 B** | 150 KB | PokeWalk 实测：省 **938 倍** |
| 17 首金银曲目 | **~32 KB**（7950 音符 × 4 B/音符） | 分钟级 PCM，兆字节 | music_sources.json 实数 |
| CPU | 4 通道 @22050Hz ≈ **1.65%**（同款芯片实测口径） | 解码+DMA 更重 | S13 §13.2 |
| RAM | 混音器状态 + DMA 缓冲 2~4 KB | 整曲装不下 231KB 堆 | — |

音序格式沿用 PokeWalk `note_t`（midi / duration / duty+env / volume，4 B/音符），
包络照 GB 做「线性步进」，**无 ADSR**——干脆感是风格的一部分。

**flash 合计预算 < 40 KB**（17 曲 32KB + SFX 音序 ~25 条 × 平均 12 B + 合成器
代码），对 8MB 是零头，与美术 ~410 KB（docs/02 §1.2）相加仍不足 6%。

## 2. 音效层（SFX）：事件 → 音效映射表

### 2.1 频率事实（设计限流的依据）

200 场 6v6 随机阵容实测（seed 20260913，sim/combat.py 现行为）：

| 量 | 读数 |
|---|---|
| 战斗时长中位 | 7.5 s |
| attack / move / die / cast / regen（均值/场） | 49.6 / 39.0 / 8.8 / 2.4 / 10.9 |
| attack 密度峰值 | **中位 11 次/s，最大 14 次/s** |
| 可听事件（attack+move+cast+die）峰值密度 | 中位 28 次/s |

结论：**只有 cast/die 少到可以逐发全额配音**；attack 必须限流，move/regen
根本不进音轨（否决理由见 §6）。限流三条规则：

1. **同类合并窗**：同类 SFX 在 120ms **观感时间**窗内只发第一声
   （窗按回放时钟计——倍速下观感密度不随倍速上升）；
2. **优先级顶替**：cast > 拔群 > die > status-apply > attack；
   低优先级正在占用的声部被高优先级复位重触发（GB 单声部 retrigger 语义）；
3. **音量与触发频率成反比**（PokeWalk 实测定律：menu 音 RMS 0.042 最轻，
   因为它被按几万次）——普攻音是本作最常触发的战斗音，必须最轻。

SFX 声部：混音器在 BGM 3~4 声部之外留 **SFX 专用 2 声部**（方波 + 噪声），
SFX 触发时 BGM duck 至 1/3、~93ms 淡入淡出（PokeWalk 数值直用）。
音效时长纪律：普攻 ≤60ms，其余 100~430ms（GB 区间，PokeWalk 先例）。

### 2.2 战斗事件映射表（事件流 kind → 音效）

事件元组见 sim/combat.py / sim/status.py；`cast` 事件自带招式名、
克制倍率（`round(eff,2)`）、伤害（0 = 未命中）——音频端零判断、纯查表。

| 事件 | 音效 | 时长 | 规则 |
|---|---|---|---|
| `deploy` 首条 | 开战横幅：短号角双音上行（新编，encounter 风格） | ~240ms | 挂**阶段开始**（第一条 deploy），12 只单位 t=0 同刻不逐只发 |
| `move` | 无 | — | 不配音（39 次/场、零信息量） |
| `attack` | 普攻轻击 tick：低音方波 + 短噪声（新编） | ≤60ms | 合并窗 120ms；音量全场最低档；4x 下整体静音（§3.3） |
| `cast` 发射 | 大招音：按**属性音色档**着色（§2.3）+ 蓄力上滑引子 | ~300ms | 2.4 次/场 → 全额播放、最高优先级；与特写切镜（§4.2.3）同步起 |
| `cast` 命中变体 | 落空（dmg=0）：哨音下滑，对应金银「避开了」演出 | ~200ms | 查事件字段，不猜 |
| `cast` 克制 | 拔群（eff≥2）：金属高音 ding 一枚（新编）；效果不佳（eff<1）：闷音 | ~120ms | 与红/白伤害数字、「效果拔群」弹字同一触发点 |
| `die` | 濒死下滑音（新编：evolve 上扫频的镜像） | ~120ms | 8.8 次/场，全额播放 |
| `end` | 胜负横幅 pop 一声，随后 BGM 切结算曲（§3.1） | ~90ms | `end` 事件带 winner，胜/负用不同音高 |
| `regen` | 无 | — | 10.9 次/场每秒一跳，节拍器效应；治疗由绿色数字表达 |
| `status` apply | 控制类（冰冻/睡眠）重短音；DOT/增益类轻 tick | 60~150ms | 只有 apply 档配音；tick/expire 不配 |
| 能量满预告 | 无 | — | 视觉已有（底座环呼吸，§4.6）；提前响会剧透下一拍 |

### 2.3 大招属性音色：9 档参数化，不是 17 条音效

PokeWalk 先例：技能命中音「按 15 属性着色，属于项目设计而非原版 SFX 移植」。
本作照搬并收敛到 **9 个音色档**——与 docs/02 §4.9 的特效图形分组同构
（观众听觉认属性 = 视觉认属性，一套分组两感一致）：

| 音色档 | 属性 | 音色语言（方波/占空比/扫频/噪声配比） |
|---|---|---|
| 高频颤 | 电 | 高音区 + 快速音高抖动 |
| 噪声爆 | 火 | 噪声占比最高 + 短爆裂 |
| 下滑泡 | 水 | 双音下滑（泡泡感） |
| 拨弦 | 草/虫 | 短促弹拨，占空比 25% |
| 纯正弦感 | 超 | 波表声部、无棱角 |
| 低呜 | 幽灵/毒/恶 | 低频 + 慢颤 |
| 清脆 | 冰 | 高音短击、快衰减 |
| 打击闷响 | 斗/岩/地/钢/普 | 噪声 + 低频冲击（attack 音的加重版） |
| 上滑扫 | 龙/飞 | 长上扫频（与 travel 特效同步） |

17 系 → 9 档查表；每档是一条参数化模板，非独立作曲。招牌招独立音色
（十万伏特专属音等）与视觉侧「招牌招独立演出」同为 M4+ 项。

### 2.4 UI 音（准备阶段与三键）

UI 音挂**动作结果**（页面状态机确认的迁移），不挂原始键事件——A/B 长按
连发时不会出现音墙；只有 CLICK/LONG 语义事件可触发。

| 动作 | 音效 | 来源 |
|---|---|---|
| 光标移动（A/B CLICK） | `menu` 24ms 极短轻击 | **PokeWalk 直用** |
| 确认（C CLICK） | 短 pop | PokeWalk `care` 变体 |
| 返回（B LONG 600ms） | 低双音 | 新编（`escaped` 风格收敛版） |
| 购买成功 | 上行分解和弦 + 金币叮 | **PokeWalk `caught` 直用** + 新编叮声 |
| 金币不足/无效操作 | 下行两音，刻意不刺耳 | **PokeWalk `escaped` 直用** |
| 卖出 | 金币叮双音（倒序） | 新编 |
| 刷新商店 | 快速滚音（扫频下行） | **PokeWalk `ball_throw` 变体** |
| 升级人口/喂经验 | 短上行四音 | **PokeWalk `level_up` 直用** |
| 利息到账（回合结算） | 轻双 ding | 新编 |
| 三合一合成开始 | 长上扫频 900ms | **PokeWalk `evolve` 直用** + `evolution` 曲 |
| 羁绊档位跳升 | 四音琶音 | **PokeWalk `rare` 直用**（同为项目自编、无版权负担） |
| 玩家淘汰 | 低钟音 | 新编 |

规模小结：**直用 PokeWalk 9 条 + 新编 ~10 条**，全部为音序数据，
合计 < 0.5 KB。

新增裁定与理由：
- **天气不换曲**（环节 3）：17 曲无天气变奏；换曲认知负担 > 情绪收益
  （与「每人格专属 BGM 否决」同族）。天气是**规划信号**（docs/05），
  stinger + HUD 图标足够；四档 stinger 复用 §2.3 音色档语言
  （晴=清脆、雨=下滑泡、沙=打击闷响、雹=高频颤）。
- **决赛圈提前到准备阶段**（环节 6）：原表只在战斗切 championbattle，
  决赛圈的准备阶段（最后的买棋/摆位决策）才是情绪顶点——提前切曲
  让「这是最后一搏」在读秒时就被听见。
- **失败不换曲**（环节 10）：17 曲无败北曲（§5-3 开放问题维持），
  常规失败立即切曲反而打断节奏；只有淘汰（环节 11）值得用静默标记。
- **濒死每局只响一次**（环节 5）：濒死是状态不是事件，反复掉进 30 以下
  会把预告变成噪音。

### 3.2 来源边界与同人声明（继承 PokeWalk 纪律）

1. **金银原曲 = pokecrystal 音序提取**，非录音、非 MIDI 转写：音符顺序、
   声部循环、占空比、定点帧时长保真；适配声明原文有效——「单声道合成；
   波表声部用三角波、噪声鼓为合成鼓组、非逐周期 GB APU 还原」。
   逐曲哈希与 commit 锁定在 music_sources.json，本仓库引用不改数；
2. **SFX 全部项目自编**（PokeWalk 同裁定：原版 SFX 是硬件寄存器脚本，
   无提取链）——不声称为原作内容，也不声称可分发；
3. 分发边界沿用 PokeWalk docs/05 §5.4：当前自用不分发，许可义务不触发；
   **一旦分发，曲目与精灵图同为不可事后合规项**，届时须整体换原创曲。

### 3.3 倍速与 BGM/SFX 的关系

观战倍速（默认 2x，A/B 切 1x/2x/4x/跳过，docs/03 §1）是**回放属性**，
不是音乐属性。裁定（PokeWalk 先例「音乐按真实音序时长运行」的对称推广）：

| 倍速 | SFX | BGM |
|---|---|---|
| 1x | 全量（限流窗内） | 恒速 |
| 2x | 限流窗按观感时间收效 | **恒速、不变调** |
| 4x | 普攻 tick 静音；仅保留 cast/拔群/die | 恒速（轻量化见开放问题 §5-4） |
| 跳过 | 全静 | 立即切结算曲 |

SFX 时钟 = 事件回放时钟（60ms 步进时钟的倍速版）；BGM 挂墙钟走真实音序
时长。跳过 = 游标瞬移到 `end`，音频端只收尾。

## 4. 混音与设置

| 项 | 裁定 | 依据/先例 |
|---|---|---|
| 轨道 | **BGM / SFX 双轨独立音量** 0~100，步进 10，0 = 该轨静音 | 自走棋「听音效关音乐」是高频需求 |
| 持久化 | NVS 独立键（namespace 各自 `bgm_vol`/`sfx_vol`），写成功才改运行态，读失败回默认 | PokeWalk audio_settings.c 模式（默认安全） |
| 默认值 | BGM 55 / SFX 70 开声（开放问题 §5-2） | PokeWalk 默认静音是陪伴设备属性，本作是主动游戏 |
| 存档联动 | 音量偏好**独立于对局存档**，不改存档结构 | PokeWalk 先例：偏好不影响队伍与进度 |
| 熄屏（C LONG） | 关 codec、清 SFX 队列、BGM 停；唤醒按偏好恢复。本作熄屏 = autosave 挂起整局，**无任何音频例外**（比 PokeWalk 遇敌提示例外更简单） | S13 硬件静音开关先例 |
| 混音纪律 | 只在越界时缩、不无条件归一化；去直流（12.5% 占空比方波直流 −0.75）；包络无 ADSR | S13 §13.4/13.5 实测教训 |

设置入口：现有设置页线性列表加两行「BGM 音量 / SFX 音量」（A 加 B 减 C 完成，
边界不循环——三键范式照搬，不新增按键语义）。

## 5. 双端音频路径（同源宪法的音频版）

```
sim/combat.py 事件流（确定性）
        │ 同一条事件游标
   ┌────┴─────┐
 渲染端(帧)    音频端(PCM 块)
   │              │
   │        C 混音器（sound_mixer 同款：BGM 3~4 声部 + SFX 2 声部）
   │           ├─→ 设备：I2S DMA → ES8311 → 扬声器
   │           └─→ Web：同一 PCM 块经预览通道 → 浏览器 AudioContext 排队播放
```

1. **一个混音器，两个出口**：内核每 60ms 时钟产 PCM 块；设备走 I2S，
   Web 预览把**同一份 C 混音器输出**送浏览器 AudioContext——**不写 JS 合成器**
   （PokeWalk firmware.html 已裁定先例：网页只传输混音器数据）；
2. **浏览器策略**：默认不播（自动播放限制 + 先例），预览页「试听」开关与
   游戏内音量非零同时满足才出声；`document.hidden`/暂停/熄屏 → suspend +
   清排队音频；
3. **对账验收**（像素对账的音频版）：native 混音器逐块 SHA-256 == 预览收到
   的字节流；触发序列对账 = 事件流 + §2 映射表 → 预期 SFX 触发清单，
   同种子可离线重放（verify_firmware_audio.js 的 mock AudioContext 计数法 +
   verify_audio.py 的 peak/dc/RMS 逐条比对法均为现成先例）；
4. 预算汇总：flash <40KB；RAM 2~4KB；CPU ~1.65% + 每事件 O(1) 查表分发。

## 6. 被否决的方案

| 方案 | 否决理由 |
|---|---|
| PCM 采样音效/音乐 | 938 倍体积差（164B vs 150KB 仅 11 条音效）；分钟级 BGM 的 PCM 在 flash 与 231KB 堆上都不可行 |
| Web 独立 JS 合成器 | 两套实现必然漂移，违反同源宪法 2.5/2.6；PokeWalk 已用「只传 PCM」解掉此题 |
| 倍速变调/加速 BGM | 音序器无任意速率路径；变调毁占空比音色；倍速是回放属性不是音乐属性 |
| 提取原版金银 SFX | 原版 SFX 是 GB 硬件寄存器脚本，非音符数据，提取链不存在；PokeWalk 先例即自编 |
| `move` 事件配音 | 39 次/场零信息量，与普攻音叠成噪声墙 |
| `regen`/`status tick` 逐跳配音 | 每秒一跳 × 多单位 = 节拍器效应；治疗/DOT 已有绿紫跳字（docs/06 §3） |
| 独立 mute 第三开关 | 双轨音量归零即静音；三态同步徒增设置复杂度（PokeWalk 单轨才需要 mute+volume 两键） |
| 大招切镜专属短曲 | 切镜 0.8~1.2s 短于切歌淡入淡出；duck 至 1/3 已足够让位 |
| 每对手人格专属 BGM | 17 曲撑不起 8 人 × 阶段的矩阵，换曲认知负担大于情绪收益 |
| 语音/环境长音效 | 越出 GB 四声道风格（= 本作音频身份），预算与听感双输 |

## 7. 落地顺序

1. **sim 侧（纯 PC，先行）**：事件 → 音效映射表参考实现 + 离线触发对账
   （sim/ 纯标准库，宪法不变）；新编 ~10 条 SFX 的音序数据（4B/音符格式）；
2. **PC 验收**：离线 PCM 逐条 peak/dc/RMS 比对、限流窗行为、倍速稀释规则
   （verify_audio.py 先例）；
3. **M4 C 内核**：混音器/音序器移植（PokeWalk sound_mixer.c 直搬）、
   音频端挂上事件回放游标；
4. **BGM director**：§3.1 场景表 + duck + 淡入淡出（music_director 先例）；
5. **设置与持久化**：双轨音量页 + NVS + 熄屏联动；
6. **真机实听**：扬声器频响（低音可能整体听不见，S13 §13.9 同题）、
   音量梯度、4x 听感、音频常开对续航的影响。

## 8. 开放问题

1. 扬声器通路（PWM vs I2S+ES8311）与 PokeWalk 硬件是否同款——决定
   audio HAL 可否直搬；
2. 默认开声还是默认静音：本作是主动游戏会话（倾向默认 BGM 55/SFX 70），
   但「掏出来就在公共场合」的场景仍在——真机首响后定；
3. 失败/淘汰无金银原曲可用（17 曲无败北曲）：新编低音短句 vs 纯静默 +
   下滑音，待实听；
4. 4x 下 BGM 是否切「仅鼓组声部」轻量版（音序天然分声部，技术零成本，
   听感待验）；
5. 普攻音是否按攻击手体型/费用档微调音高（提升可读 vs 变吵，A/B 实听）；
6. 决赛圈情绪阶梯只有 `championbattle` 一档上限，是否值得新编 1 首
   原创决赛曲（先不做：曲库够用，且新编曲要过「不违和」这关很难）。
