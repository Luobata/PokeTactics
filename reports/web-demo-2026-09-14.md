## 1. 架构与关键裁定

- **会话 = 内存 dict（uuid 键）+ 全局锁**；玩家席位（seat 0）+ 7 bot
  （人格混合 L1×3 + L2×3 + L3×1，`LINEUP[7]`，开局一次 pers 子流发牌）。
  会话上限 8（逐出最旧并清帧目录）；
- **回合循环**：准备（不限时）→ `end_prep` 服务端结算 → 掉血/淘汰 →
  `next` 进下一轮（天气按 `weather_for_round`：R6-10 晴、R11-15 雨、
  R16-20 沙暴、R21-25 冰雹）→ 存活 ≤1 或满 31 轮收官排名；
- **玩家战斗 = 解算与渲染同源**：`DemoBattleAnimation`（demo.py 内的
  适配子类，渲染器零改动）把 `BattleAnimation` 内部那次 `Battle` 换成
  `layout="back"` + 外部 battle 子流——玩家摆位真实生效（我方后排
  列表头 → combat 行 3，前排列表尾 → 行 2），帧（240×320@10fps）即
  权威战报；bot 对 bot 秒算只留结果行（与 `match._pvp_round` 同轨）；
- **配对**：直接复用 `Match._pair_up`（无重复对手优先 + 奇数席打幽灵），
  pair 子流每轮现派生，在准备期算好供 UI 展示对手快照（战斗时原样使用，
  不二次消费）；
- **与 sim 的差异**（适配层裁定，均可从 demo.py 头注索引）：
  - 玩家商店 **4 格**（docs/10 §1.2 裁定；sim `SHOP_SLOTS=5` 只读，适配层
    把第 5 格抽取后归还池）→ bot 仍 5 格；
  - 玩家备战 **6 格**（docs/10 §1.1；bot 仍 9 格）；
  - 幽灵战/野怪战也吃当轮天气（match 只给 PVP 主对战上天气）；
  - 渲染帧内 HUD（左上读数）是渲染层固定占位值（渲染器只读不改），
    真实读数在 Web HUD。

**动作 API**（`/api/demo/action?cmd=…&sid=…`，校验全在服务端，
错误返回中文原因、HTTP 恒 200）：`new(seed)` / `state` / `buy(i)` /
`sell(loc)` / `refresh` / `levelup` / `move(from,to)`（棋盘↔备战互移，
支持交换；`bench_to_board` 为语义别名）/ `craft(item)` / `equip(item,loc)`
/ `unequip(loc)` / `end_prep` / `next`（淘汰后 = 观战快进）。

## 5. UI（/demo 页，PokeWalk 米纸皮肤 + CONSOLE_CSS 色板）

浏览器自动化在本环境不可用（子代理无 BrowserControl），已用
node 对页面内联 JS 做 `--check` 语法校验 + DOM 桩全渲染通路验证
（36 棋盘格 / 7 精灵 / 4 商店格 / 8 排名行 / 战斗浮层 51 条事件）；
战斗画面另抽帧目检（r1 第 40 帧）：GBC 像素风正常——上下备战行、
沙/草双色战场、精灵 + 红 HP 条/金能量条、描边伤害数字（-22/-20）、
顶部 HUD、底部「战斗记录/自动战斗中……」，无白剪影/错位/黑屏。
布局（自上而下，全部中文）：

- **HUD 条**：❤HP ｜ 🪙金币 ｜ 等级(经验/升级经验) 上场/人口 ｜ 轮次
  （x/31）｜ 天气图标+效果（如 ☀️晴（火/草系招式 +20%，水系 -20%））｜
  连胜/连败 ｜ 阶段提示（准备/结算/终局）；
- **C-sym 6 列棋盘**（docs/10 §1.1）：敌方备战快照行（虚线观战格，
  显示本轮对手名）→ 敌方战场 2 行（沙色）→ 战场中线 → 我方战场 2 行
  （草绿）→ 我方备战行（6 格虚线）。棋子 = 精灵图（/demo/sprite/，40px
  源图 CSS 缩放）+ 底座属性色环（TYPE_COLORS）+「×N」同种计数（3 合 1
  进度提示）+ 持装备金环（左上「装」金徽 + 格内金描边）；
- **点击流**（无拖拽）：点棋子选中（绿框）→ 点目标格移动/交换
  （备战↔战场有人口校验）；选中后信息栏显示名/费/属性/招式/装备 +
  「卖出(+N金)」「卸下装备」按钮；
- **商店 4 格 + 动作条**：格内精灵/价格/档位，点击即买；[刷新（2金）]
  [买经验（4金 +4XP）] [开战 ▶]；错误全部 toast 中文（金币不足/备战已满/
  人口已满/此处不能放等）；
- **右栏**：羁绊面板（当前激活档高亮 + 生效效果 + 「还差 N 只到 (4)」）；
  装备仓库（组件 ×N / 可合成按钮带配方 tooltip / 成品点击进入装备态，

  [下一轮 ▶]；终局显示最终排名（冠军金色）。空场判负/轮空显示无画面说明。

## 6. 已知限制（下期清单）

1. **平衡未调**（明确单独 pass）：随机/贪心策略下玩家名次恒 8——
   bot 有羁绊定向买棋 + 3 合 1 + 场景门合成（L2+），而 demo 玩家商店
   4 格/备战 6 格（docs/10 裁定，bot 仍 5/9）再叠加一手牌差；会玩的
   人（凑羁绊/追 3 合 1/装备主 C）能显著改善，但未做数值校准；
2. **渲染帧内 HUD 是占位读数**（渲染器只读，帧内左上恒 34/13/L5）；
   真实读数以 Web HUD 为准；
3. **每场玩家战斗渲染 0.3-1s**（~80 帧 × PIL，~700KB/场落盘），
   end_prep 请求偶发秒级等待；`/anim` 的帧缓存键控机制未搬到 demo
   （会话帧不跨重启复用）；会话帧目录 ~8MB/局（上限 8 会话 ≈ 64MB，
   逐出即清，但低磁盘机器需留意 `.build/demo/`）；
4. 会话内存态：**无存档/断线恢复**（S9 下期）；服务重启即失效，
   帧目录 `.build/demo/` 随会话逐出清理；
5. 进化石合成后会因「无通信族载体」滞留仓库（驱动读数可见）；
   三色围巾等场景门只对 bot 生效（玩家自由穿戴）；
6. 幽灵战/野怪战吃天气与 match 有差异（demo.py 头注裁定 4）；
   PVE 波次对玩家的快照行只显示波次前排；
7. 商店 UI 无锁格/直购上场（备战满需先卖）；移动端窄屏未专门适配
   （cols 布局 900px 断点折叠为单列）。
