# 战斗特效与动作改造

日期：2026-10-13。接续会话「Review 战斗特效设计」；用户已要求完成方案后直接实施，并将动作、施法、前后摇的问题一并修正。

## 审查结论

原有材质库已有独立的水体、火焰和近战造型，问题主要来自上层重复叠加与动作编排，不需要把所有招式重新画成另一套风格。

| 问题 | 证据 | 改造 |
|---|---|---|
| 技能机继承原作招式威力，被判成原生大招 | `_ult_move_powers()` 混合 arena 与原作目录；雷电机器自身威力35，但原作名字可查到更高威力 | 竞技大招同时要求原生归属、威力≥75、实际敌方扣血；机器仅保留自己的局部反馈 |
| 治疗、免疫、全额吸盾也被计入全场打击反馈 | `_index_impacts()` 原先对所有 attack/cast 无条件索引 | 索引实际扣血，辅助只表现真实治疗、净化、回能或盾效果 |
| 同一技能主体上反复叠圆环、白核、碎屑 | `_draw_actions()` 的属性材质与物种图案，以及 `_draw_impact_accents()` / `_draw_ult_bursts()` 同时出现 | 原生与普攻用自身接触材质，共享强调仅用于击杀或兜底招式；重击齐射缩短为两组 |
| 普攻细线、圆圈和1.5倍图案与3px原生材质混用 | 旧普攻走 `_material()` + `_motif()` + 源/目标圆环 | 53种普攻复用各自轮廓，在整数3倍像素格上绘制，去掉诊断箭头/瞄准圈与通用属性弹体 |
| 普攻与施法的身体语言相同 | 通用姿态丢弃 action kind；部分关节曲线不读取 cast | 普攻前冲，施法后撑聚能；为既有关节补充三阶段区分 |
| 近战释放到命中只有一帧 | 旧 `travel=.05`，20Hz仅一个采样间隔 | 最短近战出手窗口改为.15秒，补接触过程 |
| 作者动作与实际命中边界不同 | MotionSystem按固有clip时长重算strike，而Web按ActionTiming切换 | 身体统一消费start/release/impact/recover_end；保留没有timeline的兼容路径 |
| 全场白/黑/白高频切换掩盖招式 | 旧三帧flash alpha 175/110/80、目标亮度最低12% | 一次暖色高光54→36→18，蓄力暗场减半，目标至少保留55%亮度 |

## 制作约束

沿用37号像素材质规范、现有角色原图与已经成立的原版参考。歌声、生命脉冲、幸福合唱分别体现音乐、生命载体和叠层合唱；电链、雷击、电球与超能切面分别按真实招式结果编排。主体要有填充面和有限色层级，辅助线用于边缘与连接。

攻击与施法的身体阶段可见，释放端仍使用角色/炮口/手臂锚点。命中、HP、护盾、治疗、位移、状态只消费权威事件；不增加受害者、玩法范围或随机数。呈现时间改变不修改模拟时钟与事件。暂停、回退、倍速使用同一渲染器。

## 验收与成果

- 新增层级负例：技能机、辅助、免疫、全额吸盾；真实HP命中才进入全场反馈。
- 普攻检查53个物种的独立轮廓、有限尾迹与单层分发；区别于逐招审美验收。
- 动作检查近战至少三个20Hz出手采样间隔、命中时切恢复、恢复结束回待机、attack/cast三阶段差异和回退一致。
- 治疗、电与超能检查轮廓、阶段编排、真实效果归属、参数与生命周期。
- 保存13个真实动作片段及三个6v6固定种子场景的前后对照，比较源事件SHA256、读数、渲染预算和帧耗时。
