# 31 · 战前准备流、奖励排队与海克斯原型设计

状态：2026-10-05 设计稿。本文只描述现状与候选，不改运行源码，不注册 `tactics_v6`，也没有实现海克斯。执行口径以 [10-prep-controls.md](10-prep-controls.md) 顶部的三键 host 修订为准；该文下方旧的双击补轴、拿起态长按卖出等段落保留为历史追溯，当前 `/device` 不是那套交互。

本文要回答三个问题：

1. 一局开始前和每个准备期，玩家实际能做哪些事；
2. 普通轮、野怪奖励后的准备期、未来候选海克斯轮分别如何排队，避免两个强制弹层互相抢操作；
3. 三键操作、事务保存、旧档兼容和学习系统扩展需要守住哪些边界。

## 1. 结论

- 当前 `/device` 的准备页已经是七项主菜单：商店、棋盘与备战、仓库与教学、羁绊、侦察与排名、开战、保存/返回主页。装备合成/使用、技能机教学、站位、护卫/天气、进化选择、卖出和侦察都有真实入口；不是 docs/10 旧稿里的“装备预留”。
- 普通准备轮没有强制玩家动作。轮开始自动结算收入、利息、连胜/连败、每轮 XP、幸运蛋收入和未锁定商店重掷；然后玩家可以买棋、移动、合成、装备、学习、升级、刷新、查看侦察，最后确认开战。
- 野怪轮 R5/R10/... 结束会自动入仓组件，并在战术远征中生成一个已冻结的教学三选一待办。下一准备期玩家必须领取一台或明确放弃；开战服务端硬门拦住未处理待办。组件自动入仓，不需要掉落页拾取。
- 候选海克斯如果按 29 号建议在 R6 首次出现，必须排在 R5 教学待办之后，不能再造成两个同时待选弹层。推荐顺序：处理教学待办 → 生成并持久化海克斯候选 → 三选一必选 → 回到普通准备动作。R6 与 `tactics_v6` 都是待验证方案，不是现行规则。
- 强力技能机器进入前，先补完整技能目录和学习资格表；准备流只预留“领取 → 学习目标 → 替换确认”的同一事务通道。不能把原作学习表直接搬进本项目，也不能把新技能当成现有六台机器的数值换皮。

## 2. 现状：局前与每轮自动动作

### 2.1 开局前行囊

只有远征和战术远征有局前行囊；经典局直接确认开始。设备首页入口为「远征」或「战术远征 · 护卫与天气」，然后依次选择主搭档、招式机器、开局装备，最后「出发」确认。选择主搭档会重置已选教学，教学列表按当前搭档过滤兼容项；未解锁项和搭档不兼容项置灰。

这些选择发生在 `Session` 创建前，属于新对局配置，不是每个准备轮动作。战术远征沿用远征预算、搭档和经济，并额外启用护卫、共享天气和教学三选一；经典与普通远征不静默升级规则。

### 2.2 每个准备期开始时自动完成

进入 Rn 时，服务端在玩家可操作前完成：

1. 更新轮次与阶段为 prep；
2. 结算基础收入、利息、连胜/连败和幸运蛋；
3. 发放每轮 XP，可能升级并提高人口；
4. 未锁店则重掷玩家和 bot 商店；已锁店保留玩家货架；
5. bot 完成当轮决策与教学/战术配置；
6. 计算 PVP 配对、幽灵来源或 Rn 野怪波；
7. 对玩家生成对手快照。PVP 快照包含对手名称、生命、等级、两行战场和备战席；PVE 显示野怪名称与波次。该快照就是本轮承诺阵容，准备期不会被暗中换成另一套。

因此玩家不需要手动“领工资”“翻商店”或申请配对。侦察页只是查看已生成信息，不消耗行动或金币。

## 3. 当前普通准备轮动作清单

准备页统一为 A 上一项、B 下一项、C 确认；长按 B 返回，长按 C 详情，C 继续长按关屏。列表每屏显示五行并可滚动。下表中的“决策数”指玩家需要选择的语义对象数量；实际按键数还随列表位置、行数和滚动变化，只能作为脚本测量，不能冒充真人三键耗时。

| 动作 | 必选/可选 | 入口与确认 | 决策内容与约束 | 状态 |
|---|---|---|---|---|
| 买棋 | 可选 | 准备 → 商店 → 商店格；普通购买无确认 | 4 格货架、价格、备战/人口、三合一；v5 若会合成先进入购买预览，可选自动进化/暂缓/取消 | 已实现 |
| 刷新 | 可选 | 准备 → 商店 → 刷新 | 2 金，保留货架不再需要锁定；刷新会解除锁店 | 已实现 |
| 锁店 | 可选 | 准备 → 商店 → 锁定/解除 | 下轮保留当前货架，手动刷新解除 | 已实现 |
| 买经验 | 可选 | 准备 → 商店 → 购买经验 | 4 金 +4 XP；人口提升允许更多上场棋子 | 已实现 |
| 移动/交换 | 可选 | 棋盘与备战 → 行 → 棋子 → 移动/交换 → 行 → 列 | 备战到空战场受人口限制；棋子互换不受人口限制；UID 跟随同一实例 | 已实现 |
| 合成装备 | 可选 | 仓库与教学 → 组件与合成 → 成品 → 确认 | 两组件变成成品，零金币；可合成列表由仓库决定 | 已实现 |
| 装备/卸下 | 可选 | 仓库 → 成品 → 棋子 → 确认，或棋子 → 装备道具 | 每实例一槽；进化石仅通信进化目标可用且触发后不可卸下 | 已实现 |
| 学习/替换教学 | 可选 | 仓库 → 招式机器 → 棋子 → 确认，或棋子 → 学习招式 | 每实例一个教学槽；属性/规则不符置灰并说明；替换需确认且旧机器返仓 | 已实现 |
| 三合一/暂缓 | 可选 | 商店购买预览，或棋子 → 进化预览 | v5 支持自动连锁预览、暂缓/锁定、只执行一步；产物先进备战再重新上场 | 已实现 |
| 护卫配置 | 可选 | 棋子 → 战术配置 → 选择护卫对象 → 确认 | 学习护卫、已上场、目标四向相邻；每队一个名额，切换会停用原配置 | 已实现 |
| 天气手配置 | 可选 | 棋子 → 战术配置 → 设为天气手 → 确认 | 学习晴天/求雨且上场；每队一名，切换会停用原天气手 | 已实现 |
| 卖出 | 可选 | 棋子 → 卖出 → 确认 | 默认停在取消；装备和教学自动返仓，卡池归还 | 已实现 |
| 羁绊查看 | 可选只读 | 准备 → 羁绊 → 长按 C 详情 | 按上场实例计数；显示当前档、距离下一档和效果 | 已实现 |
| 侦察/排名 | 可选只读 | 准备 → 侦察与排名 | 查看本轮承诺对手、棋子详情、装备/教学/特性摘要与排名；不改变状态 | 已实现 |
| 手动保存/回主页 | 可选 | 准备 → 保存/返回主页 | 成功动作本就自动保存；手动保存只增加显式提交 | 已实现 |
| 开战 | 必选 | 准备 → 开战 → 确认 | 空场额外明示将直接判负；待领教学会先被拦截 | 已实现 |

当前没有一个“每轮必须移动一次”或“必须用完金币”的规则。最小流程可以是：进入准备页 → 直接导航到开战 → 确认。若上场为空，确认文案会说明风险，但不阻止玩家空场求败。

## 4. 当前野怪奖励后的准备期

战术远征的野怪轮是 R5、R10、R15、R20、R25、R30。结算时：

- 所有存活席位获得保底装备组件，落后方还可能获得加权加发；
- 参战玩家胜利额外获得 2–3 金；
- 战术规则为每个存活席位生成一台教学机器的三选一，候选立即写入存档；
- 候选固定包含护卫；另一项优先与当前持有棋子兼容；第三项从其余有效教学中抽取；
- 组件和金币自动入账，没有独立拾取页。

因此 R6、R11、R16... 的准备期开头存在一个必选待办：仓库与教学 → 待领补给 → 选择一台入仓，或明确放弃。返回、熄屏、读档不会重抽，也不会自动选择。选择只是把机器放入仓库；是否马上教给棋子仍是普通准备动作。

当前开战硬门只拦“待领教学”。领取后机器可以留在仓库不开战前学习，这是合法选择；如果阵容没有兼容目标，玩家可以留到转型后使用，或明确放弃本轮待办。

### 4.1 奖励轮的三键流程

1. 战斗结算页按 C 进入下一轮；服务端生成 Rn+1 准备期。
2. 准备主菜单「仓库与教学」显示 `N 待领`。
3. 进入「待领补给」，选择第几轮奖励。
4. 在三个固定候选中查看兼容名单和长按详情。
5. 选择候选后确认入仓；或选择「放弃本次补给」并确认。
6. 返回普通准备动作；可立即走「招式机器 → 目标棋子 → 确认」学习，也可保留在仓库。
7. 选择开战时，服务端再次检查 pending 状态；未处理则拒绝并回到待办。

## 5. 候选海克斯轮设计（未实现）

29 号建议先做一次三选一、三个有界行为。本文把它细化为下列候选流程，但 `tactics_v6`、schema5、海克斯目录和效果注入均未实现，R6 也未裁定。

### 5.1 排队规则

R6 同时挨着 R5 教学奖励，不能把两个强制选择叠在一个弹层里。建议固定顺序：

1. R5 战斗结算完成后，先保留现有教学三选一待办；
2. 玩家在 R6 进入普通准备期，先被引导处理教学待办；
3. 教学领取或明确放弃提交成功后，若玩家存活且本局启用海克斯，立即用独立随机流生成三条海克斯候选；
4. 候选生成与存档保存处于同一事务；页面看到候选前，磁盘已有固定列表；
5. 海克斯为一次必选三选一，无跳过；选择和可选目标绑定后确认；
6. 提交成功后回到普通准备页，继续买棋、装备、站位和侦察；
7. 若断电或重进发生在候选生成后，恢复同一候选；不会重抽、不会双发；终局或淘汰时未选候选关闭并记录原因。

这个顺序让 R5 教学结果可以影响 R6 候选可用性，也避免玩家在两个强制待办之间来回跳转。代价是 R6 首屏负担最高；所以候选页必须只做三选一，不夹带普通商店或布阵操作。

### 5.2 页面与操作

建议不新增准备主菜单第八项。pending 状态复用主菜单提示和开战硬门：

- 准备主菜单用横幅或「仓库与教学」行显示「天赋 · 1 待选」，不新增第八个主菜单项；
- 进入后默认选中第一项，A/B 在三项中移动；
- 每项一行显示名称、当前可用性、关键代价和受益实例；长按 C 查看完整详情；
- C 先进入确认页，默认停在取消；确认页显示效果、绑定目标、反制条件和不可撤销提示；
- 需要指定实例的候选，确认前增加一次目标选择；目标列表只显示当前合法实例，且切换页面后按 UID 重新定位；
- 疗愈回响这类全队规则候选不额外选目标；
- 选择成功后回准备页，并在棋盘/HUD 显示一个持久标记。

首批三候选仍按 29 号：蓄势待发、余势追击、疗愈回响。它们都必须有触发条件和破坏方式，不做全队攻速/攻击/吸血的泛数值堆叠。发牌至少一项当前可用，一项通用，一项可转型；没有可用治疗来源时疗愈回响不进入候选。

候选不足是首批实现的未决放行项：若疗愈回响被排除后只剩两条，必须给出一个预先裁定的通用备用候选，保证所有席位在同一规则下仍有确定的三选一。备用候选不能通过重抽补齐，不能用延后选择让不同席位获得不同机会，也不能在发牌时临时发明。该 fallback 未裁定前，海克斯原型不得进入实现验收；补上它也不等于把 29 号方案静默改成已裁定的四候选池。

### 5.3 与技能机器的边界

海克斯是本局的一次战术承诺，不占技能机仓库；技能机器是可入库、可学习、可替换并随实例继承的资源。二者可以影响同一战斗行为，但确认页必须说明叠加关系。首批技能机器扩展前，必须先给出：

- 技能名称、效果、触发次数、能量/伤害/时间参数；
- 本作学习资格，不以原作 TM/HM 学习表为准；
- 与原生大招、现有六台教学、装备、羁绊、天气、特性的叠加与互斥；
- 反制方式和目标阵容；
- 动画轨道与权威事件的映射；
- 旧档兼容、规则白名单与是否需要 schema 扩展的字段校验；
- 代表性完整队伍与同预算对照证据。

首批技能目录由后续设计表裁定后，再补入本文第 3 节的学习入口与替换文案；本文不预先宣称任何新强力技能已可学习。

## 6. 开战清单与信息设计

当前开战入口已显示入场天气摘要和终局压力说明，空场时确认文案明确风险。为控制三键负担，建议后续最小改善为扩展「开战」行的长按详情，形成只读清单，不新增页面：

- 待办：待领教学 / 候选海克斯；
- 上场：当前上场数 / 人口、备战席占用；
- 资源：金币、可买经验、可刷新；
- 物资：未使用装备、组件可合成、未使用技能机；
- 岗位：护卫配置、天气手、失效提示；
- 对手：本轮名称、关键近战/远程、已知装备/教学/特性摘要；
- 风险：空场、备战席有核心但未上场、人口空余、站位或实例变化导致战术配置失效。

清单只提示，不自动替玩家买、合、装、学或移动。唯一硬门继续是当前待领教学；未来海克斯待选也应是硬门。这样普通轮保持“最少 1 个开战决策”，信息丰富度靠长按详情补足，不强迫每次遍历全部系统。

另一个低成本教学入口改善是：领取奖励成功后提供「立即学习」与「稍后」二选一。立即学习进入现有机器 → 兼容目标 → 确认流程；稍后回准备页。候选实现时不自动消耗机器，也不默认选中第一个兼容棋子。

## 7. 操作成本口径

当前已有自动测试证明三键能完成买棋、上场、开战、下一轮、装备、合成、卸下、学习、替换取消和 UID 过期取消。它们是脚本路径覆盖，不能替代真人时长验收。

| 场景 | 语义决策数 | 三键路径要点 |
|---|---:|---|
| 无操作普通轮 | 1 | 准备 → 开战 → 确认；空场仍可确认 |
| 买一只普通棋 | 1 | 准备 → 商店 → 选中货架 → C |
| v5 购买并进化 | 2 | 商店进入三合一预览 → 选择自动/暂缓 → 确认 |
| 上场/交换一只 | 2 | 选择来源实例 → 选择目标格；人口失败零副作用 |
| 合成一件装备 | 1 | 选择可合成成品 → 确认 |
| 装备一件 | 2 | 选择成品 → 选择目标实例 → 确认 |
| 学习一台机器 | 2 | 选择机器 → 选择兼容目标 → 确认；替换额外明确确认 |
| 领取教学奖励 | 1 | 选择三候选之一或明确放弃 → 确认 |
| 配置天气手 | 1 | 选择已学天气棋子 → 确认 |
| 配置护卫 | 2 | 选择护卫棋子 → 选择相邻目标 → 确认 |
| 候选海克斯 | 1–2 | 三选一；需绑定的候选再选实例；均确认 |
| 开战 | 1 | 确认；空场使用更明确的风险文案 |

操作预算目标：普通中后期一轮不应要求玩家遍历所有准备入口。建议以“开战前必须处理的待办 ≤1 类”和“每个待办最多 2 个语义决策”为体验线；完整脚本记录键数和耗时，另做真人三键局验收。PC 鼠标 `/demo` 只是参考界面，不作为三键负担结论。

## 8. 事务、UID 与保存恢复约束

当前所有可变动作经 demo 公开事务提交。成功动作先更新内存，再保存，保存失败回滚到操作前内存；提交结果未确认时暂停后续操作，要求重新读档核对。三键层在提交前携带 `expected_sequence`，若另一页面已更新存档，本次选择取消；UID 目标在提交边界重新定位，找不到就要求重选，不会把装备/教学落到另一只棋子上。

准备期状态由 schema4 保存：棋盘格位、备战、实例 UID、装备、教学、进化锁、组件/成品/机器库存、战术配置、冻结奖励、共享池、配对、对手快照、规则版本和指纹。读档不会重跑 `begin_round`、bot 决策、掉落或战斗，因此收入与奖励不能重复发放。恢复后无旧战斗帧时显示已结算摘要，不重算战斗。

新技能机器不必一律新增 schema。若仍能沿用现有 technique 标识、每实例一个教学槽和库存计数，只需要新的显式规则版本/白名单与指纹校验；只有字段校验证明现有状态形态承载不了新增语义时才扩展 schema。海克斯若保存候选、选择、绑定目标和关闭原因，则大概率需要新增状态，但是否升级 schema 仍必须由字段校验决定，不能因“新增系统”自动升级。

无论是否扩展 schema，都不能把海克斯字段塞进现有 technique 奖励，也不能让 v5 旧档静默升级。新增随机用途必须独立于商店、野怪和战斗流，避免改变旧种子结果。候选生成、选择、绑定目标和关闭原因都要可恢复，并保留终局关闭记录。

## 10. 验收建议

若后续实现海克斯或新技能机器，每包至少提供：

1. 三键真人或真机路径截图/视频，包含长按详情、默认取消、确认、返回、熄屏唤醒和重复 release；
2. 生成后保存、恢复、断电模拟、备份导入、重复提交和终局关闭记录；
3. 与 `/demo` 并行操作同一存档时的 sequence/UID 取消证据；
4. 每条候选/新技能的开闭对照、同预算替代、实际触发、赢家变化和多对手结果；
5. 完整局获取与成型读数，包含 R25 成长机会；
6. 新技能动画只消费权威事件，不写 HP/能量；
7. 旧 v5/base 存档指纹和金样本不因新增目录或随机流改变。

本文本身不宣称以上新增验收已完成，也不把现有单元测试扩大为真人体验或全池平衡结论。
