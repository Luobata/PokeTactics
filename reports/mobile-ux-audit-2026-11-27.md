# 手机交互与 UI 审计（2026-11-27）

> 方法：在 Dora 安卓云真机（Pixel 9a / Android 15 / WebView 158，1080×2424，DPR 2.625，视口 411×865）上安装
> 安卓壳 App（docs/73，1.0.132），像玩家一样从新开局玩到第 4 轮：选海克斯 → 商店招募 → 备战席上场 / 换位 →
> 合成与装备 → 开战观战 → 结算 → 商店刷新 / 买经验 → 共享选秀 → 羁绊 / 背包 / 强化 / 对手 / 指令 / 战报面板 →
> 长按菜单 → 返回键。另用 `wm size / wm density` 在同一台手机上看了**小屏 360×731**（≈360×780 设备去掉挖孔）和
> **大屏 480×1010**。所有点击都是 `adb shell input tap/swipe` 的真实触摸，元素位置从 WebView DevTools 读出。
>
> 截图在 `reports/mobile-ux-audit-2026-11-27/`（已缩到 360px 宽，不含地址与个人信息）。
> 严重程度：**高** = 影响一局能否顺畅玩下去 / 有 bug；**中** = 明显别扭、易误触或看不清；**低** = 细节。
> 「处理」一列是本次（PR `feat/mobile-ux-polish`）的结果，改后对比见文末。

## 高

### H1 商店弹层盖住备战席
* 现象：招募后新精灵在备战席上只露出上半身（411×865），要先关商店才能点它上场；360×731 小屏上商店弹层把备战席和「开始战斗」整个盖住。
  docs/72 已记录「标签页模式下商店会盖住备战席」，壳 App 里同样存在（视口 865px，比 PWA 全屏 923px 矮）。
* 截图：`03-shop-covers-bench.jpg`、`10-small-shop-covers-all.jpg`
* 原因：`measureSheet()` 的 peek 高度 = 「备战席底边 → 标签栏顶边」，但下限 180px；上方被 H2 的页头吃掉后，这段距离不足 180px，弹层就往上盖。
* 改法：先解决 H2 腾出 ~110px；peek 高度不再设 180px 下限，而是按剩余空间自适应，空间不足时商店卡切换成紧凑卡（图 + 名字 + 费用，约 96px 高）。

### H2 页头太高、导航链接易误触
* 现象：顶部依次是挖孔黑条（58px）→ 站点导航（营地首页 / 游戏试玩 / 战术图鉴 / 玩法指南 / 调试工具，48px）→ HUD 两行（回合、生命、金币、人口 + 等级经验 + 7 个工具按钮，95px）。
  首屏 865px 里约 200px 不是游戏内容。导航里的链接一碰就离开对局（壳 App 里还会触发「回到对局」确认），「调试工具」也暴露给了玩家。
  工具按钮 34px 见方、只有图标（音乐 / 音效 / 震动 / 引导 / 指南 / 存档 / 新开一局），「新开一局」在小屏缩成一个「＋」。
* 截图：`15-site-nav-and-tools.jpg`、`02-toast-covers-hud.jpg`
* 改法：手机布局隐藏站点导航；HUD 压成一行（回合 · 生命 · 金币 · 人口 · 等级与经验条 · 「≡ 菜单」）；音乐 / 音效 / 震动、新手引导、玩法指南、
  下载存档、新开一局和站点链接（营地首页 / 战术图鉴 / 玩法指南）放进「菜单 · 设置」底部面板，每项带文字、48px 高。

### H3 触屏不能拖拽
* 现象：手指按住棋子拖到另一格，什么也不发生（没有拿起的反馈，也没有提示要点选）。桌面可以拖，手机只能「点精灵 → 点格子」。
  docs/61 把这列为已知限制，但自走棋玩家第一反应就是拖。
* 改法：用 Pointer 事件实现触屏拖拽：按住移动超过 10px 拿起（与长按菜单不冲突：长按 450ms 内不动才出菜单），手指下跟一个半透明精灵，
  可放置的空格 / 备战席虚线高亮、手指下的格子实线高亮，松手即移动（与点选同一个 `move` 命令），拿起时轻震。
  备战席保留横向滑动（只有向上 / 斜向拖才拿起）。

### H4 长按后下一次点击被吞；长按会选中文字
* 现象：长按棋子出菜单 → 手指继续按住，系统开始选中菜单里的文字（出现蓝色选字柄，`05-longpress-selects-text.jpg`）→ 按返回关菜单 →
  再点「背包」没反应，要点第二次。
* 原因：`play_context.js` 长按后设置 `eatClick`，只在 `pointerup` 时转成「吞掉 400ms 内的点击」；手势变成选字时浏览器发的是
  `pointercancel`，`eatClick` 一直留着，于是吞掉了之后任意一次点击。另外游戏界面没有禁止选字 / 长按呼出系统菜单。
* 改法：`pointercancel` 和菜单关闭时清掉 `eatClick`；手机上游戏界面 `user-select: none`、`-webkit-touch-callout: none`（输入框除外）。

### H5 反馈层盖住 HUD 数字
* 现象：买、卖、移动、升级都有吐司从顶部滑下，正好盖住生命 / 金币 / 人口——刚花了钱，金币数字被挡住看不到；升级时「−4 金」飘字、吐司、
  「升级！Lv.3」横幅三层叠在 HUD 和对手芯片上（`09-feedback-pile.jpg`）。每次操作都有吐司，信息量低（「绿毛虫 移动」）。
* 改法：手机吐司改到 HUD 下方、棋盘顶条位置，单行、最多 1.8 秒，同类吐司覆盖而不是排队；有升级横幅时不再弹重复吐司；
  纯确认类吐司（移动成功）在手机上不弹，反馈交给棋子落位动画和震动。

## 中

### M1 招募按钮离拇指太远
* 现象：点商店卡（在屏幕底部）后，「招募 · 1 金」出现在屏幕最上方的操作条里；再点一次卡片是**取消选中**（docs/70 的规则），
  双击才是招募，但没有任何提示。实测第二次点卡片后金币没变、卡片取消选中。
* 截图：`04-context-bar-overflow.jpg`（操作条在顶部）
* 改法：选中的商店卡下方直接出现「招募 · N 金」按钮（在弹层里、拇指可及），买不起时显示「还差 N 金」；顶部操作条照旧保留。

### M2 操作条按钮溢出
* 现象：选中备战席精灵后，操作条是「详情 / 推荐 气势披带 / 设为核心 / …」，「卸装」「出售 +N」在屏幕右侧外面，要横向滑操作条，没有任何滚动提示。
* 改法：手机操作条分两行：上行头像 + 名字 + 摘要 + ×，下行按钮自动换行；按钮最少 44px 高。

### M3 点选后不知道能放哪
* 改法：选中己方精灵时，己方空格与空备战席显示和拖拽时一样的虚线高亮。

### M4 字太小
* 现象：在 411px 视口的主界面统计可见文字字号：8px ×4、9px ×10、10px ×16、11px ×23（棋子名标签、经验文本、徽标、状态标签、面板说明）。
  面板正文多为 11px（`12-panels-small-text.jpg`）。
* 改法：新增设计变量 `--fs-xs/sm/md`，手机上次要信息不小于 11px、正文不小于 12px；棋盘上的小角标（星级、⚔N）保持图形化。

### M5 战斗弹窗
* 现象：右上角 × 的实际作用是「跳过回放、直接进入下一轮」（`battle-close` → `advanceRound`），看起来却像「关闭」；
  底栏「全场阵容」「重开一局」两个文字按钮挨着，后者会打开新开一局确认；「画风 PMD 动画」选择器和英文「ROUND JOURNAL」对玩家没有意义；
  标题上方约 60px 空白。
* 截图：`06-battle-dialog.jpg`、`07-verdict-no-hp.jpg`
* 改法：手机上 × 换成文字按钮「跳过 ›」；「重开一局」从战斗底栏移除（菜单里有）；隐藏画风选择器；「ROUND JOURNAL」改中文；去掉顶部空白。

### M6 结算不说扣了多少血
* 现象：失败时战果卡只写「回合失利 · 你失败……」，扣了几点生命要回到准备界面自己对比 HUD。
* 改法：战果卡加一行「生命 100 → 94（−6）」（客户端记下开战前的生命值，结算后对比；胜利时显示「生命无损」）。

### M7 海克斯三选一一屏看不全
* 现象：每张卡约 690px 高（适配度、理由、「选择后」、按钮全部展开），第二张只露出一半，第三张要滚动（`01-augment-stacked.jpg`）。
* 改法：手机上卡片紧凑显示：名称 + 简述 + 适配度条 + 第一条理由 + 选择按钮，其余收进「详情」展开；三张约 220px，一屏放下。

### M8 精灵图加载中像空格子
* 现象：VPN 下首轮对手的缩略图要 2–4 秒才到，期间格子里只有星级、职业点、装备角标（`08-sprites-blank.jpg`）。
* 改法：图片加载完成前显示柔和的精灵球剪影占位，加载后淡入。

### M9 屏幕高度没有被用上
* 现象：480×1010 大屏下备战席与标签栏之间约 280px 空白（`11-large-unused-space.jpg`）；360×731 小屏格子 46×34px，低于 44px 触控建议。
* 改法：腾出页头后，格子高度按「可用高度 − 备战席 − 商店 peek」计算，上限为格子宽度（不超过正方形）。

### M10 返回键 / Esc 的实现不可靠（结构问题）
* 现象：壳 App 的返回钩子 `PokeTacticsShell.onBack()` 派发一个假的 Esc 键盘事件，再用 MutationObserver 看 DOM 有没有变化来判断「关掉了东西」；
  Esc 的处理分散在 10 个脚本里（有的在捕获阶段 `stopPropagation`，有的在冒泡阶段），关闭顺序取决于脚本加载顺序。
  新加一个弹层就要记得在自己的文件里接 Esc，而且只要 DOM 有任何变化（比如一个计时器刷新）都会被当成「已关闭」。
* 改法：重构为统一弹层栈 `PlayOverlay`（见 docs/74）：每个弹层登记 `isOpen / close / 层级`，返回键与 Esc 都关「最上层的一个」，返回值确定。

### M11 等待服务器时没有任何提示
* 现象：第 1 轮选完海克斯后，一个请求在云真机的 VPN 链路上卡住；页面进入「忙」状态，商店、招募、刷新、开战全部变灰，
  10 多秒没有任何说明（桌面靠鼠标的「忙」光标，触屏没有光标）。play.js 12 秒后会超时并提示「继续存档」，但这之前玩家只能干等。
  第一次跑改前的 E2E 也卡在这里（`timed out waiting for recruit button`）。
* 改法：手机上请求挂起超过 0.7 秒，在 HUD 下方显示「同步中…」；超时与恢复逻辑不变。

## 低

* L1 触屏提示文案：操作提示写「右键 / 长按更多」「Esc 取消」「空格开战」——手机上只写「长按更多 / 双击上场」。
* L2 备战席名字标签压在精灵脚上，弹层盖住时只剩半行——手机上名字移到格子下沿、字号 10→11px。
* L3 小屏「新开一局」只剩「＋」——收进菜单后不再出现在 HUD。
* L4 壳 App 沉浸模式下挖孔区留的黑条与深绿色 HUD 割裂——壳 App 窗口背景改成 HUD 同色（`#14231b`）。
* L5 已买走的商店卡位仍占一张卡的宽度——手机上空位缩成窄条。
* L6 「一键上场」按职业挑行，结果 5 只全在前排——属于布阵规则（`autoDeploy`），本次不改。

## 触控目标实测（改前，411×865）

| 元素 | 尺寸（CSS px） | 结论 |
|---|---|---|
| 底部标签栏按钮 | 55×52 | 合格 |
| 商店工具（锁 / 刷新 / 买经验 / 关闭） | 44×44 起 | 合格 |
| HUD 工具按钮 | 34×34（`::after` 扩到 44） | 视觉偏小、太密 → 收进菜单 |
| 操作条按钮 | 40 高 | 偏小 → 44 |
| 棋盘格 | 54×44（小屏 46×34） | 小屏不合格 → M9 |
| 备战席格 | 50×50 | 合格 |
