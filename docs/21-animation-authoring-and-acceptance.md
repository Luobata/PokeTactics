# 21 · 新角色动画制作与验收

2026-10-05。当前系统可以渐进扩展普通角色和专属技能，但还不是完整的动画制作工具。
本次补齐动作覆盖说明、六类预览、内容校验与跨物种效果复用；没有新增正式物种、
独立手绘素材或逐部件编辑器。

## 当前到底完成了什么

| 维度 | 当前实现 | 仍缺少的内容 |
|---|---|---|
| 全上场池 | 84 只，8 专属机制、76 通用；都支持六类基础动作 | 每只都有区别明显的专属美术，并未完成 |
| 身体 | 16 套手编整身姿态，68 套程序化兜底 | 转身、跳跃等大轮廓变化需要新增独立帧 |
| 命名部件 | 喷火龙、水箭龟、妙蛙花的普攻/施法已接轨道 | 其余 5 核心角色仅结构计划；部件级待机、走路、受击、退场轨道尚未提供 |
| 技能 | 8 套分层演出，16 套手编技能视觉；其余模板 | 任意新技能不可能仅填名字就获得独创编排 |
| 动作预览 | 待机、移动、普攻、大招、受击、退场，阶段定位与逐帧 | 独立状态、入场、胜利预览；其中胜利动作尚未实现 |
| 状态/入场 | 冰冻定格、状态图标/染色/环、共享开场表现 | 物种专属的睡眠、眩晕、护盾、胜利等演出 |
| 编辑器 | 全 84 只可预览；8 只可调四个表现参数 | 拖动部件、支点、关键帧、事件标记、多轨保存发布 |
| 通用运行时 | 无游戏依赖的轨道校验/纯采样，保存与三键输入已有参考实现 | C 采样、ESP32 绘制/缓存与真机时间、内存预算 |

“部件轨道”与 `motion.py` 旧有局部形变不是同一制作能力。整身动作可以包含呼吸、
晃动和局部像素变形，但不因此标记为完整命名部件动画。
编辑器的动作覆盖表分别列出手编、通用、共享和待制作状态。

## 新增一只普通宝可梦

1. 按 [物种扩展合同](19-roster-extension-contract.md) 补图鉴、学习表、入池规则、
   正面精灵及色板；中文名称/招式还要检查字体字形。
2. 先不加 `species_motion`、`_RIGS` 或前端名单。通过 API 资料确认角色自动出现，
   `resource_ready=true`，技能 `can_cast=true`。
3. 六种通用技能原语和程序化身体负责基础表现。执行下方单物种验收，检查待机、
   位移、出手前摇/命中/收招、受击、退场；特别确认远程弹道与血量变化同步。
4. 需要特色时分别升级整身、部件、技能视觉。普通/专属是技能机制分类，
   不限制普通角色也拥有定制身体动作。

## 新增一只带特殊技能的宝可梦

先交付技能设计卡：**触发条件、选目标规则、作用范围、伤害/治疗/资源、控制保护、
反制方式**。例如藤鞭可以设计成“前排单体拉拽”，但拉拽逻辑必须由模拟器判断
格子占用、边界、免疫与死亡；不能在动画里直接移动棋子。

可以复用现有原语时，在 `profiles.PROFILE[id].ult.arch` 绑定该机制。
专属仍须有可解析的伤害招式；`resolve_cast` 的无学习招兜底目前只适用于通用技能。
需要新原语时，应同时交付 `sim/combat.py` 的结算、因果事件与边界测试，不能只增加
一个 `arch` 名字。

表现层按下面三部分制作：

- **身体动作**：蓄力姿态、释放姿态、回收及受击叠加；不修改模拟时间、目标或随机数。
- **部件与挂点**：技能从实际身体挂点发射，例如爪尖、口部、炮口、花盘、藤尖。
- **技能编排**：蓄力 → 飞行 → 命中 → 余波。伤害、治疗、吸能和控制反馈必须消费
  权威事件；同一毫秒有多个动作时用 `cast_index` 归属，不能按角色或时刻猜测。

本次移除了“附属技能效果只允许原 8 只”的限制。新角色复用 `line_push`、
`chain_lightning`、`solar_siphon`、`energy_drain`、`quake_break` 时，
对应事件会复用水流、电链、治疗回流、吸能、地裂等表现。主技能仍走通用模板，
不会自动变成一套新的专属分层演出；独创外观仍需补制作数据/编排。

## 如何拆动作

采用按物种定义的 2D 部件，不要求统一的人形骨骼。当前素材是单帧切片，
没有完整骨骼父子层级、IK 或被遮挡区域的补画能力。

| 身体结构 | 推荐的独立部件 | 关键挂点 | 需要检查的动作 |
|---|---|---|---|
| 喷火龙 | 身体、翼、近侧手臂/爪；尾焰可后续单独制作 | 口部、爪尖 | 抬臂、挥爪、回收；展翼喷火，受击不漂脚 |
| 妙蛙花 | 身体、花盘、左右藤鞭 | 花盘焦点、两根藤尖 | 藤鞭伸展/弯曲/回收；花盘聚光，左右遮挡 |
| 水箭龟 | 身体、两个炮筒 | 两个炮口、口部 | 蓄压、独立后坐、回位，弹道跟炮口 |
| 蛇形/多节角色 | 头、若干躯干段、尾 | 头/口、尾端 | 相位传递、关节连续、转向和回收 |
| 幽灵/软体 | 主体、脸部/下颌、阴影；形变大时采用帧动画 | 口部、阴影中心 | 漂浮、压缩、消散，保持关键轮廓可读 |

最后两行是制作建议，不代表相应新部件系统已交付。变形过大、张嘴内部、
完全转身、倒地等效果需要画新帧或独立部件素材，不能靠切片拉伸获得。

`character_rigs.py` 的局部坐标按**精灵非透明包围盒**的百分比定义；支点按部件
切片百分比定义。源精灵朝左，镜像改变位移/角度和挂点，不倒转时间。
脚点固定在底部中心，外围留 24 像素，最多 8 个部件、每阶段最多 16 个关键帧。

当前可制作的命名轨道格式：

```python
# at, dx, dy, angle, scale_x, scale_y, visible
windup = [[0, 0, 0, 0, 100, 100, 1],
          [1, 2, -3, -55, 100, 100, 1]]
```

每个有动作的部件提供 `windup / strike / recover`，覆盖时间 0–1。
`visible` 按关键帧离散切换；其他维度整数插值。身体本身由 `motion.py` 的七种
状态控制：`idle / walk / windup / strike / recover / hit / death`。
新增部件角色须同时提供整身表；只有部件定义而没有整身表会明确报错，避免页面
显示“已完成”而战斗根本不使用。

校验会拒绝重名部件、悬空挂点、缺阶段、乱序/重复时间、NaN、越界变换、错误支点、
缺整身状态。切片在实际屏幕尺寸上变成零像素时，会报告物种和部件名。
这些是结构检查，不能替代画面检查：素材接缝、留白裁切、轮廓和重叠仍要逐帧看。

## 可执行验收

```sh
# 新角色入池并补好素材后，用它的 ID 替换 6
python3 tools/acceptance/animation_acceptance.py --species 6 --seed 7 --output .build/actor-6.json

# 全池六类动作，原生 240×320 帧
python3 tools/acceptance/animation_acceptance.py --seed 11 --output .build/action-matrix.json

# 内容错误、新物种升级路径、真实效果、全池动作
python3 -m unittest discover -s tests -p 'test_animation_authoring.py' -v

# 全系统回归及素材清单
python3 tools/acceptance/system_acceptance.py --presentation
```

浏览器打开 `/animation-editor?species=6&kind=attack`，逐项切换六类动作。
受击和退场的观察对象是所选宝可梦，攻击/大招的观察对象是目标。
无攻击的待机片段不会伪造伤害阶段；移动和退场也有自己的阶段标记。

每只正式新增角色必须交付：

1. 规则：实际施法、属性免疫、空目标、边界/占位、实际治疗与控制保护等该技能的定向用例。
2. 画面：六类动作分镜，左右方向、关键挂点、缩小到棋盘后的轮廓；新部件逐帧看接缝与裁切。
3. 回放：前摇不提前掉血、命中时才结算显示；倒放/倍速一致、渲染不改原始事件。
4. 组合：受击与施法叠加、冰冻定格与解除、死亡优先、同刻多次技能、多人效果预算。
5. 资源：精灵/色板/字形、清单哈希、缺失资源错误；正式资源和借用素材测试分开记录。

自动矩阵验证真实动作、尺寸、采样帧重放、权威事件不变、命中/死亡状态和
192 粒子/3 活跃技能轨上限。它不证明美术好看，也不替代混编战斗与真机预算。

## 下一批完整工具链的验收边界

| 交付项 | 可验收结果 |
|---|---|
| 逐部件编辑器 | 可选部件、拖支点、增删关键帧、分阶段拖动；导入/导出后帧一致；复用现有时钟 |
| 版本化角色内容包 | 独立部件素材/源帧、整身表、挂点、轨道、效果绑定统一验证，坏包不替换已发布版本 |
| 其余核心部件 | 每只提交真正素材、轨道、普攻/施法分镜与镜像测试，不把计划结构算完成 |
| 额外动作 | 按物种制作待机/移动/受击/退场部件，补状态、独立入场和胜利；各自可预览 |
| ESP32 | C/Python 固定输入对账，真机峰值内存、满人口+天气+状态帧耗时及缓存策略 |
