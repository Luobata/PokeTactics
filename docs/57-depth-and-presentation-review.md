# 57 · 竞技模式深度与战斗表现评审（2026-11-15）

依据：两路只读代码评审（玩法系统、动画管线）、17 局机器人模拟、一场亲自开局并目视渲染帧、
codex `glm-5.3-flash` 通过 HTTP 手动打满两局（试玩原文见
[reports/playtest-codex-glm-2026-11-15.md](../reports/playtest-codex-glm-2026-11-15.md)）。
本文只陈述现状与建议，未改玩法代码。

## 1. 组合玩法单一：根因

1. **存在主导策略：堆高费 + 拉 7 级。** 属性预算按费用线性给（`sim/stat_budget.py:18`，300→780），
   1 星 3 费（540）强过 2 星 1 费（480）。17 局模拟冠军平均 7.0 只 ≥3 费、15/17 到 7 级、全场只出现 1 只 3 星。
   低费多段家族的 1 星多用通用 `family_strike`（`sim/arena_skills.py:268-285`），1 星单位中 42% 是这个技能。
2. **羁绊只有面板。** 17 个属性羁绊是 3–10% 数值（`sim/arena_bonds.py:33-49`），在开战时一次性加属性；
   8 个战术羁绊是“满足条件给几点能量/一次护盾”。没有任何一档改变索敌、站位或规则。
3. **站位意义弱。** 索敌是最近敌人 + 滞回（`sim/combat.py:707-735`），机器人阵型按定位固定生成
   （`sim/arena.py:420-442`），玩家面对的对手阵型不可读、也不可针对。
4. **机器人不构筑。** 选阵按属性 BST 堆叠（`sim/bots.py:440-478`），不看战术羁绊；
   海克斯随机选（`sim/arena.py:227`）。环境里没有多样的对手体系。
5. **转型没有入口。** 无选秀/中立轮；卖出返 1 金；3 费 3 星需 9 张、池仅 18 张，几乎只剩“攒钱拉人口”一条路。

## 2. 技能、道具、海克斯浅：根因

- **海克斯**：17 个中 11 个是纯数值或随轮成长数值，实现是 `combat.py:450-472` 的一串 if；
  没有任何一个改变商店、人口、装备位、升星或站位规则。
- **装备过剩、无取舍成本**：每场固定掉 1–2 份战利品，冠军终局平均闲置 6.2 件成品、10.4 台技能机；卸装免费。
  18 件条件装备几乎都是“触发 → 8–16 能量/6–10% 护盾，冷却 4 秒，每战 3 次”同一模板。
  机器人装备表硬编码旧物种编号（`sim/arena_equipment.py:146-174`），对家族池多数形态无效。
  4 对组件（磁铁×2、磁铁+鞋、鞋+水、炭+雷碎）无配方。
- **技能**：151 个本命技能共 63 个原型，45 个物种共用 `family_strike`；`iron_fault`×7、`cross_bullet`×6
  等同原型只改数字。18 台技能机全是“普攻后触发的小附加”。
- **反馈缺失（试玩最强烈的感受）**：坚不可摧、能量涌动、急救花园等没有独立结算；条件海克斯/装备
  看不到“为何没触发、差多少”；专爱头巾在低星上只多打 5–19 点，玩家无法在决策前预估。

## 3. 战斗动画单一：根因

亲自目视（第 1 轮，`/demo/frame/<sid>/r1/*.png`）：960×640 画面里精灵约 50px，挤在中间两排；
透视棋盘但精灵不随深度缩放；特效多是身上一小团闪光；血条、名字、标签互相遮挡；镜头固定。

代码层面（数据来自动画评审实测）：

1. **节奏像节拍器**：76–83% 的动作落在 3 种时长组合，最常见一种占 39–49%；只有 3 个物种改过蓄力/恢复时长
   （`tools/mockups/animation_timeline.py:266-301`）。所有技能共用“蓄力 0.4 → 飞行 → 接触 0.22 → 收尾 0.8”。
2. **身体语言弱**：精灵最大 64px（`tools/mockups/web_battle.py:827`）；约 86 种用 25 个同形家族模板，线性插值、
   待机不动；约 46 种只有 4px 前冲 + 5% 压扁。分肢体关节动作只有 3 种。
3. **打击感被压低**：命中停顿预算整场平分，实测每次约 33ms，不到一帧；受击无击退；无慢动作、推拉、聚焦、立绘切入；
   组合/羁绊只是一次性印章，没有连携编排。
4. **管线拖慢迭代**：服务端 Pillow 逐帧出 PNG，20fps；一场 583 帧约 80s 渲染、约 68MB；
   编辑器只有 4 个全局滑杆，改动作要改上千行 Python。

## 4. 建议路线

### 4.1 架构先行（解锁后续所有扩展）

**A. 玩法效果系统（数据驱动）**
- `EffectSpec{id, source, trigger, condition, action, params, cooldown, limit, tags}` + 战斗内事件总线
  （`battle_start/tick/basic_hit/cast/damage_taken/hp_cross/kill/status_applied/knockback/shield_absorbed`），
  确定性派发、统一冷却与次数。
- 属性修饰栈 `Modifier(stat, op, value, duration, source)` 替代直接改属性。
- 局外钩子 `round_start/shop_roll/sell/combine/income`，让规则型海克斯、经济效果也是数据行。
- 说明文字、机器人评分、战报“收益账本”都从同一份 `params/tags` 生成——顺带解决反馈缺失和文档过时。
- 迁移顺序：现有钩子包适配器（行为不变）→ 海克斯 → 装备 → 羁绊 → 技能修饰；以现有回归 + 同种子事件流对账兜底。

**B. 战斗渲染移到浏览器（需要用户拍板）**
- 服务端只出事件流 + 时间轴 JSON；浏览器 Canvas2D/PixiJS 60fps 实时绘制；Pillow 保留给设备模式、参照帧与测试。
- “双端同源”改定义为“同一事件流 + 同一时间轴 + 同一份关键帧数据与采样规则”
  （`esp32_runtime/animation.py` 已有 7 字段可移植关键帧格式）。需修订 `docs/01-constitution.md` 第 1、32 条。

### 4.2 玩法深度（按优先级）

| # | 机制 | 新决策 | 规模 |
|---|---|---|---|
| 1 | 规则型海克斯：装备位+1但禁技能机、人口-1全队强化、卖出返组件、1/2费两张升星、羁绊阈值-1面板减半等 | 开局定方向，海克斯间可叠组合 | M |
| 2 | 羁绊断点改行为：2 档数值，4/6 档改规则（岩分担相邻伤害、飞行开场跳后排、幽灵首次致死虚化、水溢出治疗转盾） | 为高档羁绊牺牲战力；与站位交互 | M |
| 3 | 本命技能分化：删除通用 `family_strike`，前期形态用终形技能弱化版；升 2/3 星二选一技能修饰 | 同一精灵多种玩法，升星成为决定 | M–L |
| 4 | 装备重做：组件带小属性、成品“条件触发+主动效果”、战利品稀缺、拆卸/重铸有成本、多余成品可回收 | 先给谁、要不要拆 | M |
| 5 | 索敌/站位规则：远程优先低血、刺客跳后排、同列掩护、光环只作用相邻格；机器人可变阵型 | 针对对手布阵 | M |
| 6 | 核心标记：每轮指定核心，多一装备位、羁绊计两次，但会被针对 | 围绕谁构筑 | S–M |
| 7 | 共享选秀轮：低血先选“精灵+装备” | 追赶与转型入口 | M |
| 8 | 阶段地形轮换（复用 `arena_fields`） | 每阶段重新布阵 | M |
| 9 | 经济：压缩费用预算差距、低费 3 星可达、定向刷新、连败止损 | 低费追三星 vs 拉人口两条路 | S |
| 10 | 机器人按战术羁绊/海克斯标签构筑、按评分选海克斯 | 环境多样、对手可读 | M |
| 横切 | 收益账本与决策前预估：每个海克斯/装备/技能机的触发次数、未触发原因、预估收益 | 选择可被理解 | S–M |

### 4.3 动画（按收益/成本）

| 阶段 | 内容 |
|---|---|
| S（Pillow 内即可） | 按角色/体重区分蓄力与恢复时长 + 单位固定偏移；停顿只给击倒/暴击/大招且每次≥2 帧；受击击退回弹；动作幅度随画面放大；待机呼吸错相；大招/击倒镜头轻推与压暗；“单调度检查”做成回归门槛 |
| M | 事件流/时间轴 JSON 接口；浏览器渲染器接管单位、身体、镜头、数字、HUD；技能特效暂用 Pillow 预烘焙图集；动画工作台 v1 |
| L | 特效全部数据化移植；连携编排（组合/羁绊多单位接力、镜头跟随）；大招立绘切入；同一动作 JSON + C 采样器生成设备子集 |

**宝可梦动画工作台**（升级 `/animation-editor`，复用 `animation_player.js`）：
- 拆解对象：身体动作片段（idle/walk/attack_melee/attack_ranged/cast/hit/ko/victory，按部件轨道，7 字段关键帧 + 缓动）、
  时间事件（蓄力结束/出手/接触/恢复，片段可自带时长）、特效层（蓄力/弹道/拖尾/接触/地面贴花/全屏）、镜头轨、音效与数字挂点。
- 分析：现有 Python 动作表批量转 JSON 作起点；Gen1–3 参考 GIF 洋葱皮对照；
  单调度看板（时长组合分布、同屏施法数、无焦点帧占比、停顿可见率）。
- 流程：选场景 → 曲线编辑 → 实时预览 → 新旧对比 → 存 `assets/motion/*.json`（schema v2）并校验提交。
