# 00 · 头脑风暴：PokeTactics 玩法设计

状态：**草案，待逐节讨论定稿**。每节结构为「问题 → 方案 → 倾向 → 开放问题」，
定稿的节拆出去成为 `docs/systems/Sxx-*.md`，本文只保留索引。

## 0. 一句话定位

8 人对战宝可梦自走棋：花金币买宝可梦、摆阵型，三只同种**进化**合体，
用 17 系属性克制和羁绊在棋盘上自动战斗，把其他训练家的 HP 打光。

与 TFT/云顶的差异点就是卖点，按重要性排序：

1. **进化即升星**——不是抽象的星星，是妙蛙种子真的变成妙蛙花，属性和招式随之变化；
2. **分支进化选择**——3 只伊布合体时，选水/雷/火伊布（升星时选流派，TFT 没有的决策点）；
3. **属性克制网**——17×17 的克制表是现成的策略资产，counter 换位价值极高；
4. **种族值即面板**——151 只的面板/攻速/射程全部从种族值推导，设计成本近乎为零。

## 1. 核心循环

```
准备阶段(约30s)                    战斗阶段(自动, 约30s)
┌─ 收入结算(金币+利息+连胜/连败)     ┌─ 棋子按攻速普攻攒能量
│ 买棋 / 卖棋 / 刷新商店            │  能量满放本系招牌招式
│ 摆位 / 换装备                     │  属性克制决定伤害倍率
│ 买经验升训练家等级(人口)          │  一方全灭或超时结束
└──────────────→──────────────└──────→ 败方按存活敌人掉 HP → 下一轮
                     每 5 轮插入野怪轮(PVE)，掉装备组件
```

- 玩家 HP 100，归零淘汰，按淘汰顺序排名。
- 训练家等级决定上场人口（1 级 3 只起步，上限 9 只）。

## 2. 羁绊系统：17 系怎么收敛

**问题**：TFT 用 ~25 个特质撑起阵容多样性；宝可梦 17 系 × 双属性，
如果只是「水系数量 ≥4 全队 +X」，会退化成数数游戏。

**方案**：
- A. 纯数量羁绊：(2)(4)(6) 给全队数值——实现最快，无聊；
- B. **每系一个机制主题** + 数量阈值：(2) 给小机制、(4) 强化、(6) 质变；
- C. 双轴：属性 × 蛋组（怪力同时供「格斗」和「人形」）——深度最高，认知负担大，留二期。

**倾向 B**，机制主题初稿（对抗性要互相咬合）：

| 系 | (2) | (4) | (6) | 备注 |
|---|---|---|---|---|
| 火 | 招式灼烧 DOT | 斩杀线提升 | 击杀重置能量 | 进攻端 |
| 水 | 全队回血 | 受击回能 | 濒死护盾 | 续航端 |
| 草 | 每轮成长属性 | 受击反伤 | 枯荣：复活一次 | 后期端 |
| 电 | 攻速 | 麻痹普攻 | 开局抢先手 | 速度轴 |
| 超 | 回能加速 | 招式穿透 | 法强叠加 | 大招轴 |
| 恶/钢 | 吸血 | 护甲 | 死亡诅咒 | 防御轴 |
| 地/岩 | 破甲 | 击飞 | 地震 AOE | 反远程 |
| 普 | 全属性小加成 | 复活甲 | 暴击 | 万金油 |
| （余系同思路补全） | | | | |

**开放问题**：
- 双属性棋子天然跨羁绊（快龙=龙+飞），是否需要「单属性棋子」的补偿强度？
- 阈值梯度 (2)(4)(6) 还是 (3)(6)(9)（双属性世界凑数更容易）？
- 传说（急冻鸟/闪电鸟/火焰鸟）作为「独占羁绊」单位：单只即成羁绊，如何定价？

## 3. 进化 = 升星（核心差异机制）

**状态**：✅ 已定稿 → [S2-evolution-starup.md](systems/S2-evolution-starup.md)
（2026-09-13）：规则全文 + **档位改为按形态自身 BST 定价**（1费<365 / 3费≥500，
旧「档位=进化阶段」有跨档倒挂实证）+ 84 只完整档位表 + 两段/三段线合成数学。
保留开放问题：进化可否拒绝、彩票线定价、终形态直售（归 S4）。

**问题**：TFT 的 3 合 1 升星是纯数值翻倍；宝可梦的进化是**换一个种族**。

**规则草案**：
- 3 只同种 → 自动进化到下一形态，继承装备与羁绊计数按新形态计算；
- 种族值自然增长就是升星强度（不需要额外倍率）——已验证：终形态 vs 基础形态
  在当前等级差下强度差足够大（见 reports/skeleton-2026-09-13.md）；
- **分支进化弹出选择**：关都 151 范围内只有伊布族分支（→水/雷/火伊布），
  但它是「升星时选流派」的原型机制；二期扩入金银时自然获得蚊香皇/呆呆王等更多分支；
- 通信进化族（勇基拉→胡地、豪力→怪力、鬼斯通→耿鬼）：进化需要持有任意装备
  （把「通信」翻译成「给东西」，顺便做装备决策）；
- 无进化宝可梦（卡比兽、拉普拉斯、飞天螳螂、大葱鸭……）：直接以 3-5 费入池当「成品棋」，
  或设计「极巨化」终局技替代第三段进化。

**开放问题**：
- 进化可否拒绝（TFT 的卡星策略：保持 1 星凑低级羁绊/经济）？
- 鲤鱼王→暴鲤龙是自走棋最好的「彩票」叙事：1 费废物 3 合 1 直接变身 4 费战力，数值怎么给；
- 3 段线（御三家）终形态 ≈ 几费单卡的战力？（当前 sim：终形态统治力过强，等级差要压平）

## 4. 战斗解算

**已有骨架**（`sim/combat.py`，规则全部可替换）：
7×6 方格棋盘、tick 制、速度→攻速、特攻手远程(3格)/物攻手近战、
能量满放招牌招式、金银伤害公式、大招吃克制与本系加成。

**待定问题**：
- **棋盘形态**：方格（现状）vs 六边形（TFT，走位更细腻）vs 宝可梦式左右两军侧视图（情怀但摆位表达弱）——倾向方格起步；
- **普攻吃不吃克制**：✅ 已由实验定稿（[克制实验报告](../reports/effectiveness-experiment-2026-09-13.md)）：
  **克制只作用大招**——克制上普攻会使 2x 对位 100% 决定论；同时**等级拍平**
  （消除档位双重计费），2x 克制对位由 39% 回到 62%（健康线 65-85% 的边缘）；
  压缩表暂不采纳（会把 2x 压到无意义），将来只压 4x 不动 2x；
- **近战/远程失衡**：✅ 已由实验定稿（[近远程实验报告](../reports/melee-ranged-experiment-2026-09-13.md)）：
  **近战突进 ×0.6**（0.5s/格→0.3s/格）设为默认，无克制对照组 6%→52%，2x 对位不动；
  远程出手惩罚否决（伤及克制信号）。**射程归属裁定**：基础射程按宝可梦
  （特攻种族>物攻=远程），大招施法射程按技能修正列入 S1/S5（投射/接触手工标定）。
  水 vs 岩地 100% 是「特防纸×4x 一击溢出」的结构问题（水炮打隆隆岩 444 vs 127 血），
  修法归 S3 羁绊（岩地族特防光环），同种纯克制压力对位允许打到 ~100%；
- **状态招式轻量化**：麻痹=减速、中毒/灼伤=DOT、睡眠=短禁锢、冰冻=眩晕；一击必杀不入池；
- **速度三义**：攻速（现状）/移动速度/起手序，是否拆给不同系；
- PP 不做，能量制替代（宪法条款）。

## 5. 经济与商店

**倾向**：起步贴 TFT 验证过的节奏，差异化后置。
- 每轮基础收入 5 + 利息（每 10 金币 +1，上限 5）+ 连胜/连败（2/3 舆论梯度）；
- 刷新 2 金币，买人口 4 金币 +4 经验；
- 池子结构：当前 84 只（1费34/2费32/3费18，2026-09-13 S2 按 BST 重排）起步，最终按羁绊需求精选并扩到 4/5 费
  （化石翼龙、卡比兽、快龙、三神鸟、超梦做 5 费传说位）。

**开放问题**：
- 商店 5 格 vs 4 格（小池子浓度更高）；
- 「树果经济」要不要：野怪轮掉树果，树果是装备组件（文柚果=复活甲组件）——宝可梦味浓，但多一套资源轴。

> 状态（2026-09-13）：M2 已落地首版经济与商店（5 格、按等级概率表、共享卡池
> 1费22/2费18/3费12），批量验收全过，参数表与读数见

## 6. 装备/道具

- 基础件（野怪掉落）：各类头带/护符/石头；
- 成品 = 基础件两两合成，全部用宝可梦携带道具命名：
  木炭/神秘水滴/磁铁（系别伤害）、剩饭（回血）、气势披带（锁 1 HP 一次）、
  专爱头巾（攻速换伤害）、亮粉（闪避）；
- 装备栏 1 个（宝可梦携带道具惯例），进化继承；
- 道具应尽量挂在已有机制上（回能/斩杀线/DOT），不新增结算类型。

## 7. 回合结构与 PVE

## 8. 随机性与竞技性

- 保留：伤害浮动 0.85-1.0、命中骰（用原作招式命中）、商店序列；
- 不做：一击必杀、闪避大数（亮粉小数值除外）；
- **确定性回放**：同 seed 同战局（宪法第 3 条），社区可以复盘；
- 平衡验证全部走 sim：目标胜率带宽（属性 45-55%，棋子出场率见 systems 文档）。

## 9. 平台与双端同步架构

**目标**（2026-09-13 补充，推翻初稿「不进 ESP32」）：Web 与 ESP32 设备**双端同源**，
同步调试、渲染一致。PokeWalk 已验证的架构直接继承：

```
            ┌─ 同一份 C 内核（游戏逻辑 + 页面 + 渲染）─┐
            │                                        │
   ESP-IDF 构建│                                     │ 本地编译为 native 进程
            ▼                                        │
   ESP32-C3 固件 ←─ RGB565 字节流 ─ LCD        tools/preview 服务
   （240×320，三键）                              │
                                                   ▼
                                     浏览器 Canvas.putImageData
                                     （A/B/C 与 ↑/↓/Enter 映射三键六事件）
```

要点（全部有 PokeWalk 先例与验收脚本可抄）：
- 浏览器**不自行计算**布局、字体、动画——只解码内核吐出的帧；
- 渲染一致性以像素对账验收：native 进程与浏览器 Canvas 的 RGBA SHA-256 逐帧一致；
- 构建按 C 源 + 资产 SHA-256 键控；预览用确定性测试场景，不碰真机存档；
- **渲染同步契约 = 事件流**（宪法 2.6）：解算器输出 `(t, kind, ...)` 离散事件，
  两个渲染端都是回放器。`sim/combat.py` 已输出事件流且自带同种子一致性自检；
- sim（Python）与 C 内核是参考实现关系：同种子必须产出同事件流，移植验收即比对两端事件流。

**屏幕适配账**（240×320，约束棋盘设计反过来约束 sim，**三个布局方案待选**，
详见 [02-art-and-layout.md](02-art-and-layout.md)）：
- 核心矛盾：40px 是精灵原生最小档，240px 宽放 6 列 40px 格正好；7 列则格缩 32px、精灵须缩图；
- 方案 A：7×6 棋盘 @32px（摆位深，缺 32px 素材）；B：6×4 @40px（精灵原生+常驻羁绊条，纵深浅）；
  C（倾向）：6×6 @40px + 己方末行为「备战行」（纵深与精灵质量兼得，备战席并入棋盘）；
- sim 棋盘列数随布局定稿改一行常量（`combat.py COLS`）；
- 棋子素材候选：GSC 菜单图标（约 32×32、251 只全有，pokecrystal `gfx/icons/`，
  尺寸待核对）或 40 档正面图直用（方案 B/C）。道具/羁绊图标走 UI 图标库。

美术资产、色彩语言与动效预算见 [02-art-and-layout.md](02-art-and-layout.md)；
一局节奏、观战可读性、机器人 AI 分层与人格参数见 [03-gameplay-and-ai.md](03-gameplay-and-ai.md)。

**单机模式**：设备无对战网络 → 一局 = 玩家 vs 7 名机器人训练家（轮转配对照常）。
机器人需要经济/摆位策略分层（弱 bot 攒钱不刷新、强 bot 认羁绊）——这使 M2 的
买入 AI 从平衡工具升级为玩法内容本体，验收标准也更严（可玩性而非仅收敛性）。

## 10. 三键交互设计（A=上 · B=下 · C=确认）

自走棋的输入天然分两态：**准备阶段**（全部操作）与**战斗阶段**（零输入纯观战）——
三键压力全部集中在准备阶段，而准备阶段在单机下可以不限时或用「C 确认开战」推进，
这是三键设备能做自走棋的根本原因。

**页面模型**（沿用 PokeWalk 光标化惯例）：

| 页面 | A（上） | B（下） | C（确认） | 长按 B |
|---|---|---|---|---|
| 主备战页 | 焦点上移 | 焦点下移 | 进入焦点区（棋盘/商店/备战席） | 返回/系统菜单 |
| 商店条（5 格横排） | 光标左移 | 光标右移 | 买入焦点格 | — |
| 棋盘/备战席 | 光标上移 | 光标下移 | **拿起/放下**焦点棋子 | 卖出确认 |
| 信息页（羁绊/图鉴） | 上一项 | 下一项 | 详情/翻页 | 返回 |

**棋盘 2D 光标的三种方案**（S9 定稿项）：
- γ. **双击补轴**（倾向）：单击 A/B=上/下，双击 A/B=左/右，C=拿起↔放下。
  六事件全用上，学习成本中；拿起状态下棋子跟随光标，再按 C 落格；
- α. 蛇形线性化：A/B=前/后格（读序蛇形遍历 42 格），C 同上——零学习成本，
  远距离移动按键多；
- β. 列切换模式：C 短按在「选列 ↔ 列内上下移」两模式间切换——按键最少但模式切换烧脑。

卖出：拿起状态下长按 B → 弹卖出价确认（防误触，PokeWalk 的长按确认惯例）。
战斗阶段 A/B 可调回放速度（倍速/跳过），长按 C 熄屏（宪法继承）。
