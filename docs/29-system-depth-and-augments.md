# 29 · 玩法深度盘点与海克斯推进判断

2026-10-05（Asia/Shanghai）。审计基线 `24090f5`，现行 `tactics_v5` / `budget_v1`，只看关都正式池。本包新增审计工具与证据，没有改战斗、卡池、经济、存档或三键规则，没有实现海克斯。

## 判断

**数量已经足够，深度还不均匀。** 目前可以支持若干强力整套构筑，突进、续航、启动施法、能量干扰和针对突进的阵型都有实战差异；天气方向也能组成有用的整队。缺的不是继续加几十只宝可梦或一大批道具，而是普通形态的清楚岗位、深羁绊的实际价值、反制因果收益和让同一套核心走不同路线的局内选择。

**海克斯值得开始设计和一个小的端到端原型，不宜直接开做9–12条池。** 首包只做一次三选一、三个可比较行为；先验证选择、收益、反制和恢复，再扩到六条及第二次选择。基础护卫、封疗和天气应在没有特定海克斯时也有用，不能靠抽到天赋才能完成反制。

## 1. 当前数量与真实差异

| 系统 | 实际数量 | 玩法含义与边界 |
|---|---:|---|

| 射程 | 49近战、35远程 | 使用正式档案覆盖后的射程；面板形状、属性克制与技能行为还会改变岗位 |
| 专属技能 | 8角色、8原语 | 喷火龙溅射、胡地闪现收割、卡比兽范围自愈、水箭龟贯穿击退、妙蛙花伤害转治疗、雷丘连锁、耿鬼偷能、隆隆岩范围畏缩 |

| 素材配方 | 36种无序对子 | 含同素材两份；14种映射特定成品、22种默认映射进化石。主动选进化石还可消费特定对子，36对子不等于36玩法 |

| 羁绊档位 | 定义52档 | 实际重复计数下49档可分别构造；假设同形态去重则39档可分别构造。不是一队同时拥有49档 |
| 组合技 | 17个名字、当前14系可被选中 | 同一种齐射机制，达到6档后每队最多一次开场齐射，不回能；不能算17个独立战术系统 |
| 天气 | 无/晴/雨/沙/雪 | 主动教学与入场特性只控制晴、雨；沙雪全局DOT未实现。雨不提高电/冰招式，天气石目前仅8%减伤 |

通用侧的引擎职责只有近战输出39、远程输出28、坦9；另有8个专属岗位说明。进攻、防守、干扰、辅助确实存在，但分布明显偏输出：只有4只通用形态拿到铁壁/自愈，明确偷能只有耿鬼。重击带真实击退，不能把所有通用角色都当纯输出；审计标签允许重叠，不是新增游戏职业。

当前不同形态最多可细分80个忽略面板的战斗签名（费档、属性、射程、技能原语、有效招式载荷、固定特性）。这个数仍包含招式威力等差异，**不代表80个流派**；不能反过来把76个通用角色说成76个换皮。

## 2. 羁绊覆盖与复制采购

| 属性 | 不同形态数 | 属性 | 不同形态数 |
|---|---:|---|---:|
| 毒 | 23 | 水 | 18 |
| 飞行 | 12 | 一般/草 | 各9 |
| 火/地面 | 各8 | 虫 | 7 |
| 格斗/超能/岩 | 各6 | 电 | 5 |
| 幽灵/龙 | 各3 | 钢 | 2 |
| 冰 | 1 | 恶 | 0 |

现行 `synergy.compute()` **按实例计数，同形态副本也算**。因此钢、幽灵、龙、冰均可用终点复制采购达到6档；不能沿用旧注释中的“只有2/3种，所以高档不可达”。若要求六种不同形态，只有11系能到6档，电5、钢2、幽灵/龙3、冰1、恶0不能。

这不直接证明复制队过强：六张终点有金币、共享池、人口、招募与功能单一成本。应单开“不同形态计数 vs 现行实例计数”的版本实验，并连同阈值/AI估值测；不能在本次盘点中静默去重或借此加入二世代。

还存在齐射选择遮蔽：17个定义中恶无载体；岩载体全部带地面，钢载体全部带电，因此地面计数始终不低于岩、电始终不低于钢，并列时按属性名排序优先地面/电。岩、钢即使达到6档，也不会被 `combo.volley_pick()` 选中。本包为其余14系保存真实函数判定的六单位构造见证；16系可达最高羁绊，不等于16系都能实际齐射。这属于可读性和深羁绊设计债，不在本包偷偷改优先级。

## 3. 有多少值得的组合

纸面六种不同形态有406,481,544组；限定六人口且直购总价恰好15金，仍有7,376,640组。两者忽略获取、装备、站位、教学与战略价值，**都不是值得玩的构筑数量**。也不应把13道具×17羁绊×14技能原语简单相乘。

本次冻结7个人工命名方向、11套已有配置，在当前v5两两对阵：55组，每组100个独立种子 `2026100580000–2026100580099`，再做同种子换边，共11,000场。每套六人口、15金、三件普通成装、一教学、一搭档，基础天气无；旧弱队与失败配置全保留。此实验不是全池搜索，也不包含组件可得率、真实招募、AI或进化路线成本。

预登记筛查：对另一个方向，胜场率至少60%且Wilson95%下界高于50%记优势；同标准的败场率记劣势。至少一个优势和一个劣势算“本样本有取舍”。区间是逐对阵区间，未做多重比较校正，只作探索筛查。

结果：**7个方向都有至少一套配置通过此筛查，11套中10套通过。** 幽影前后排交换配置对原幽影98%，但同方向内部不计新增优势；对花园57%未过阈值，对突进0%，因此它没有通过本次跨方向筛查。通过也不表示平均实力相当，或每套都适合盲选。

| 方向/配置 | 系统联动 | 当前样本优势 | 当前样本弱点 |
|---|---|---|---|
| 双翼突进 | 暴鲤龙/格斗突进、胡地收割、攻击装、卡比兽搭档 | 对原花园71%、电流100%、原幽影76% | 对幽影护阵22% |
| 花园续航 | 卡比兽承伤/睡觉/剩饭，妙蛙花治疗，浅水草毒羁绊 | 对电流100%、原幽影87% | 对突进29%、降雨续航33% |
| 幽影护阵 | 幽灵前排、站位、治疗与护卫教学 | 对突进78%、电流74% | 对花园及降雨续航0% |
| 电流法阵 | 雷丘搭档有限回能、聚光镜启动、远程连锁/群伤 | 对原幽影95%、日照控场98% | 对突进/花园/降雨续航0% |
| 幽影控场 | 耿鬼压能量、隆隆岩控制、喷火龙与搭档接力 | 对幽影护阵64% | 对突进24%、花园13%、电流5% |
| 日照控场 | 九尾入场晴，喷火龙火伤，妙蛙花治疗 | 对原幽影89%、封疗幽影98% | 对突进27%、花园17%、电流2% |
| 降雨续航 | 拉普拉斯、水系前排与呆壳兽，卡比兽/妙蛙花续航 | 对原花园67%、电流100%、原幽影93% | 对突进23% |
| 封疗幽影（功能替换） | 原幽影把聚光镜换成封疗针 | 对幽影护阵76% | 对花园29%、突进3%；不是全局更强版本 |

完整矩阵、逐种子胜负/战斗指标/事件哈希见证据。整套降雨续航的67%不能全部归因于降雨；护阵78%也不能归因于护卫。此前有因果消融：封疗本身对花园净增23个百分点；护卫选/未选无赢家变化；雨天续航的胜率收益也不来自天气开启。这些旧证据没有被本次联赛改写。

由当前样本可见 `突进 → 花园 → 护阵 → 突进` 的构筑级循环，但换站位、换对手和混编会改变关系，不能做成硬编码克制表。突进仍明显压制多数配置；深4/6档羁绊与齐射几乎没有在这些强队里扮演核心角色，需另测，不能借浅羁绊联赛宣布深羁绊成立。

## 4. 哪些联动值得先补

1. 给主要方向补低费过渡、核心、辅助、同费替代岗位；先手工打磨少量形态，不加池子。技能原语按图鉴号余数分配，47条进化边都会换原语，但这不等于47条有策划意图的职责转型。
2. 统一羁绊“实例/不同形态”口径，再实验少量机制档。电4继电、草4实际治疗后保护仍是22号候选，尚未交付；高档机制应替换部分旧预算，而不是再免费叠一层。
3. 分开测反突进来源、封疗与启动能量机会成本、公开侦察和转型AI。护卫触发不等于有效反制，封疗也不应变成无代价启动装。
4. 用完整局测这些路线真实能否获得并成型。v4压力提高自然终局，但减少R25存活与教学机会；新选择应放在足够早的轮次，并记录操作负担与成长机会。

## 5. 海克斯值得推进到什么程度

当前已有版本路由、教学奖励三选一、UID选择、原子保存与有界战斗原语，可以复用工程框架；**海克斯目录、持有效果、发牌随机用途、效果注入、AI估值和专属页面全部尚未实现。** schema4奖励只接受教学，不能直接把天赋塞进旧字段。新增sim文件还会改变规则指纹，须先冻结v5指纹与旧局金样本。

建议下一份实现规格先限定：新规则 `tactics_v6`、一次必选三选一、三条候选、每场有限触发。首个选择轮建议R6（第一轮R5教学奖励后），是本次新候选而非已裁定参数；不直接沿用历史R2/R8/R14三阶段。先验证一次选择的流程与收益，再决定第二次轮次及扩池。新版本可采用schema5，保留schema4及旧规则执行；不是现在就修改所有旧档。

首批候选只复用已有行为通道，具体能量/伤害/时间需控臂标定：

| 候选 | 一件事 | 代价、反制与边界 |
|---|---|---|
| 蓄势待发 | 指定一个实例，开场在原格保持一段时间后获得一次能量 | 移动/击退破坏资格；不能全队无条件起手；玩家选择与站位有关 |
| 余势追击 | 指定实例首次原生大招命中后，下一次普攻兑现一次派生打击 | 偷能、集火和无法继续普攻可破坏；派生不回能、不再次触发完整链 |
| 疗愈回响 | 我方每场第一次实际治疗给被治疗者一次能量 | 没有可用治疗来源时不进入适配选项；封疗和集火能降低收益；过量治疗不触发 |

随后才考虑拦截回响、晴雨协同、一次付费功能位刷新：前两者要求基础机制先有独立收益，后者涉及真实商店、共享池和AI，是另一个工作包。转训依赖尚未交付的本金/迁移账，不进首批。

发牌建议“当前可用、通用、可转型”，至少一项当时可用。依赖护卫/天气的选项必须展示实际来源；强力玩法来自改变启动时机、保护对象或后续动作，而不是全队攻击、吸血、攻速三个泛数值选项。天然终点、进化终点与中段按同一实例规则参与，不给可进化棋额外成长层。

放行需要四类证据：

- 生成候选后先持久化；取消重进/断电/备份/重复release不重抽、不双发；终局待选关闭。独立随机用途不移动商店/战斗随机流。
- 三键完成详情、选择、确认与恢复；实际玩家记录操作耗时，PC脚本不能替代真人。
- 每条控臂启用/关闭与同成本替代，多对手、换边、逐种子反向局、实际触发与赢家变化；不只报触发率。没有恒默认项，也没有长期死选项。
- 100完整局初筛：获取/成型/选择率、自然终局、R25成长机会与存档恢复。海克斯不能把基础反制锁在抽卡运气之后。

## 6. 本包证据和复现

`reports/evidence/system-depth-2026-10-05/` 保存盘点、完整矩阵、逐种子压缩JSON、重放检查和哈希清单。55组的首个种子另做完整事件重放：事件、winner/duration/survivors、单位投影与记录的事件SHA均一致；Unit实例对象不以对象地址判相等。所有依赖在运行前后稳定，用户原双银行未变。

本地QualityGate返回raw/gate pass，但没有匹配脚本规则、未运行AST/中央语义，task_complete=false；完整runner检查还有缺失依赖，不能把此PASS写成有效语义覆盖。独立代码/证据审计另记。

```sh
python3 tools/acceptance/system_depth_probe.py --output .build/system-depth-new/inventory.json
python3 tools/acceptance/system_depth_probe.py --battle --seeds 100 --output .build/system-depth-new/tournament.json
```

本审计的“有取舍”只覆盖预声明固定阵容，尚不证明全池平衡、真实招募可行性、深羁绊强度或真人/真机体验。
