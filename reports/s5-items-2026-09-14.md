## 2. 实现要点

- **施加协议**：`Bot.battle_comp()` 对带装备者传 `(Piece, item_key)` 二元组，
  裸 Piece 照旧——`Battle._deploy` 解包后调 `items.apply_to_unit`（S3
  `synergy.apply` 同模式的施加点）；羁绊计数喂裸 Piece。prototype/野怪波次
  传裸 Piece，战斗层默认无装备；
- **结算维度**：只复用现有维度（combat.Unit 加 item_ult_dmg/item_dr/
  item_heal/item_energy/item_dodge/item_type_dmg/item_sash 七个中性默认
  0/None/False + 面板/攻速在施加时直改）。亮粉闪避=出手即整次挥空
  （事件流补 miss 条目，attack/cast 数字与掉血一致的渲染契约不破）；
  披带=致命伤留 1 HP 一次/场（sash 事件）；剩饭走既有 1s 一跳的 regen 循环；
- **随机全走子流**（S7 协议）：掉落走 pve 子流的**掉落 counter 段**
  （`PVE_DROP_COUNTER=1024` 起，保底段 +i、加发段 +256+j，与掉金 counter=i
  互不位移）；闪避骰走本场 battle 子流；合成/装备/进化石决策**零随机**
  （固定序 + 列表序，确定性）。跨进程、跨 PYTHONHASHSEED（0/12345/999）
  重放一致（淘汰+排名+装备统计，§5 复现）；
- **通信进化双通道**（S2 §1.5）：① 3 合 1 门——选中三只至少一只持任意装备
  （持装备者优先入选，装备随棋子进新形态，多余持有者卸回仓库）；② 进化石
  ——装备到勇基拉/豪力/鬼斯通上即进化（池记账 sources 追加新形态占 1 张）。
  装备开时 L2 买入评分解除通信族第 3 只的 −800 暂缓罚；
- **bot 策略（L1+，L0 教学沙包不参与）**：合成走优先级表（**梭哈型先合
  攻击件**：专爱头巾→疾风羽→聚光镜；其余 专爱头巾→聚光镜→剩饭…），
  无特定配方可合时兜底进化石（无通信目标/已用则不烧，组件留作后续配对）；
  装备给主 C（BST 最高空手者），幸运蛋给最弱棋（不占主 C 的 1 格），
  进化石只装通信族中段形态；卖棋/换仓自动卸回仓库（`_unequip`）。

## 4. 进化石触发统计与平衡发现

- **触发率 4.60 次/局**（230 人次/50 局，50/50 局出现）——按 L1+ 席位折算
  **60-70%**（saver 70% / copycat 67% / roller 65% / balanced 60%）：
  几乎每个持有通信族中段形态（勇基拉/豪力/鬼斯通都是常见 2 费买入）的
  bot 都能等到一次免费进化。兜底配方「任意两组件」使进化石是**最容易
  合成的成品**——通信进化从「凑不齐的陷阱」翻转为「近乎保底的收益」。
  但触发强度有限：单只 2 费→2/3 费（BST +85~100），且每局限一次，
  对局长/名次结构无可见冲击（§3 各行位移均在抽样波动带内）；
- **最意外的发现：通信 3合1 通道几乎死掉**（50 局仅 1 次）。「3 只中段 +
  任意成品装备」的资源组合在实践中凑不齐——bot 拿到第 3 只前，组件早就
  兜底烧成进化石走单人进化了。S2 §1.5 的「持装备 3合1」与 S5 的进化石
  实质互斥，需在 S6/S5 终裁时择一为主通道（或给 3合1 通道加权重：如
  通信族 3 只齐时优先合成而非烧石）；
- **梭哈型是装备最大受益者**（冠军 9→16，名次 4.48→4.33）：人格差异条款
  （先合攻击件）兑现为可读的读数位移——装备轴确实在人格空间里制造了
  真实的手感差异，不是装饰；
- **经济侧零通胀**：组件免费 + 幸运蛋极稀（终局 5 件/50 局），金币曲线
  前中期两臂逐点重合——S4 经济常量无需为 S5 重标定；
- **「三系围巾 + 天气石」吃掉最多装备位**（围巾 18 + 天气石 15 = 终局
  带装 44%）：系别伤害对大招乘区（STAB/克制/聚光镜全叠）是最陡的
  收益曲线。S11 天气落地后这条曲线会更陡，盯防围巾+天气的组合上限。

## 5. 验收与复现

```sh
python3 sim/items.py                      # 数据表自检：12 成品/8 组件/合成序
python3 sim/prototype.py --games 100      # 与 S5 改造前逐字节一致（战斗层默认无装备）
python3 sim/experiment_match.py --games 50 --seed 100   # 四条验收 PASS（items 默认关，读数=旧基线）
python3 sim/experiment_items.py --games 50 --seed 100   # 双臂 + 健康线三判全 PASS
PYTHONHASHSEED=999 python3 sim/experiment_items.py --games 50 --seed 100  # 逐行一致
```

- prototype：A52/B48、时长中位 6.7s，与改造前输出逐字节一致（item_* 全
  中性默认 + tuple 解包守卫，无装备路径零分支变化）；
- match（items 关）：seed 7/100 单局简报与改造前逐行一致（仅决策耗时抖动行）；
- 重放一致（宪法 2.2）：experiment_items 内建「装备开」同种子重放自检通过；
  种子 100-109 ×（淘汰顺序+排名+装备统计）指纹在 PYTHONHASHSEED
  0/12345/999 三进程一致；
- 不 git 提交；`docs/systems/README.md` S5 行已更新（概念稿 → sim v1 已落地）。
