### 1.2 决定性论据

**淘汰 A（7×6@32px，摆位纵深优先）——资产与信息密度是决定性的**：

1. 40px 是正面图原生最小档（02 §2 首句）；32px 精灵是**缺口资产①**，
   84 只 × 逐只缩样验收是 M4 关键路径上最大的美术风险。缩不动的只（构图密的
   48/56 档）在 32px 会糊成一团，「金银像素」的作品身份直接受损。
2. 32px 格面积比 40px 少 36%，装不下已验证的**四层底座语言**（类型双环 +
   档位角点 + 血条 + 能量条）——02 §4.5 判定④只在 40px 下验证过可读；
   32px 未验证且大概率不可读。
3. A 多出的纵深（每方 21 格 vs 12 格）被三个事实摊薄：近战突进 ×0.6 已把
   前后排几何压扁（sim 布阵中敌我前排本就相邻）；人口上限 9，12 格够用
   （最满 75% 占用）；3+3 行的纵深差异在 240px 宽小屏上肉眼不可读。
   **频率裁优先：精灵可读性是每一帧都在用的资产，纵深是每一轮用一次的资产。**
4. 附带损失：[羁] 入口挤成图标（A 自认的缺点）。

**淘汰 B（6×4@40px，常驻羁绊条）——省下的 36px 给错了人**：

1. B 与修订 C 的战场几何完全相同（2+2）；差异只在富余的 36px 给谁：
   B 给**常驻羁绊速览条**，C 给**两行备战行**。
2. 备战行是**操作对象本体**（买入落点、3 合 1 原料、摆位中转），必须常驻可见；
   羁绊计数是只读信息，HUD 角标（已激活数）+ 一键羁绊页覆盖绝大多数场景
   （信息分级见 02 §3：羁绊计数够格常驻，但角标即可承载）。
3. 交互成本：B 的独立备战条在棋盘坐标系之外，备战↔上场要跨区跳转
   （每次多 1-2 键）；C 的备战行在棋盘内，拿起-移动-放下一次连续光标流完成。

**维持 C 的核心收益**（02 §2 已列，全部保留）：40px 原生精灵 + 备战席零额外
空间 + 「虚线格=观战席」的设备化表达；且已有像素级真稿
（`docs/design/mockups/prep_240x320.png`，像素账闭合）。

### 1.3 对草案 C 的两处修订（本稿新裁定）

1. **对称战场（敌 3 我 2 → 敌 2 我 2 + 双方各 1 备战行）**。原案敌方 3 行战场
   对玩家是系统性劣势（对手的后排多一格缓冲），且 sim 是对称 3+3——设备与
   参考实现几何不同构，违反宪法 §1「sim 是 C 内核参考实现」的精神。修订后：
   - 战场 = 6 列 × 4 行（敌 2 + 我 2），备战行不参与战斗；
   - 敌方备战行在准备页显示**上轮快照**（配对在决策之后，准备期不知道下个
     对手，docs/03 §3「决赛圈前不共享战况」不破）；战斗开始时配对已定，
     敌备战行揭示为**对手真实备战席**——零成本的侦察观战内容；
   - 我备战行在战斗期照常显示替补（呼吸动画），棋盘永不「下半截空掉」。
2. **备战容量 6（`BENCH_SIZE 9→6`）**。备战行只有 6 格；场上 ≤9 + 备战 6 =
   总持有上限 15，3 合 1 攒卡（最坏 9 只同名）需要「边买边合」，压力真实但
   可玩（bot 已有超限卖出逻辑，`sim/bots.py` L242 起）。小屏纪律：容量必须
   等于可见格数，不做滚动/翻页备战。

### 2.4 冲突处理（操作进行中的中断）

| 冲突 | 裁定 |
|---|---|
| **转场锁**（开战→战斗、进化演出 2.5s、结算横幅、掉落过渡） | 输入全锁；进行中手势清理至 END；锁释放后 **100ms 消隐期**吞掉所有按键（防连击穿透到下一状态，PokeWalk 观测模式手势清理先例） |
| **突发弹层插入**（放下触发进化演出、低电提示） | 演出/提示入 FIFO 队列（深度 ≤3）逐个播放；队列播放期间底层焦点与拿起态冻结 |

## 3. 核心操作流走查（按键序列 + 界面反馈）

记号：`A` `B` `C`=单击；`A·A` `B·B`=双击（≤200ms）；`B~`=长按 600ms；
`C~~~~`=长按 1.5s。动效全部来自 02 §1.3 零成本清单（呼吸/闪白/抖动/飞入/白闪）。

### 3.1 买棋（含自动入备战/上场判定）

前提：光标在 Z4 商店格。序列：`C`。

1. 前置检查（任一失败 → 该格红闪 2 次 + 60ms 抖动 + HUD 行 2 提示，无副作用）：
   金币 ≥ 费用；备战未满 或（备战满 且 场上人数 < 人口）。
2. 扣费：HUD 金币数字滚动 −N；商店格翻为虚线空格。
3. **落点判定**（按序）：
   - 备战有空位 → 精灵从商店格**飞入**备战行首空格（复用三合一「飞入」轨迹）；
   - 备战满且场上人数 < 人口 → 按人机共用的摆位规则自动上场
     （`sim/bots.py::_arrange` 同款：近战→前排首空格，远程→后排首空格；
     首选排满放另一排），飞行轨迹 + 落格尘土提示「自动上场」；
   - 两者皆满 → 不可能走到这步（第 1 步已拦截）。
4. 买入后立即跑 **3 合 1 判定**（§3.5）；拿起态中的棋子不参与判定。
5. HUD 行 2 焦点摘要刷新为新棋子（名称/费/属性）。

教学 T4（首次出现 2/3 进度时，一次性）：「再买 1 只皮卡丘即可进化！」
（合成进度 x/3 常驻显示在棋子详情页与信息摘要行）。

### 3.2 拿起—移动—放下（γ 双击补轴完整规则）

**拿起**：Z3 棋子焦点按 `C` → 棋子抬起 2px + 底部阴影 + 四角括号放大；
信息摘要行显示该棋子名称与关键数；进入拿起态。

**移动（γ 规则，输入层实现，三端同一份代码路径）**：

1. `A` / `B`（单击）：**立即**上移/下移一格（CLICK 即发，零等待）。
2. `A·A` / `B·B`（200ms 内同键第二次单击）：**先回滚该键刚刚那格竖移，
   再横移一格**——双击的净效果永远是「从双击前的位置纯左/右移一格」。
   画面表现：竖移闪现 ≤200ms 后回弹并横移（有心理预期后即「双击=左右」）。
   若第一次单击本就被边缘钳位（无位移），回滚为空操作，双击=纯横移。
3. 拿起态同样适用；棋子跟随光标平滑插值移动（`battle_anim.gif` 已验证的
   移动插值路径）。
4. **连打保护（γ 的已知代价，明示给玩家）**：竖移连打需间隔 >200ms，
   否则被解释为横移。己方热区纵向只有 3 行（战场 2 + 备战 1），最远 2 步，
   暴露面极小；教学文案直接教会节奏。
5. 光标限定己方 3 行 ×6 列；到边界钳位 + 边缘反馈，不能移入敌方区/动作条
   （防止带着棋子迷路到不可放置区）。

**放下**：拿起态按 `C`：

- 目标空格在**战场**：仅当 场上人数 < 人口 → 落格（尘土 + 轻震）；
  人口已满 → 棋子弹回原格 + 抖动 + 提示「人口已满——放到棋子上＝交换」；
- 目标为**己方棋子**（战场或备战）：**交换位置**（两棋对调，白闪 1 帧），
  不受人口约束（交换不改人数）；
- 目标空格在**备战行**：落格入备战；
- 放下后立即跑 3 合 1 判定（§3.5）与羁绊计数刷新（HUD 羁绊角标数字即时更新）。

**教学文案**（HUD 行 2 轮播 / 首次触发气泡，每种手势成功 3 次后永久退场，
进度入存档）：

- T1 首轮准备页：「A·B 上下移动　快按两下 A·B 左右移动　C 拿起／放下」
- T2 首次拿起：「C 放下　长按 B 卖出」
- T3 首次人口满放置失败：「人口已满——放到棋子上＝交换位置」
- T6 首次双击触发时气泡：「双击 = 左右移动一格」

### 3.3 卖出（长按 B 确认防误触）

前提：拿起态（**卖出只能从拿起态发起**——空格焦点的 B~ 是系统菜单，
结构性防误触）。序列：`B~`（600ms）。

1. 长按期间棋子下沉预备态（视觉预告长按正在积累，松手即中止且不补发任何键）；
2. 600ms 到 → 弹**卖出确认弹窗**：棋子缩图 + 「卖出 皮卡丘 +2 金？」
   （卖价 = 累计投入 −1，1 费保底 1 金，`sim/shop.py::sell_value`）+
   屏上大字标注「**A 取消 / C 卖出**」（≤3 项字母直达惯例）；
3. `A` → 关闭弹窗，回拿起态（棋子还在手上，光标还原）；
   `C` → 金币滚动 +N、棋子缩小消失、共享池归还（`sources` 全量回池），
   弹窗关闭，回空格焦点；
4. 弹窗打开后 200ms 内的任何按键忽略（防长按 B 的残留节奏误触 C）；
5. 卖出后跑一次人口/羁绊摘要刷新。

### 3.4 刷新 / 买经验

前提：光标在 Z4。

- **刷新**（[刷2] 焦点）`C`：金币 ≥2 → 扣 2 金，4 格错峰翻转
  （每格延迟 60ms 的翻牌动画），未买走的格子归还共享池后重抽
  （`sim/shop.py::roll`）；光标停在刷新钮上便于连刷。金币不足 → 红闪+抖动。
- **买经验**（[验4] 焦点）`C`：金币 ≥4 且未满级 → 扣 4 金 +4 XP
  （`sim/economy.py`）；若因此升级：横幅「升级！Lv6 人口 8」0.8s + HUD 闪白，
  人口上限提升立刻反映在放置规则里。满级 → 提示「已满级」；金币不足 → 红闪。
- 每轮开始的**免费重滚**自动发生（收入结算后），无需操作，
  画面表现为动作条整体翻转一轮 + 金币入账数字上浮。

### 3.5 3 合 1 自动进化与分支进化弹窗（伊布）

触发时点：买入后 / 放下后（`try_combine` 全量扫描场上+备战；拿起中的棋子
不在判定范围——「手里的棋子不会突然消失」是红线 §5-7）。战斗阶段不触发
（S2 §1.1）。

**普通进化流**（如 3 只皮卡丘）：

1. 输入锁（转场锁）→ 三只中两只**飞入**第三只所在格 + 白闪；
2. 进化光球 2.5s（PokeWalk 八轮压缩版，02 §1.3）→ 新形态（雷丘）落格；
   **落位 = 三只中位于场上的那只的原格位；全在备战则备战首空位**
   （场上合成不断阵，§1.5 已列 sim 对齐改动）；
3. 底座语言切换（形状→2 阶、色环按新属性）、羁绊计数即时刷新、
   「3合1！」消息窗 1s；解锁锁，光标回合成格。

**分支进化流**（3 只伊布，S2 §1.4）：

1. 同上飞入+白闪后，不直接合成 → 弹**分支选择弹窗**：
   水/雷/火伊布三立绘并排，各自属性色底 + 键位标注「**A 水伊布 / B 雷伊布 /
   C 火伊布**」（≤3 项直达惯例，无光标、无取消——S2 裁定未选择前不合成，
   弹窗即选择本身）；
2. 按键 → 选中立绘放大 + 白闪 0.5s（明示「不可更改」文案）→ 进化光球 → 落格；
3. 拿起态被合成结算打断的情况：若手里拿的**不是**被合成的三只之一，
   弹窗队列播放完毕后持有态原样恢复（手里那只没参与判定）。

**通信进化**（勇基拉/豪力/鬼斯通，S2 §1.5）：凑齐 3 只但无装备 → 不合成、
三只保持原状，信息摘要行一次性提示 T5：「勇基拉×3：持有装备后进化」。
装备穿脱入口见 §3.6。

**池枯竭等待**：进化形态在共享池无存量 → 同样保持原状等待
（`try_combine` 现行为），无提示（玩家不需要知道对手卡了他的牌）。

### 3.6 装备穿脱（S5 预留）

入口定死在**棋子详情页**（`C~` 600ms 打开）：

- S5 落地后：详情页装备栏位 `C` → 打开道具背包（光标列表）→ `C` 穿上；
  已穿则 `C` 脱下回背包；进化继承装备（S2 §1.2）；卖出时装备回背包（S5 口径）；
- 本稿状态：装备栏显示空槽，`C` = 提示音 + 「装备系统即将开放」（或直接无操作）；
- 野怪掉落的组件直接进背包（§3.8），不在棋盘上散落——避免「地面拾取光标」
  这第二个 2D 焦点区。

### 3.7 羁绊面板浏览

入口：Z1 徽标 [羁绊N]。序列：`C` 进页 → `A/B` 逐行 → `C` 展开 → `B~` 返回。

- 17 系固定顺序（火水草电…），**不按激活重排**（位置记忆优先，PokeWalk
  列表惯例）；每行：系色块 + 系名 + 计数 pip（x/2/4/6）+ 当前档效果摘要；
- 激活行高亮 + 呼吸；`C` 展开三档效果全文 + 「还差 N 只到下一档」
  （下一档补哪只从当前阵容/商店可直接推断，配图鉴交叉引用）；
- 双属性棋子供两个计数（S3 §1.1），行内以双 pip 显示；
- 返回后焦点回 [羁绊] 徽标。

### 3.8 野怪轮掉落拾取

PVE 战斗胜利 → 结算横幅「野怪击退！+3 金」：

- **金币掉落**（现行 `PVE_GOLD=(2,3)`）：自动入账（横幅数字上浮），无独立页面；
- **装备组件掉落**（S5 起，弱队血量加权优先，docs/03 §5）：横幅后接**掉落页**：
  组件图标逐件排开 + `A/B` 逐件浏览（高亮+名称）+ `C` **收取全部** →
  组件依次飞入背包图标 → 自动返回准备页；
- 掉落页无取消路径（收是唯一出口，但本来就全是收益）；
  输入锁与 200ms 消隐同 §2.4。

### 3.9 开战与回合推进（补充定稿：开战按钮）

docs/03 §1「准备不限时，C 开战」的 C 落在动作条最右 **[战▶]** 钮：

1. `C` → 转场锁（100ms 消隐）→ 战斗页：全屏棋盘 + 双方 HP 条 + 倍速角标
   （02 §4.2），敌备战行此时揭示为对手真实备战；
2. 战斗播放：`A` 降速 / `B` 升速（1x/2x/4x/跳过；默认 2x）；`B~` 无效
   （**战斗不可中途返回准备页**，红线 §5-2）；`C~~~~` 熄屏照常；
3. 结算横幅 ≥2s 不可跳（败方掉血 = 2 + 存活敌棋 × 阶段系数，数字逐项弹出），
   之后 `C` 立即继续或 3s 自动继续；
4. 回到准备页：收入结算（基础 5 + 利息 + 连胜/连败）数字上浮 + 免费重滚 +
   白送 XP（可能升级横幅）；HP 归零 → 淘汰演出 → 观战/快进剩余轮次
   （docs/03 §1，淘汰后 A/B 调回放速度照常）。

## 4. 状态机（文字版）

### 4.1 准备页焦点栈（无环绕，端点续按跳区）

```
Z1 徽标行(1D,3)  ⇄  Z2 敌方区(1D,≤12)  ⇄  Z3 己方棋区(2D,6×3)  ⇄  Z4 动作条(1D,7)
  A 端 = 页面顶（钳位）                                      B 端 = 页面底（钳位）
```

### 4.2 Z3 己方棋区内部（γ 光标，col∈0..5，row∈{战场前排, 战场后排, 备战}）

```
CLICK_A  : row−1（前排再按 → 焦点交 Z2 末项）
CLICK_B  : row+1（备战行再按 → 焦点交 Z4 首格）
DOUBLE_A : 撤销同键前次 CLICK 的竖移，col−1
DOUBLE_B : 撤销同键前次 CLICK 的竖移，col+1
（拿起态：同一套移动规则，光标限定己方三行，不跳区）
```

### 4.3 拿起态（HOLDING）

```
进入：Z3 棋子焦点 × C
退出：C（有效落点 → 放下/交换，回 IDLE）
      B~600 → 卖出确认弹窗 → C 确认 → 回 IDLE 空格焦点 / A 取消 → 回 HOLDING
约束：放下到战场空格需 场上<人口；放到棋子上=交换（免人口检查）
冻结：弹窗/演出/转场/熄屏期间 HOLDING 保持（含棋子、光标、拿起来源格）
```

### 4.4 弹窗层与页面栈

```
弹窗（全局互斥，FIFO ≤3）：卖出确认 | 分支进化 | 掉落页
页面栈（≤2）：准备页 → {羁绊页 | 棋子详情页 | 图鉴 | 战绩 | 系统菜单}
规则：弹窗/页面打开 → 底层焦点冻结；关闭 → 焦点回来源位置（焦点永不丢失）
      演出队列（进化/升级横幅）不占弹窗层，播放期间输入锁 + 手势清理至 END
```

### 4.5 回合状态机

```
准备页(不限时) --C×[战▶]--> 转场锁 --> 战斗页(A/B 调速) --> 结算横幅(≥2s 锁)
   ↑                                                        │
   │            [PVE 胜且有组件掉落] → 掉落页 --C 收取-->──┘
   └── 收入结算 + 免费重滚 + 白送 XP（合成判定只在买/放后触发，回合开始不补跑）
玩家淘汰 → 淘汰演出 → 观战模式（调速/回放，docs/03 §1）→ 局终排名页
```

## 5. 可用性红线（PokeWalk 教训对照，全部一票否决级）

1. **长按结束后不补发短按**：`B~` 弹出卖出窗后松开不得触发「下移」；
   转场锁释放同理（PokeWalk 两份报告原文：「长按结束后不再补发下一项」
   「取消指针、失焦或长按后不会补发短按」）。
2. **返回不绕过结算**：战斗页与结算横幅 `B~` 无效；掉落页无取消键；
   进化演出不可跳过（PokeWalk：「不会通过返回绕过反击、结算或存档」）。
3. **双击回滚是输入层原语**：回滚状态由内核输入模块持有，BSP/浏览器/native
   三端走同一实现（PokeWalk 三层六事件一致性先例），禁止页面层各自补丁。
4. **弹窗 200ms 消隐**：任何弹窗/转场锁打开后 200ms 内按键全部忽略
   （防长按残留节奏与连击穿透）。
5. **失败操作零副作用**：金币不足/备战满/人口满的 `C` 不扣费、不改状态，
   只给红闪+抖动（PokeWalk 体能前置检查先例）。
6. **熄屏不可覆盖、唤醒手势只用于亮屏**：C 长按 1.5s 在任何状态生效
   （含详情页打开中）；唤醒不做任何其他事（PokeWalk 原裁定）。
7. **拿起态棋子永不消失**：不参与合成判定、卖出必经确认弹窗、
   熄屏/转场/弹窗期间冻结保留、存档含持有态。
8. **不可逆操作必有显式前手势或标签化确认**：卖出=长按+标注键位弹窗；
   分支进化=标注键位直达（不可取消但文案明示）；开战=专用按钮（非误触键位）。
9. **焦点永不丢失**：页面/弹窗关闭后焦点回到来源；空格/空商店格可停留，
   无效 `C` 给反馈（闪+短震），绝不静默吞输入。
10. **60s 无操作熄屏**：准备期不限时，靠熄屏+暂停控制放置；重进无惩罚。

## 6. 开放问题

1. **γ 的真机阈值**（最大开放项）：双击窗 200ms 下，纵移连打误横移率与故意
   双击成功率的实测（§7-3）。若误触发率超标 → 切 **β 备胎**：
   C·C 双击切换 列模式（整列高亮，A/B=左右选列）/ 格模式（四角括号，
   A/B=上下），模式态在光标形状上永远可见；拿起/放下仍为 C 单击。
   β 不占用长按键位，模式可视化是其相对原草案的关键补丁。
2. **商店 4 格与备战 6 格的经济复验**：`SHOP_SLOTS=4`、`BENCH_SIZE=6` 重跑
   m2 口径（刷新频率、卖出频率、局长带宽）；畸变则调池深而非回 5 格/9 格。
3. **4 行战场（6×4）的近远程平衡**：后排缓冲少 1 格，`experiment_melee`
   复验；若远程被压制过度，调突进倍率（0.6→0.5）而非加行。
4. **准备页敌方区内容**：现为上轮快照（dimmed）；备选「空地形+轮次水印」。
   快照的优势是免费的败因回看，劣势是首轮空态与少量视觉噪音。
5. **教学退场进度的存档字段**（手势成功 3 次计数）是否随局重置——
   倾向跨局持久（老玩家不再被打扰）。
6. **卖出撤销窗**：倾向不做（长按+弹窗双确认已够；撤销窗会削弱卖出的
   严肃性并多一个状态）。真机误卖读数超标再议。
7. **分支进化弹窗的默认键位分配**是否随本局已选记忆（第二次 3 伊布
   默认停在上次选的分支）——低成本人情味，待 M4 手感试。
