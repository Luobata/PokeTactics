# 18 · 角色专属技能与物种部件动作

2026-10-05，第四批。目标是让站位和选人产生不同结果，并且从动作中读出结果。
本批覆盖核心 8 只的玩法，部件动作实际覆盖喷火龙、水箭龟、妙蛙花。
未实现独立星级、28 核心池、全角色骨骼编辑或 ESP32 绘制后端。

## 角色设计与验收

沿用当前数据选出的真实招式，不通过改名字制造新技能。每个专属机制限定对象数、
范围和触发顺序，侧伤独立计算防御和属性，不回能、不额外掷随机状态骰。

| 角色 / 招式 | 当前战术作用 | 可观察的验收与反制 | 部件进度 |
|---|---|---|---|
| 喷火龙 / 喷射火焰 | 主目标周围 50% 溅射 | 抱团会波及；分散站位减少波及 | 已接入身体、翼、近侧手臂；普攻抬爪助力火弹，大招展翼喷火 |
| 水箭龟 / 水炮 | 一格宽前向射线，最多两名额外敌人各 45%，主目标退一格 | 所有伤害先结算再击退；错位躲贯穿；边缘/占位阻止击退 | 已接入双炮独立挂点和后坐 |
| 妙蛙花 / 日光束 | 实际掉血的 35% 治疗两格内 HP 比例最低的受伤友军，包含自己 | 过量伤害不增加治疗；全员满血无治疗；治疗对象需靠近 | 已接入花盘、双藤鞭；普攻挥藤，大招花盘聚光 |
| 雷丘 / 十万伏特 | 三格射程，最多两跳，每跳两格内，55% / 35% | 每个目标至多一次；地面免疫截断电链；拉开距离减少连锁 | 耳、尾、脸颊挂点已有定义，轨道待制作 |
| 胡地 / 精神强念 | 闪现至最弱敌人邻格再施法 | 无合法落点时不闪现；保护残血单位周边，切入后可集火胡地 | 汤匙、焦点已有定义；仍使用原整身与瞬移演出 |
| 耿鬼 / 舌舔 | 命中偷至多 20 能量，自身获得实际偷取量的一半 | 在主命中回能后取余额；免疫不偷；低能量限制收益 | 下颌、阴影、口部挂点已定义，轨道待制作 |
| 隆隆岩 / 地震 | 自身邻格其他敌人各 40%，实际受伤的存活目标短暂畏缩 | 0.3 秒畏缩遵守现有控制保护；飞行免疫；不围殴减少波及 | 左右臂与地面挂点已定义，轨道待制作 |
| 卡比兽 / 破坏光线 | 自身邻格 50% 波及，自愈最大 HP 的 15% | 拉开距离减少近身伤害；集中伤害压过续航 | 腹部、头与口部挂点已定义；保留原蓄力/光束 |

这些比例是第一版可测参数；定向场景证明触发和边界，不等于阵容平衡已验证。
喷火龙、胡地、卡比兽保留已有机制，其余五只新增。当前 84 只棋子中有 8 只专属、
75 只通用、1 只无可释放招式（凯西）。技能命中率沿用数据，例如水炮不是必中。

## 统一接口与不同身体

`character_rigs.py` 用统一结构描述每个物种自己的命名部件、局部支点、绘制层级、
挂点与 `attack/cast → windup/strike/recover` 轨道。画布留出边距，使用固定脚点定位。
动作按时间纯采样，支持镜像、倒放定位，冻结/死亡保持原有优先级。

喷火龙、水箭龟使用原始单帧精灵切片；妙蛙花额外使用原创程序化像素藤鞭。
这不等于已获得完整手绘骨骼素材。切片缺少被遮挡的身体信息，后续应补画手臂、
翅膀根部等独立素材；轮廓变化大的跳跃、转身和倒地优先用专用帧，不强拉切片。

特效从 `mouth`、`left_muzzle/right_muzzle`、`flower_focus` 等真实动作挂点发出。
技能附属效果采用模拟器的 `skill_effect` 记录，只呈现真实命中、治疗和能量转移。
链跳从上一名受击者连至下一名；治疗从主命中目标回流至实际受益者。

通用框架边界：动作采样器、挂点和预算不依赖宝可梦规则；物种部件数据和技能编排
归游戏内容包。清单已导出数据；Pillow 变换和特效编排仍是 Python，C 采样器、
设备缓存、旋转成本和真机帧预算尚未验收。

## 因果事件与回放

新增可选元数据 `(t, skill_effect, caster, target, arch, effect, payload)`。
`cast_index` 指向原始主施法事件；`event_count` 只归属紧随的确定事件包；几何坐标
记录结算前位置。旧 attack/cast/regen/unit_state 等 tuple 不变。

时间轴将附属状态对齐所属主技能命中，不按同时间或物种猜归属，避免第三方提前
回血、击退等待受击者自身动作恢复。同刻其他独立动作仍保留自己的因果顺序。
伤害、生命、能量以模拟器状态为准，动画不能回写战斗。

## 可复现验收

```sh
python3 sim/experiment_signatures.py --seeds 7 11 29
python3 tools/acceptance/system_acceptance.py --demo --balance --presentation --output .build/acceptance/batch-d.json
```

第一条为 8 角色 × 3 种子 × 档案开关，共 48 个定向首轮施法场景。夹具预充能、
固定站位、增加生命，太阳治疗含受伤友军；初始状态也记录为事件。所有后续效果
通过真实 `Battle._act` 产生，无伪造伤害或治疗。

浏览器 `/animation-lab` 展示 16 段普攻/大招和覆盖进度；`/animation-editor` 用
同场景默认参数与调参结果比较，并显示部件、战术、反制和实际附属效果记录。
这仍是四参数表现编辑器，逐部件时间轴/关键帧编辑尚未实现。

验收要求包括：真实对象/范围/免疫/过量伤害/控制保护；时间轴无提前状态；
镜像与固定脚点；真实输出像素有变化；重放确定性；粒子预算和 HUD 保持可读。

后续按每角色交付动作素材、轨道、技能场景和反制场景推进剩余五套部件，随后扩展
核心池、星级和阵容关系。逐部件编辑器要复用当前命名轨道，补关键帧增删、支点、
曲线、事件标记及资源版本校验；不会重新发明一套与战斗脱离的演出时钟。
