# 离线远征、主搭档与战斗预算 v1

状态：2026-10-05 批次 F；玩法闭环可验收，数值均衡尚未完成。入口 `/expedition`，实战仍由 `/demo` 驱动，动画实验室继续负责演出制作。

## 本次实现

- 局外档案：已见、实际上场、随队获胜物种；已完成局数、冠军、前四、累计最高回合。经典局和远征局均可推进挑战。
- 4 个挑战：上场 1 种解锁居合斩；上场 3 种解锁雷丘搭档资格与冲浪；完成 1 局（失败也算）解锁睡觉与剩饭开局装备；上场 6 种解锁卡比兽搭档资格与气势披带。
- 已有 84 只商店宝可梦仍可抽到。解锁的是主搭档身份/开局配置，未把旧棋池重新锁住。永久奖励不叠加基础攻击、防御或生命。
- 初始主搭档为妙蛙花、喷火龙、水箭龟三个家族。开局自动按普通价格买入基础形态（妙蛙种子/小火龙/杰尼龟），费用从首轮金币中扣除。雷丘用皮卡丘开局，卡比兽按自身 3 费购买。
- 选择主搭档后，同进化链按部署顺序第一只上场棋子获得特性和学习招式；其余副本保留普通身份。进化后仍匹配家族，未上场则不生效。采用此规则暂不需要给每只 OwnedPiece 增加永久实例 ID，界面明确显示当前载体。

## 主搭档和普通棋子

种族技能与搭档身份是两个维度。选喷火龙、抽到卡比兽：喷火龙家族中一只获得「振翼鼓舞」；卡比兽照常使用原生技能，但没有「分享便当」。无需削弱普通棋子的招式来体现搭档价值。

| 搭档 | 实际战斗特性 | 配队含义 |
| --- | --- | --- |
| 妙蛙花 | 首次大招治疗两格内最虚弱受伤队友 20% 最大生命，每场一次 | 配坦克、持续作战 |
| 喷火龙 | 首次大招给两格内最近至多两队友各 18 能量，每场一次 | 调整站位、启动队友大招 |
| 水箭龟 | 开场给两格内最近至多两队友 20% 减伤 6 秒 | 保护脆弱后排或第一排 |
| 雷丘 | 前两次命中普攻为两格内最低能量队友提供 16 能量 | 配高价值大招角色 |
| 卡比兽 | 首次受伤至半血且存活时，治疗两格内至多两名受伤队友各 15% | 前排承伤与团队续航 |

特性都排除自己，次数有上限，无无限回能链。技能效果日志有中文说明；血量/能量以 `unit_state` 为唯一权威。新增特性尚无逐角色专属分层特效，不能把数值接入等同于动画完成。

## 招式机器与秘传技

首批把秘传技按适合自走棋的规则重新设计，不照搬回合制原版。永久解锁教学资格；每局出发选一种，不能中途免费换装，也不会覆盖宝可梦原来的大招。

| 招式 | 相容家族 | 效果 |
| --- | --- | --- |
| 居合斩 | 妙蛙花、喷火龙 | 第一次造成伤害的普攻，追加打主目标邻格的一名敌人，普通属性 35 威力；不额外回能 |
| 冲浪 | 水箭龟 | 第一次造成伤害的原生大招，对主目标释放时位置邻格最多两名其他敌人追加 35 威力水属性伤害；不额外回能 |
| 睡觉 | 首批全部 5 家族 | 第一次半血时行动，治疗自身 25%，本拍不攻击，消耗一个攻击间隔；每场一次 |

开局装备与学习槽分开，装备仍占现有一格，可卸下。当前未实现战斗掉落实体 TM、背包消耗教学、多只普通棋子教学或多招式选择；下一阶段在 OwnedPiece 引入稳定实例身份后再扩展，避免合成/卖出时串教学记录。

## 羁绊

现有 17 种属性羁绊继续按实际上场阵容结算，当前计数包含同种副本。搭档特性增加站位、启动节奏与队友选择，仍不额外占一个羁绊名额，也不重复计算同一单位。

后续可加少量定位羁绊（承伤/突进/施法/支援）和基于家族的去重规则，需要先跑完整队伍实验；暂不增加大量固定角色组合，避免未来扩充物种时维护配对表。每个新羁绊必须能在准备页看到阈值、受益对象和战斗实效。

## 种族值与伤害分离的边界

远征中双方、bot 对 bot、幽灵、野怪均使用 `budget_v1`。经典对局、旧动画样例默认 `legacy`，旧档不会静默切换预算。

种族值仅决定六维分配比例。同费用总点数为 300/420/540，每轴限制在均值 60%–160%，整数化后仍守恒；HP 每点折为 2 生命，攻防/特攻特防/速度各按统一换算。忽略旧角色档案 HP/攻速乘数，保留射程与移动身份；天气、装备、羁绊、技能在统一基础属性之后计算。现有费用划分仍按旧规则，未完成角色费用重分配。

固定点数不是固定战斗价值。32,256 场同费跨物种 1v1 的预算后胜率区间为：1费 2.1%–83.3%，2费 8.3%–87.5%，3费 3.1%–100%。1/2费离散度下降，3费极差扩大。不能宣称已经达到每只强度接近。该样本不含完整组队职责，也不能据此直接把耿鬼改成和卡比兽一样的单挑输出。

下一批平衡验收：固定前排/后排/支援等阵容槽位，对同定位同费角色做换位 A/B；增加群体目标数量、首大招时间、有效治疗、控制与溢出伤害读数；先修鲤鱼王、尼多力诺、耿鬼、卡比兽等极端机制，再讨论费用/技能预算。没有组队证据前，预算模式保持实验标记。

详见 `reports/partner-budget-2026-10-05.md` 与可复跑脚本 `sim/experiment_partner_budget.py`。

## 存档和通用框架边界

`esp32_runtime` 继续只负责 codec、A/B 存储、校验、恢复、导入前检查点；挑战、学习相容性、搭档逻辑都在游戏层，不进入通用运行时。

- 局内 `SessionCodec` schema 2 保存持久 `run_id`、loadout 和累计图鉴快照。schema 1 可迁移且保持经典模式；同一旧备份用原 payload 哈希生成稳定 ID。不同时间点的旧版备份没有共同持久 ID，无法追溯它们是否属于同一局，不能承诺这种跨旧快照去重。
- 写入顺序：更新局内观察 → 持久化 Session → 按 run_id 合并 Profile。档案失败不回滚已提交的战斗，界面提示，读取状态/继续存档会重试。若关闭待同步对局，需要重新继续那份存档；本批尚无全存档后台 outbox 扫描器。
- 新版同一局的重复导入、旧累计快照重试不增加局数/胜数；终局排名冲突拒绝合并，保留旧记录。档案导入会替换而非与当前档案合并，界面先预览并保留检查点。
- 档案与单局分开备份。Profile 独立 namespace `poketactics-meta`、slot `trainer`。物种 ID 支持 uint16，不以 151 为 ID 上限；每局每类观察列表最多 151 条、最多 2048 个 run_id、8MiB 文件上限，达到容量明确报错且不删除去重记录。更大棋池/更长生命周期需升级容量或压缩账本方案。
- 这是 Python host 参考实现，ESP32 NVS 后端和闪存空间预算仍未实现；8MiB 是文件备份上限，不是承诺设备端常驻 RAM 消耗。

## 哈迪斯参考与后续节奏

参考其可解锁武器形态、战绩记录和高难度契约，让一次失败也能带回发现，玩家能选择下一局的目标。官方资料：[Weapon Aspects / Pact](https://www.supergiantgames.com/blog/hades-superstar-update-patch-notes/)、[Permanent Record / Security Log](https://www.supergiantgames.com/blog/hades-the-nighty-night-update-patch-notes/)。本项目选择先做横向解锁；哈迪斯本身也有永久数值成长，两者不能等同。

后续按可验收批次推进：

1. 平衡与实际阵容价值：同定位换位实验、技能预算、部分弱势通用招式改造。
2. 局内抉择：首批 9–12 个海克斯/天赋，阶段三选一、独立 RNG 子流、选择待办和恢复测试；当前仍未实现。
3. 内容与挑战：主题道馆、天气预告/天气改变、可选难度契约、技能机器掉落与教学。每项有独立结算/备份用例。
4. 成长与演出：终形态成长选择、搭档特性的可视反馈、居合斩/冲浪专属动作和技能特效，再扩更多分件与角色特性。
