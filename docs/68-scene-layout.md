# 68 · 场景布局：入口与面板相邻

> 状态：已实现（浏览器）。承接 docs/61（以棋盘为中心的准备界面）与 docs/66（响应速度）。
> 代码：`tools/acceptance/play.html`、`play_layout.js`、`play_layout.css`，海克斯条位置见 `play_interactions.js`。

## 问题

docs/61 的桌面布局把入口坞放在棋盘**左侧**，抽屉却在屏幕**最右侧**打开：点「背包」后视线和鼠标要横跨整个棋盘。
横屏手机上棋盘只占左半边的一小块，备战席和开战按钮占了右半边；竖屏手机的弹层默认盖住大半个棋盘。

## 规则

1. **相邻**：面板总在打开它的入口按钮旁边展开，入口按钮位置不随面板开合移动。
2. **棋盘可用**：面板打开时棋盘仍然可见、可点、可拖（装备、布阵流程依赖这一点）；开战按钮始终可达。
3. **同一套 DOM**：三种布局只靠 `body.layout-desktop / layout-phone / layout-landscape` 与 CSS 切换，面板仍是 `#drawer-body` 里的静态 `section`，保持 keyed 渲染和乐观更新（docs/66），不额外请求服务器。

## 三种布局

| 布局 | 判定（JS 与 CSS 同一组媒体查询） | 结构 | 面板 |
| --- | --- | --- | --- |
| 桌面 | 其余情况 | `棋盘 | 抽屉 | 入口坞`：入口坞固定在最右侧，抽屉在它左边展开，激活按钮带一个指向抽屉的小三角 | 抽屉高度 = 视口高度，与棋盘并排；761–960px 平板为悬浮抽屉，仍紧贴入口坞左侧 |
| 横屏手机（主手机模式） | `(max-height: 520px) and (orientation: landscape)` | 整屏场景：左边棋盘尽量高，备战席一行在棋盘下；右边场景区自上而下是 HUD（回合/生命/金币/等级/人口 + 工具）、顶条（对手、天气/地形/指令/模拟芯片、全场阵容）、提示，右下角是开战按钮；最右是入口竖栏，**商店在竖栏最下方** | 其它面板 = 侧边面板，从棋盘右缘（JS 测量 `--sheet-left`）到竖栏，底部停在开战按钮之上；商店 = 底部托盘（TFT 手游式），一行卡片，右端正对竖栏底部的商店按钮，金币仍在上方 HUD 可见 |
| 竖屏手机 | `(max-width: 760px)` | 顶部 HUD，棋盘，备战席 + 开战，底部固定标签栏 | 底部弹层坐在标签栏上：商店 `peek` 停在备战席下方；其它面板默认 `half`，**高度测量为停在棋盘行下方**（`--sheet-half`），可展开到 `full`；弹层打开时页面底部增加同等滚动余量，可以把备战席滚到弹层上方 |

补充：

* 站点侧栏在手机上隐藏，它上面的「音效」开关由 `play_layout.js` 移到 HUD 工具区；玩法指南用 HUD 里的书本按钮。
* 已选海克斯条：桌面在入口坞底部，横屏手机在 HUD，竖屏手机在备战席标题旁。
* 横屏宽度 ≤ 760px（如 667×375）时，备战席不再撑宽棋盘列（超出部分横向滚动），提示条隐藏；侧边面板至少保留 260px 宽，可能盖住棋盘最右一小条。
* 桌面抽屉打开使舞台变窄时，HUD 用容器查询收起「新开一局」文字和经验说明，保持一行，避免把备战席挤出 720px 高的屏幕。

## 验证

* `tests/test_play_layout.py`：假 DOM 场景覆盖桌面抽屉、竖屏弹层（含 `--sheet-half`）、横屏侧边面板/托盘（`landscapeSheet`）。
* `PlaySceneGeometry`：在 Chromium 中实测 1440×900、1280×720、844×390、390×844，断言面板矩形紧邻其入口按钮（≤16px）、不与棋盘相交、棋盘格与开战按钮未被遮挡、竖屏弹层顶边在棋盘下方，且无页面报错。需要 Node 的 `playwright` 包（`POKETACTICS_PLAYWRIGHT_NODE_PATH` 指向其 `node_modules`），缺失时跳过。
