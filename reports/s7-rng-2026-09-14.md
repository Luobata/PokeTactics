# S7 RNG 分层派生改造 · 2026-09-14

**决策**（docs/09 §2.2 存档设计裁定）：`sim/match.py` 的单流
`random.Random(seed)` 贯穿全局（顺序喂商店/bot/配对/战斗）改为
**分层派生子流**——master_seed → 轮种子 → 用途子流。这是存档系统
（docs/09 §8 落地顺序第 2 步）的前置依赖：轮边界快照从此**零 RNG 游标**。

改动面：新建 `sim/rng.py`（派生函数 + counter 打包）；`sim/match.py`
全部 rng 消费点改走子流。combat/economy/shop/bots 一行未动——
`Battle(rng)` 本就吃调用方传入的 rng，本改造只在 match 层把对的手流
递过去。

## 1. 派生函数（S7 种子协议 v1 定稿）

```python
derive(master_seed, round_no, purpose, counter=0) -> random.Random
# seed_child = sha256( K_<purpose> ‖ master_seed(u32 LE) ‖ round_no(u32 LE)
#                      ‖ counter(u32 LE) )[:8]  →  random.Random(seed_child)
```

- 实现取 **sha256 前 8 字节（u64）做整数种子**，取代 docs/09 §2.2 里
  mix32（splitmix32 finalizer）的示意写法——文档明言「定稿归 S7 种子
  协议，本档是它的第一消费者」，本报告即定稿。理由：① 一局约 1.6k 条
  子流，u32 种子生日碰撞概率 ~0.03%/局（两个子流同种子 ⇒ 随机数序列
  完全相同），u64 降到 ~10^-10，不冒这个险；② 字段定长 4 字节小端
  拼接、purpose 以编译期盐 K_PERS/K_SHOP/K_BOTS/K_PAIR/K_BAT/K_PVE
  参与，无分隔符歧义；③ C 移植用任一 SHA-256（ESP-IDF mbedTLS 自带），
  取同样 8 字节初始化 64 位状态 PRNG——协议只锁「同字节流 → 同子流
  种子」这一步，PRNG 本体随端；
- 随机方法本体仍是标准库 `random.Random`（整数种子跨 Python 版本、
  跨平台、跨 PYTHONHASHSEED 稳定）；
- `pers` 开局发牌流从旧实现 `random.Random(seed ^ 0x5EED)` 改走
  `derive(seed, 0, "pers")`——XOR 弱混合退役，全部随机消费点归一到
  同一派生函数（docs/09 §1.2「只在开局用、不跨轮」语义不变）。

## 2. counter 表（同一轮内多次消费的递增游标）

| 用途 | counter | 消费点（match.py） | 对齐 docs/09 |
|---|---|---|---|
| pers | round_no=0 恒 0 | 人格/能力发牌（`__init__`） | §1.2 派生不存·人格发牌 |
| shop | **席位×256 + j**；j=0 免费滚，j≥1 = 第 j 次手动刷新 | 开局铺货（round 0）+ 每轮免费重滚（j=0） | §2.2 shop_seed 第 j 次；**j 即 1B refresh_count 游标（§1.1）**，M5 人类席直读档现派生 |
| bots | 席位 | `decide()` 传入的决策 rng：L0 买入/卖出/摆位随机、20% 刷新门、**bot 手动刷新的商店抽取** | §2.2 decide_seed「开战后才消费、永不跨写点」——bot 刷新不跨写点，故归 bots 流不占 j |
| pair | 恒 0（每轮一条） | ≤20 次配对洗牌尝试 + 幽灵镜像源选择，顺序消费 | §2.2 pair_seed「配对/幽灵」；配对完整发生在写点 A 后，无游标需求 |
| battle | **i**（该轮第 i 场，0 起） | PVP 按对序、幽灵战殿后；PVE 轮 = 各家野怪战 | §2.2 battle_seed 第 i 场——**单场可独立回放** |
| pve | i（第 i 个存活者） | 野怪轮胜利掉金 2-3 | §2.2 pve_seed「野怪轮掉金」 |

商店 counter 打包 `shop_counter(seat, refresh_count) = seat×256 + j`：
256 = 存档 refresh_count 的 u8 游标宽度——席位占高段、刷新序占低段，
恢复时直读训练家块里的 (seat, refresh_count) 现派生，无需任何流位置
状态。j≥1 在当前全 bot 局面不出现（bot 刷新走 bots 流），是给 M5
人类玩家席预留的通道——这正是存档设计里「唯一的跨写点随机消费」。

子流互相独立是本改造的核心收益：任何一处消费次数变化**不会移动**
其他用途的随机数序列（旧单流下商店多抽一次，其后全部战斗骰位移）；
第 r 轮的全部随机只依赖 `(master_seed, r, purpose, counter)`，
不存在跨轮生成器状态。

## 3. 验收读数

### 3.1 同种子重放（宪法 2.2 升自检）

- `match --seed 7 -v` 跨进程 × 跨 PYTHONHASHSEED（0/12345/999/7）
  逐字节一致（唯一差异行 = 决策耗时 perf_counter 抖动，非游戏内容）；
- 种子 100..119 共 20 局批量摘要（局长/战斗数/淘汰顺序/排名/末金币）
  三次独立进程（默认/12345/999）完全一致；
- `experiment_match --games 50 --seed 100` 内建重放自检「通过」，且
  整批四条读数在 PYTHONHASHSEED=999 下复跑逐行一致。

### 3.2 战斗层不受影响（combat 未触碰）

`prototype.py --games 100` 改造前后输出**逐字节一致**：确定性自检
通过、A51/B49、时长中位 7.4s——prototype 用自己的单流
`random.Random(seed)`，与 match 层改造无关，读数不位移。

### 3.3 M2 四条验收（第三基线，50 局 × 8 bot）

| 指标 | 旧基线（羁绊关） | 新基线（羁绊开） | **第三基线（+S7 分层派生）** |
|---|---|---|---|
| 局长 | 29.7（中位 31） | 28.4（中位 29） | **29.1**（中位 29，区间 24-31，36/50 提前决出） |
| 人格方差 | 0.136 | 0.376 | **0.189**（balanced 5.07 / copycat 3.85 / roller 4.59 / saver 4.49） |
| 决策耗时 | p99 0.67ms | p99 1.04ms | **p99 0.73ms** / 均值 0.20ms |
| 无死锁 | 84% / 0 | 84% / 0 | **85% / 0** |
| 能力层名次 | L0 7.92 / L1 2.87 / L2 4.98 / L3 4.52 | L0 7.90 / L1 3.69 / L2 4.27 / L3 4.22 | **L0 7.88 / L1 3.61 / L2 4.32 / L3 4.34** |
| 冠军人格 | balanced×15 / copycat×17 | copycat×19 / saver×15 | **copycat×23 / roller×10 / balanced×9 / saver×8** |

**位移原因**：RNG 流整体更换（种子 → 随机数映射全变），非平衡性改动。
同一 master_seed 下商店抽取/配对/战斗骰全部落在不同的随机数上，对局
树从 R1 起分叉——这与 S3 翻羁绊时的位移同性质。判读：四条验收全过；
能力梯度（L0 垫底、决赛圈 L2/L3）与人格结构（copycat 领先）形状保持；
局长 28.4→29.1 回到 28-34 带内中段；人格方差 0.376→0.189 更均衡属
50 局样本的抽样波动（冠军分布单格 ±3 即可见）。第三基线已追加至
docs/systems/S4-economy.md §9.1。

单局读数（新种子协议）：seed 7 → 26 轮、106 场战斗、3合1×24、成型
中位 R9（7/8）、掉血轮 21/26；seed 100 → 31 轮打满、110 场、3合1×22、
成型中位 R7、掉血轮 27/31。

## 4. 对存档系统的解锁说明

docs/09 §8 落地顺序第 2 步（本改造）完成，`sim/save.py`（第 1 步
参考实现，实际已可开工）现在拥有全部前置：

1. **轮边界零游标**：档里 (master_seed, round_no) + 训练家块 1 B
   refresh_count 即可在恢复时现派生当轮全部子流
   （§1.1 字段表原样成立，无新增字段）；
2. **跨写点消费已收敛**：准备阶段中段（写点 A/B/C 的统一档面语义）
   之后的随机 = 玩家手动刷新（shop 子流 j≥1，游标进档）+ 开战后
   bots/pair/battle/pve 子流（全部现派生，快照里零状态）；
3. **只读回放**：战斗页从 (master_seed, r, battle, i) 可独立重演
   单场——战绩页/观战回放的种子协议基础就位；
4. **宪法 2.2 自检升级路径**：「存档→恢复→续跑 ≡ 连续跑」的逐轮
   逐场一致验收，在 sim/save.py 落地后即可常驻（分层派生使其成为
   结构性保证：恢复不重放历史轮，当轮子流与历史无关）。

遗留两处文档口径（非代码问题，供后续修订）：S4 §6「整局单 rng」
表述已成历史口径（§9.1 已注记）；docs/09 §2.2 的 mix32 示意与本报告
§1 的 sha256 定稿并存，正式 S7 文档起草时以本报告为准。
