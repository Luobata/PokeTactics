# 48 · 逐宝可梦动作设计与公开资料

2026-10-14。范围：当前竞技模式的 **53 只普通形态角色**。本文是资料核验与动作设计提案，不是动画实装或视觉验收记录。角色职责与原生技能来自当前工作区；物种资料来自固定版本的 PokeAPI 数据；动作参考来自固定版本的 SpriteCollab。未导入外部精灵图、未改变模拟规则。

## 1. 每只独立设计的内容

同一种身体大类只适合帮助组织制作工具。每只仍要独立回答：它是什么形态、靠什么移动、用什么部位发力、在本项目帮助谁、如何让玩家读懂这个行为。

| 维度 | 必须记录的内容 | 依据 |
|---|---|---|
| 身份与形态 | 物种 ID、普通/地区/超级等形态、图鉴分类、体型、版本、性别外观差异 | PokeAPI 物种与形态资料，实际采用的资源 |
| 行为特征 | 图鉴中的运动、觅食、威吓、发光、发声、保护等行为；选择适用于当前形态的描述 | 带游戏版本的图鉴条目；不要由静态图猜生态 |
| 项目职责 | 攻击/防守/辅助、普攻射程、原生技能目标、实际效果及条件分支 | sim/arena.py、sim/arena_skills.py |
| 身体设计 | 支撑点、重心、附肢关系、发力链、技能源点、遮挡和轮廓 | 逐角色设计判断，并用多姿态参考校正 |
| 动作规格 | 待机、移动、普攻、技能、受击、退场；每个动作的关键姿态与轨迹 | 独立角色卡与分镜，不能由一个通用标签代替 |
| 生产状态 | 资料已核验、姿态提案、素材待补、轨道已制作、画面已验收 | 分开记录，不能把技能特效覆盖当作身体动作完成 |

共享的可以是播放器、插值、事件时钟和校验器。身体拆件、支点、轮廓变化和动作节奏属于每只角色自己的内容。同为四足，肯泰罗的角与肩背、风速狗的颚与鬃毛、太阳伊布的额珠与分叉尾，其发力与技能语义不同。

图鉴分类也不等同于现实动物分类。例如“甲壳宝可梦”“乘载宝可梦”是原作分类；“壳体承重”“长颈与鳍肢传力”是本项目的动作设计解释，二者应分开标注。

## 3. 如何拆解动画

### 先拆行为与阶段

先写清动作动词，再选择渲染方法。例如水箭龟是“稳住壳体 → 炮口瞄准与蓄压 → 双炮释放、身体后坐 → 回稳”；大舌头是“识别受伤友军 → 伸舌连接 → 治疗、合法时拉回 → 舌与身体复位”。两者不能共用一个缩放前冲动作。

每个普攻与技能先画静止、蓄势、释放、命中/效果生效、过冲、恢复的分镜。先让蓄势、释放、恢复三个身体剪影明显不同，再补中间姿态；输出更多帧不会自动补出新姿态。关键姿态数量按动作复杂度决定，不要求每只画满 60 张。

身体发力链必须可以解释：脚/支撑点 → 躯干重心 → 肩、髋、颈或体节 → 拳、爪、颚、炮、花、核心等作用点。浮游者以影子和悬浮中心作基准，蛇形者检查体节连续，不能套人形手脚。

### 再拆部件、遮挡和轨迹

1. 标出承重基座、主动发力件、跟随件、技能源点与受击变形区。
2. 为每只单独标支点、父子关系、前后层级、接缝与运动极限。头角、臂钳、背炮是不同的结构。
3. 用遮罩提取可见件，补画被原图遮住的连接处、背侧肢体、口腔等。矩形裁切不等于获得干净部件。
4. 保持脚点、影子与身体质量一致；肢体过冲和躯干回稳采用各自轨迹。
5. 转身、张嘴、翅膀透视、翻滚、倒地和大幅软体变形，优先补独立姿态帧。可采用“少量新帧 + 局部轨道”的混合方式。

当前 source-slice 制作合同最多 8 部件，且没有完整层级骨骼、IK 或自动补遮挡能力。下文的解剖拆件是设计清单：实际制作时可合并次要跟随件；超过现有能力的姿态需要素材和管线扩展，不能声称切一张静态图就全部完成。格式与现有能力见 [21 · 制作与验收](21-animation-authoring-and-acceptance.md)。

### 怎样阅读 PMD 动作资料

[格式说明](https://wiki.pmdo.pmdcollab.org/PMD_Sprite_Format)中，动作图横向是帧序、纵向是方向。AnimData.xml 记录 Durations，以及部分攻击的 RushFrame、HitFrame、ReturnFrame。Offsets 图提供身体中心、头和双手锚点，Shadow 图记录影子位置；**它们不是已经拆好的图层、遮罩或骨骼。**

逐只采用以下顺序：查实际形态目录与署名 → 解析 CopyOf → 选择与棋盘视角接近的方向 → 按每帧停留播放 → 看哪些部位先动、重心怎样转移、轮廓何时改变 → 提炼自己的部件和关键姿态。自动统计动作名与帧数只完成了资料索引。

Duration 的单位为 1/60 秒，是时间刻度，不代表每秒 60 张独立图。水箭龟 Attack 定义了 13 个帧槽，总时长 25/60 秒，Rush/Hit/Return 为 1/7/10；这是参考数据，不能原样覆盖本项目的演出轴。

### 最后绑定本项目事件

- 身体轨道服从 ActionTiming 的 start、release、impact、recover_end；参考节奏按阶段适配。
- 近战接触、远程发射、弹道到达与辅助效果生效必须分别判断。参考 Shoot 的 HitFrame 不能未经核对就当作我方弹体命中敌人的时间。
- 治疗、回能、护盾、净化、嘲讽、地形与击退由对应权威事件决定，不能因为动作看起来该发生就新增结果。
- 条件追击使用施法前快照与真实命中事件；当次新中毒、新易伤、新岩钉不能反过来满足当次条件。
- 受击与状态也按物种设计：重甲的质量回弹、飞行者的翼姿失衡、软体的形变各有区别。冰冻锁住当前姿态，死亡覆盖恢复，持续状态层与身体轨道分开管理。

## 6. 逐只制作与验收顺序

1. 先补每只的形态与行为资料卡，确认当前原生技能，并筛选确实适用的动作参考。
2. 先做无特效的三张关键剪影，再决定新姿态帧、局部拆件或混合方式；无法表达动作时补素材。
3. 制作待机、移动、普攻、技能、受击、退场，并记录技能特效和身体动作各自的完成状态。
4. 在实际棋盘尺寸下检查身体确实动起来：支撑点不漂、附肢有路径、释放与恢复可分辨、左右朝向接缝正确。不能只看放大的静态图或像素哈希变化。
5. 再接技能、状态和场地层，验证事件对齐、条件分支、受击叠加、冰冻、死亡、倍速与倒放。
6. 最后检查多人同屏的遮挡、阅读负担与帧耗时；减少装饰时仍保留身体动作和真实效果。

建议先用怪力、水箭龟、大岩蛇、风速狗、巴大蝶、妙蛙花验证六种不同表达，再逐只推进剩余角色；先做这六只不意味着其他角色套用六套成品动作。每只仍提交自己的卡、拆件、分镜与验收。

## 7. 动态验收贯穿制作过程

无需等一只全部精修、更无需等 53 只全部完成。每只按阶段交付可播放样片，前一阶段确认后再投入下一阶段；一张角色卡不能代替动态样片。

| 阶段 | 动态交付物 | 验收重点 |
|---|---|---|
| 动作方向 | 粗剪影或简化部件串成短片，呈现蓄势、释放、过冲、恢复 | 能否看出它如何发力，物种结构与项目职责是否一致；不要求精修素材。 |
| 身体制作 | 补过遮挡与新姿态的完整身体短片，分别演示待机、移动、普攻、技能、受击、退场 | 重心、支撑点、肢体轨迹、遮挡、接缝和棋盘尺寸下的轮廓。此阶段需要单独检查身体。 |
| 技能合成 | 身体与技能源点、弹道、命中、辅助效果合成，保留身体样片作对照 | 发射点跟随、伤害或援护事件对齐、收招、状态与死亡叠加。 |
| 战场验收 | 两队混编、同刻施法、场地与状态组合短片 | 同屏遮挡、可读性、预算与播放一致性。 |
