## 1. 状态、证据与统一入口

| 状态 | 含义 |
|---|---|
| `in_progress` | 本批正在实施；只有对应代码、自动检查和玩家验收证据齐备才能完成 |
| `pending` | 尚未实施的工作包；已有设计或旧系统不等于该优化已交付 |
| `passed` | 某次、某版本、某项检查通过；不是整个系统永久通过 |
| `failed` | 命令异常、非零退出、输出失败判词或成功标准未满足 |
| `skipped` | 本次未选择或被中断；不得解释为通过 |

统一执行器仅使用 Python 标准库，不安装依赖、不修源码、不代替浏览器或真机验收。
所有相对路径以仓库根目录为基准，使用当前 Python 解释器运行子命令。

```sh
# A：每批必跑，覆盖当前 tests/、编译检查、差异空白检查、真实进程重启恢复
python3 tools/acceptance/system_acceptance.py --output .build/acceptance/base.json

# D：需要验证整局 Demo/API/帧资源时，固定种子 7 与 42
python3 tools/acceptance/system_acceptance.py --demo --output .build/acceptance/demo.json

# B：规则变化后的整局读数与同种子重放自检，默认 40 局、seed 20261004
python3 tools/acceptance/system_acceptance.py --balance --output .build/acceptance/balance.json

# 完整已选自动检查；首轮修复完成后由集成验收统一执行
python3 tools/acceptance/system_acceptance.py --demo --balance --presentation --output .build/acceptance/full.json
```

执行内容：`python -m unittest discover -s tests -v`、
`python -m compileall -q sim tools tests esp32_runtime`、`git diff --check`、
`python tools/acceptance/persistence_selftest.py`（临时目录与临时端口，不写玩家存档）。
`--demo` 增加 `python tools/acceptance/demo_selftest.py --seeds 7,42`；
`--balance` 增加 `python sim/experiment_match.py --games 40 --seed 20261004`。
`--presentation` 导出核心 8 角色各一段普攻和技能，共 16 段样片，并导出、校验资源清单。
平衡命令包含该脚本现有的重放自检和四条整局判据，不新增或暗改健康阈值。

退出非零或输出 `FAIL` / `FAILED` / `FAILURE` / `FAILURES`、整局“存在未通过项”、
重放自检失败均记失败；发现 0 个单测也记失败。一次失败后继续收集其余已选检查，
完整输出同时打印并写入 JSON。未选 Demo/平衡明确记 `skipped`。
`--timeout` 默认每命令 1800 秒；超时与中断会终止该检查及其 Demo 服务子进程，保留诊断。
`--balance-games`、`--balance-seed` 可显式调整样本，报告记录原始命令，不自动改阈值重跑。
编译缓存写入 `.build/system-acceptance-pycache`，JSON 默认 `.build/system-acceptance.json`。

退出码：全部已选检查通过为 0；检查失败为 1；报告写入失败为 2；用户中断为 130。
JSON 的 `status=passed` 只证明本次 `selected_checks`，不覆盖下面的 pending 工作包。
Demo 依赖既有 Pillow 和相邻 PokeWalk 素材；缺少依赖应失败并保留输出，不自动安装。
QualityGate MCP 不可用；本机 CLI 可执行，但本项目未匹配有效 Python 规则，不能将空覆盖当成项目检查通过。

## 3. 模块 1：核心循环与局长

- **状态／依赖**：当前循环已有；玩家时间预算 `pending`。依赖包 A 的正常推进与淘汰出口。
- **玩家验收动作**：手动开局到首战，连续玩完整局；另做一局早期淘汰，直接查看结局。
  记录准备操作、开战等待、观看与淘汰后等待四段时间。
- **自动验收**：A + D + B。补逐轮阶段合法性、自然结束和上限裁决用例，记录强制终局比例。
- **成功标准**：无流程死路；轮数单调、每席最终名次完整；阶段转换不重复发收入或奖励。
  时长目标使用当期批准的规则配置，不能把 28 轮直接认定为适合玩家的 20–30 分钟。

## 4. 模块 2：棋子、角色与技能

- **状态／依赖**：核心 8 角色视觉演出与专属机制已交付，阵容策略小闭环及完整核心池仍 `pending`。
  8 角色为喷火龙、水箭龟、妙蛙花、雷丘、胡地、耿鬼、隆隆岩、卡比兽；第四批从 3 种扩到 8 种玩法签名。
  依赖真实命中、回能与事件合同。
- **玩家验收动作**：查看核心 8 只的角色卡，预测各自技能作用；在动作研究室观察溅射、
  切入、自愈、贯穿击退、治疗、连锁、吸能和畏缩。分别选一个有利局面与一个被反制局面。
- **自动验收**：A + D；包 B 开始后补逐角色标准靶场，包括能量可达、技能能触发、
  作用对象与效果正确、缺招式时不显示不可兑现的技能。平衡读数用 B 另存证据。
- **成功标准**：角色卡来源与实际机制一致，招式有中文可理解说明；拥有技能不等于已证明
  实战价值。小闭环须记录每角色强项、短板、适配队友及至少一种实际可行反制。

## 5. 模块 3：战斗、站位与目标选择

- **状态／依赖**：显式坐标、命中射程、冲锋与公平修复 `in_progress`；风筝/复杂反制 `pending`。
- **玩家验收动作**：将单只放在己方四角分别开战；将远程置后、坦克置前；留空格、换左右；
  再分散对抗溅射，核对开场位置与目标变化。
- **自动验收**：A + D + B；必须覆盖四角 deploy、交换/空格保存、阻挡与无法到达、
  冲锋结束仍超射程、同刻行动的交换阵营对照。
- **成功标准**：准备页坐标逐只对应 deploy，合法伤害满足对应技能的射程合同；
  同输入可复现。公平性报告列出样本和区间，不能靠一个随机种子的胜负或缩 tick 掩盖边序。

## 6. 模块 4：属性与羁绊

- **状态／依赖**：现有规则回归随包 A；缩池后的计数语义、阈值与阵容路线 `pending`。
- **玩家验收动作**：上/下场使羁绊跨越阈值，重复上同名棋再比较；查看增益对象，
  购买前判断是否会使目标羁绊成型。
- **自动验收**：A + B；覆盖上场/备战隔离、同名计数的明确规则、阈值上下边界、实际受益单位。
- **成功标准**：显示计数与战斗施加一致。R2 必须先裁定同名是否唯一计数，再验证核心池载体
  和阈值可达性；不得一边改唯一计数，一边直接沿用原 2/4/6 表。

## 7. 模块 5：齐射与组合技

- **状态／依赖**：开场结算公平和事件语义随包 A；新组合技 `pending`。依赖命中/死亡合同。
- **玩家验收动作**：双方均满足齐射条件开战，再交换阵营，核对开场伤害和死亡次序。
- **自动验收**：A + B；覆盖触发阈值、每队次数上限、双边同刻触发、死亡只派发一次，
  明确是否回能和施加状态；采样开场损血与普通行动前死亡。
- **成功标准**：双方使用同一规则，开场顺序不产生未经设计的单边额外机会；
  新组合技不进入本批完成清单，后续须给出反制及边际贡献证据。

## 8. 模块 6：状态与天气

- **状态／依赖**：真实命中触发与 PVP/PVE/幽灵天气一致性 `in_progress`。
- **玩家验收动作**：观察属性减益命中、免疫和到期；在天气切换轮进入普通战、野怪战和幽灵战，
  核对 HUD/预告与实际效果。
- **自动验收**：A + D + B；覆盖确定命中与落空、免疫、控制占槽/到期/递减、侧击策略、
  三类战斗同天气入参，以及天气与装备、多段的组合。
- **成功标准**：状态依据直接命中结果触发，不读事件尾字段猜伤害；三类战斗一致。
  修复前旧平衡不作为新基线，须另报控制覆盖、最长连续受控时间和 DOT/治疗贡献。

## 9. 模块 7：成长、进化与升星

- **成功标准**：本批修复旧系统的错误转换与记账；不得标为新星级已完成。

## 10. 模块 8：商店与共享池

- **状态／依赖**：锁店与守恒 `in_progress`；抽样权重和缩池供给调整 `pending`。
- **玩家验收动作**：锁住商店，开战进入下一轮，对照牌与锁定状态；解锁后再换轮；
  在备战满、人口有空位及买第三张可合成等容量边界尝试购买。
- **自动验收**：A + D；覆盖锁定/解锁、免费刷新次数、失败购买零扣费、预留/购买/卖出/
  淘汰归还总量守恒；后续 1/2/3 人同行与概率曲线用 B 配合专门供给实验。
- **成功标准**：锁定语义及是否额外花费有明确 UI，结算不意外换掉锁住的卡；
  每次失败不丢钱、不丢棋、不改变池。满备战立即合成与卡池恢复后潜在合成容量已在首批实现；
  供给权重与缩池实验仍 pending。

## 11. 模块 9：经济、转型与追赶

- **状态／依赖**：当前规则回归随包 A；策略消费出口与转型优化 `pending`。
  依赖星级收益与统一 AI，不能先以堆积金币直接断言收入过高。
- **玩家验收动作**：分别攒利息、升人口、刷新追卡，核对下一轮收入；落后时尝试转型与补给。
- **自动验收**：A + B；验证收入先后、利息阈值、胜败连、刷新/经验扣费；后续统计出局存款、
  可购买升级、追星支出与早期落后者前四率。
- **成功标准**：收入可解释、交易无负余额与重复结算；不同策略的成立需要配对种子和样本外
  对照，不将一次总体局长通过当作经济平衡已证明。

## 12. 模块 10：装备与奖励供给

- **状态／依赖**：进化石覆盖装备的事务修复 `in_progress`；双槽/行为装备/专属件 `pending`。
- **玩家验收动作**：给已装备勇基拉使用进化石；尝试非法对象、库存不足、卸下、卖出，
  对照装备、组件与棋子没有无解释消失。
- **自动验收**：A + D；覆盖装备/库存/池整体事务、失败零副作用、合法卸回或拒绝策略。
  新触发装备须补同刻护命/死亡与触发链上限用例，再跑 B。
- **成功标准**：不会吞掉旧装备；页面说明与实际效果一致。双槽扩展须先有供给分布，
  使用率按“有组件且有适配棋”计算；未实现的装备不出现在完成清单。

## 13. 模块 11：PVE、配对与终局公平

- **状态／依赖**：天气入参等一致性 `in_progress`；PVE 机制重做与同轮名次裁定优化 `pending`。
- **玩家验收动作**：进入固定野怪轮查看奖励；遇到幽灵确认来源；核对淘汰名次、

## 14. 模块 12：AI 与难度

  卖掉核心或按备战羁绊高估上场；对比不同人格的支出轨迹。
- **自动验收**：A + B 只能给当前回归与诊断；包 B 需补候选阵容、阈值贡献、复制件边际收益、

- **成功标准**：不能把既有四条整局判据通过解释为 AI 难度已达标。专项报告应给出
