**PokeTactics 全系统设计评审 · 2026-10-04**

评审基线：`eb70bbbeb3b5121cef3b23d88c4ca6792a923490`。以当前 Python 实现、Web Demo 和有效设计文档交叉核对；三名子代理分别审查战斗、经济整局、产品体验，主代理补充实际界面检查、运行验证和事件回放检查。未修改游戏代码。本文的“建议”不是已经通过的设计裁定。

**总体判断**

项目已经具备完整的规则实验平台：购买、自动战斗、羁绊、装备、天气、状态、PVE、八人淘汰局均有骨架。现阶段的主要欠账是：玩家决策能否真实作用于战斗、追卡是否有持续收益、系统之间是否使用同一套规则，以及玩家能否理解并完成一局。

最值得推进的主线是：**先修规则与交互一致性 → 做成角色与升星构筑的小闭环 → 补教学、存档和结算 → 扩装备与天赋 → 验证设备版**。不宜用更多棋子、更多乘区或更多特效替代这些工作。

当前处于迁移中：[核心玩法方向](/Users/bytedance/luobata/PokeTactics/docs/13-core-gameplay.md:29) 的 28 核心池、最终形态直售后独立升星、双槽、天赋，尚未整体落地。代码仍是 84 物种旧成长体系；已落地的是三张专属档案、六类通用技能以及新的节奏和视觉。不能继续引用旧版“全部棋子只有模板普攻”或“战斗中位 7.5 秒”作为当前事实。

**二、分模块设计评审**

**1. 核心循环与局长：骨架完整，缺少玩家时间预算**

当前已有准备—战斗—收益—下一轮、每五轮 PVE、100 HP、31 轮上限、人口与阶段掉血。40 局当前规则运行平均 28.2 轮，说明基本能结束；但“28 轮”不能证明一局操作和观看节奏合适。

建议把操作时间、开战等待、观看时间分开统计；按前中后期记录每轮有效决策数。R31 仍存活者按 HP/等级/席位裁决，需要明确预告，并单独统计强制裁决率。局长目标写 28–34 而上限 31 的文档口径应收口。PVE 如果主要提供休息，允许更短的表现，不必每轮强行制造高潮。

验收：真实手动整局时长分布、首场战斗到达时间、提前淘汰后的额外等待、自然决出冠军比例。来源：[回合参数](/Users/bytedance/luobata/PokeTactics/sim/economy.py:17)、[最终裁决](/Users/bytedance/luobata/PokeTactics/tools/acceptance/demo.py:648)。

**2. 棋子、角色与技能：方向成立，身份还没有形成完整阵容路线**

84 只已分配三张专属档案和六类通用技能；其余通用技能主要按种族值定位和图鉴号取模分配。这能迅速覆盖内容，但同类角色为何值得选择，仍缺具体设计。16 只视觉动作的丰富程度不能等同于 16 只独立机制角色。[档案](/Users/bytedance/luobata/PokeTactics/sim/profiles.py:36)、[通用分配](/Users/bytedance/luobata/PokeTactics/sim/skills.py:46)。

建议先完成 6–8 个“玩家能说清作用”的角色：群伤核心、持续单体、前排保护、后排切入、治疗、控制、反治疗/驱散等按需要取舍。每个角色明确强项、短板、适配队友、装备选择和至少一种反制，不必每只发明新原语。用这些角色先做数条完整路线，再决定核心池最终名单。

技能覆盖还需从“有分配”升级到“能发生”：凯西被分配散射，但没有 move_id，实际不能施法。逐角色靶场应验证回能可达、技能触发、行为效果发生；仅验证六个原语在整批实验中各出现过一次不够。

当前随机阵容 3/6/8 人各 200 场，曾施法单位占比仅 32.7%/35.9%/37.2%；死亡单位未放首招占比为 79.8%/77.1%/75.6%。这是随机阵容诊断，不能直接外推成型阵容，但提示“有技能”和“玩家能看到技能贡献”相差很大。优先按角色测存活到首招概率、首招收益、被克制时的可调整空间，再考虑起始能量、受击回能或生存预算。

**3. 战斗、站位与目标选择：先兑现空间决策**

已有 BFS、目标滞回、近战移动补偿、射程与技能位移。除摆位坐标外，还需明确大招独立射程、无法到达的目标何时重选、闪现被围时退化为何种施法、击退碰墙、同刻死亡和施法的先后。档案中的 kite/retreat 只是预留项，不能当作已有远程风筝行为。[行动与目标锁定](/Users/bytedance/luobata/PokeTactics/sim/combat.py:208)。

优先验证三个可理解的站位取舍：坦克保护远程、分散抵抗溅射、集中保护被切后排。让玩家在对手信息足够时能预测调整的作用，再增加复杂战术 AI。棋盘拥堵、双方绕路时间、有效攻击时间应进入日志。

**4. 属性与羁绊：有丰富标签，缺少构筑结构与信息边界**

17 系规则大部分已建表，多数羁绊仍为全队数值加成。按棋子实例计数，重复物种可以叠羁绊，所以“只有一只冰系物种，六冰绝对不可达”是不成立的；真正的问题是角色载体不足、重复上阵可能压过组合多样性。当前池无恶系载体，83 个有招式棋子里没有冰属性招式，冰标签、冰冻与冰系输出不能混为一谈。

R2 必须先裁定同名棋是否重复计羁绊。若改成同名唯一计数，要同步重做阈值和名单；不能保留 2/4/6 表就缩到 28 张。每条路线应有开局替代、转型入口、终局核心、弱点和外挂功能位。建议少量羁绊体现行为变化，剩余保持容易理解的数值，避免 17 条同时复杂化。来源：[羁绊表](/Users/bytedance/luobata/PokeTactics/sim/synergy.py:95)、[全队施加](/Users/bytedance/luobata/PokeTactics/sim/synergy.py:231)。

**5. 齐射/组合技：应作为构筑奖励，避免成为不可交互的开场结算**

当前达到最高档后 t=0 齐射，每队至多一种，必中、不回能、无状态。它能提供成型奖励，但默认在普通行动前结算，可能放大出手边序、提前消灭关键角色，削弱摆位与角色大招的重要性。[开场齐射](/Users/bytedance/luobata/PokeTactics/sim/combat.py:243)。

建议记录开场损血、首个普通行动前死亡数量、齐射对胜率的边际贡献。先解决双方结算公平性；再实验短预告、对称批处理、目标分配或条件触发。暂不扩协奏/承接，先证明现有一种组合技有清晰反制和可见收益。

**6. 状态与天气：机制已有，规则与可读性需要校正**

状态有免疫、占槽、递减与到期机制，首要工作是修复真实触发链。修好后旧平衡可能显著变化，不能用故障期间的数据直接定数值。要分别观察控制覆盖率、连续不可行动时间、首招被压制比例和 DOT/治疗占比。

还要区分模块存在与玩家可用：冰冻缺少当前常规招式来源；光墙、反射壁、剑舞有实验入口，尚无实际角色来源。先把少量控制和保护能力接到明确角色，天气石的命名与实际减伤效果也应一致，然后再评估是否增加反制装备。

天气需在准备阶段展示当前效果和下一轮变化，让玩家有调整窗口；如果只能等开战后承受数值变化，它提供的更多是波动而非策略。天气、围巾、属性、羁绊和多段伤害须用组合测试检查乘区。保留低血量补给等已有追赶机制，再测试逆风阵容是否有恢复机会，而不是仅凭“存在补偿”判定平衡。

**7. 成长、进化与升星：最关键的策略缺口**

当前合成终形态与商店直购终形态使用相同 Piece，没有独立星级收益。追九张基础形态需要金币、备战格和过渡战力，却不产生比直购更强的终局棋。通信进化还占用道具与槽位。这使追卡的投入和终局回报不匹配。[持有实例](/Users/bytedance/luobata/PokeTactics/sim/shop.py:93)。

支持既定的“最终形态直售＋同角色升星”方向。先在小池实现一星可用、二星稳定、三星承担明显机会成本；不要先批量迁移 28 张再验证成长经济。升星后的技能可以在同一语义上提高价值，不应每档变成另一套规则。星级护符必须记账清楚，不能等价于凭空增加多张可出售/回池的卡。

验收：各费段二星/三星形成时间、投入金币、成型前掉血、同行竞争、卖出回池守恒。当前分支进化 bug 应先修，不能留给未来迁移自然消失。

**8. 商店与共享池：已有竞争资源，缺少连续竞争反馈**

当前商店四格、备战六格、共享池有预留与归还。但同费仍有库存的物种等概率出现，剩 1 张与剩 22 张并无命中差异；竞争主要在耗尽时突然体现。[draw_slot](/Users/bytedance/luobata/PokeTactics/sim/shop.py:116)。这是可选设计，不能误称为剩余张数加权。

若希望玩家通过侦察同行决定转型，建议剩余张数加权并给予可理解的竞争信息；若保留均匀物种抽样，应明确说明和验证枯竭突变。补锁店、购买后的羁绊/合成预览、剩余格位提示。满备战时若购买第三张会立即合成，应按最终容量检查，而非一律拒绝。[购买检查](/Users/bytedance/luobata/PokeTactics/tools/acceptance/demo.py:838)。

缩池和改升星必须联动张数、概率与供给目标；至少测 1/2/3 人同行、不同人口等级与连续空刷体验。

**9. 经济、转型和追赶：资源齐全，尚未证明不同策略都成立**

已有基础收入、利息、连胜/连败、刷新、经验、一费无损出售、额外掉落偏向低血量。建议 UI 明示下轮收入拆解，尤其现规则按基础收入之后算息，不能让玩家用错误阈值管理金币。

30 局 seed 2500–2529 中，R25 后存活 bot 平均仍有 42.47 金币。它提示“缺少有效消费目标”或“AI 不会变现”，不能直接证明金币过多。先统计出局存款、可购买升级、刷新边际收益、过渡棋回收损失；升星提供消费出口后再调经济总量。

对照慢刷追星、速人口、保血连胜、可控连败和灵活转型。看早期落后者后续前四率、领先保持率，以及每项投入换来的战力；不要为了局长达标，只反复移动阶段掉血节点。

**10. 装备与奖励供给：先让少量装备改变决策**

8 组件、12 成品、单槽已可用；未来双槽、行为装备、专属装备仍待实施。扩槽前先证明供给足够：通常 R5 第一组件、R10 才有两组件，很多早期决策没有装备参与。

建议先做约六件能改变打法的装备：持续作战、抗爆发、范围输出、保护/嘲讽等；把配方、装备对象和何时合成都作为取舍。无适配棋子的专属件需有回收出口。明确能否拆卸、换装、出售返还，以及复活/吸血/溅射/击杀回能的触发链上限。先修吞装与多段乘区，之后按“有组件且有适配棋时的条件选择率”评估健康度，避免每件平均使用率这种失真指标。

**11. PVE、配对与终局公平性：先定每类回合承担什么任务**

PVE 当前更多是补给：30 局中 R20 为 0/193 败场，R25 为 0/91，R10 反而 29/240。如果定位休息补给，这并不一定有问题；若要做 BOSS 挑战，需要重新设计机制与曲线。

可选方案是保底组件照发，额外奖励来自可选挑战；每个敌方阵容只教一种机制，例如分散避群伤、保护后排、集火关键单位。避免弱者输野怪又失去装备的双重惩罚。

配对除避免连续同对手，还应记录幽灵实际来源。把同轮淘汰作为一批按明确标准排位，避免席位决定先后；统计各席位、幽灵次数、短期重复对手与强制终局比例。来源：[淘汰](/Users/bytedance/luobata/PokeTactics/tools/acceptance/demo.py:635)、[PVE 和追赶掉落](/Users/bytedance/luobata/PokeTactics/sim/match.py:295)。

**12. AI 与难度：需要统一价值模型，不能继续把 L2 当作天然更强**

已有 L0–L3 与四人格，但多组当前实验中 L2 平均名次落后 L1。主线程 40 局：L0 7.92、L1 3.66、L2 4.38、L3 3.98。名次越小越好，这不足以支持现有难度递增描述。

购买、上场、出售、配装的估值还不一致；部分用 profile，部分仍按 BST 或包括备战的羁绊计数；不能继续合成的终形态复制件也可能拿到追卡分。L3 主要做列交换，不等同于完整阵容反制。[上场估值](/Users/bytedance/luobata/PokeTactics/sim/bots.py:545)、[对位](/Users/bytedance/luobata/PokeTactics/sim/bots.py:593)。

先做统一边际价值：角色/星级/真实上场羁绊阈值/装备适配/经济机会成本。L2 做有限候选阵容比较，L3 再做对手反制。验收交叉平衡人格、能力、席位、种子，给出区间与对低一档的稳定优势；人格本身还应在存款、人口、刷新轨迹上可辨认。

**13. 天赋与局内变化：值得做，排在核心闭环之后**

天赋目前只有方向文档，没有选择状态、效果管线、保存恢复与 bot 选择。按既定 R4 先做 9–12 条即可，不必先做 40 条。[分期路线](/Users/bytedance/luobata/PokeTactics/docs/13-core-gameplay.md:175)。

至少覆盖经济、角色行为、阵容转换三种真实选择；候选要看当局适用性，允许有限重选或去掉明显死选项。相同稀有度/预算下避免一个永远更强；稀有度不能替代取舍。新增独立随机流，保存候选与选择；定义重复、叠加、触发次数与循环保护。选项是否有竞争要看适用条件下选择率与后续策略改变，不能只看平均胜率。

**14. 教学、三键与信息：是近期应补的系统**

教学、ABC 三键均有细设计，当前 Web 核心仍是鼠标点击 div。没有实装三键完整旅程；教学首轮“购买即自动上场”和实际“进备战”还互相冲突，旧进化术语也需随 R2 迁移。

先让新手完成买入→上场→开战，再理解一次有效摆位和羁绊变化。用真实状态判断教学完成，少量非模态提示；不要强制读完 17 系规则。角色卡应默认给定位、一句技能与射程，进阶页才展开数值。装备配方不能只藏在 hover title；战斗画布的占位 HP34/13金/Lv5/R13 应替换成真实快照。[角色展示](/Users/bytedance/luobata/PokeTactics/tools/acceptance/demo.py:672)、[占位 HUD](/Users/bytedance/luobata/PokeTactics/tools/mockups/render_battle_gif.py:836)。

三键原型必须覆盖买卖、交换、装备、开战、取消、淘汰、续玩。单击与双击的 200ms 判定需要实机误触测试。验收按键数、完成时长、误操作与恢复，不以“存在键盘播放器”代替游戏三键可用。

**15. 存档、回放与结算：已有方案，但关键数据模型需修订**

Demo 仅内存会话，加载页面直接新开，缺少继续入口。对可以熄屏、碎片游玩的设备产品，轮边界存档是基础能力，应先在 Python 原型验证再移植。快照覆盖共享池、持有实例、商店、库存、坐标、阶段、刷新计数与淘汰顺序。[会话管理](/Users/bytedance/luobata/PokeTactics/tools/acceptance/demo.py:1008)。

当前 seed-only 历史重演方案不够：人类的买卖、刷新、配装和摆位不由 seed 决定。需要版本指纹＋玩家动作日志，或关键轮战前快照/事件流。测试同 seed 的两条不同操作轨迹，不能把它们重演成同一局。[现有回放设计](/Users/bytedance/luobata/PokeTactics/docs/11-onboarding-results.md:323)。

淘汰前先保存最终阵容，不要先清空再想生成结算。最小结算展示名次、最终队伍、淘汰对手与掉血、角色伤害/治疗/施法次数，并可回看淘汰轮。先报可验证事实，再做败因推断；避免用相关统计武断告诉玩家“输是因为没升人口”。

**16. 局外目标、音频与设置：补轻量留存，避免数值负担**

图鉴、成就、训练家卡、生涯统计已有方案，尚未接入。先做核心池见过/用过/升星过，以及引导尝试不同阵容的成就；旧版鲤鱼王进化、五费传说等目标需随 R2 改写。坚持局外不加战斗数值的方向。[局外设计](/Users/bytedance/luobata/PokeTactics/docs/12-pool-and-meta.md:178)。

普通玩家入口每次新局应生成新种子，固定 seed 保留给验收/挑战模式。当前默认 7 会让反复开新局仍重复相同开场。音频目前只有离线样带，先接购买、操作失败、开战、施法、淘汰等高信息音效，再接场景 BGM。补音量、默认倍速、弱化闪光/抖动与继续游戏等基础设置，不需要先增加更多曲目或局外货币。

**17. 架构、设备与验收：将“能复现”升级为“各入口同规则”**

Python 零依赖模拟与事件回放分离值得保留。但 Match 与 Demo 各自维护整局规则，已经发生天气与装备规则漂移。建议共享规则配置、命令处理、阶段控制器；展示层只消费结果。事件采用明确类型与版本，区分普攻、技能侧击、齐射及其是否回能/触发状态，避免复用 attack 后被错误理解。

随机种子分层已有，但 [RNG 文档允许各端 PRNG 不同](/Users/bytedance/luobata/PokeTactics/sim/rng.py:17)。相同 seed 不保证不同算法产生相同事件；若要求 Python/C 对账，应统一 PRNG、抽样/洗牌算法、整数取整、tick 和同刻顺序，或者明确只对固定输入事件做渲染对账。seed、ruleset、数据版本、动作日志共同构成可复现记录。

Web 目前先生成整场 PNG，全部加载才播放。200 张 240×320 RGBA 的解码像素约 58.6 MiB，不代表 ESP32 231KB 堆下可行。先做首段缓冲即播与有界缓存，再做满人口 9v9、天气、状态、音频同时运行的设备预算纵向样机。当前没有 C/ESP-IDF 产物，这是已暂缓的目标，不应宣称双端已交付。[整场生成](/Users/bytedance/luobata/PokeTactics/tools/acceptance/demo.py:163)。

资源还依赖相邻 PokeWalk 仓库和 Pillow；sim 零依赖不等于 Demo 零依赖。试玩分发应补资源打包、版本校验与启动诊断。[素材依赖](/Users/bytedance/luobata/PokeTactics/tools/mockups/decoders.py:15)。

现有自测适合 API 与 PNG 冒烟，但没有覆盖真实手动 UI 旅程。新增验收优先级：规则守恒与状态链、准备/开战坐标、淘汰出口、保存恢复、镜像公平、当前配置指纹；之后才是更多视觉像素指标。平衡实验用配对种子、阵营交换、样本外种子和置信区间，稀有属性小样本不宣布强弱。

**三、实施顺序与完成标准**

| 顺序 | 工作包 | 到什么程度才继续 |
|---|---|---|
| A · 当前体验与规则修复 | 摆位、淘汰出口、状态事件、伤害包、射程、镜像偏置、分支进化、吞装、能量回放、天气与实验配置 | 所有已复现问题有行为回归；同状态同操作在各入口一致；旧健康读数重新建立 |
| B · 最小策略闭环 | 小核心池、独立升星、明确角色卡、数条完整阵容、商店锁定、统一 AI 估值 | 追星/升人口/转型存在真实机会成本；玩家能解释核心角色和一次调整；AI 难度不持续倒挂 |
| C · 可持续试玩 | 首五轮教学、三键原型、轮边界存档、淘汰结算、关键轮复盘 | 首次玩家能独立打完；刷新/退出可恢复；输后能提出有依据的下一局尝试 |
| D · 构筑扩展 | 少量行为装备＋供给调整，再做 9–12 条天赋；PVE 明确补给或挑战定位 | 选项有竞争、没有普遍死件、触发链有界、供给和反制可解释 |
| E · 产品与设备 | 图鉴成就、音频、设置、资源分发、C/设备纵向样机 | 有明确性能预算与跨端契约，再决定扩到 28 只及更多内容的节奏 |

C 的三键与存档原型、E 的设备预算探测可以和 B 并行，不必等全部玩法定稿。当前不建议优先做联网排位、四五费大扩池、长线战力养成、40 条天赋或完整专属装备大全；前几项与已裁定范围冲突，后几项会放大尚未闭合的规则成本。

随机阵容采样：每档 i=0..199，组队 RNG=`20261004+i`，战斗 RNG=`50000+i`，当前默认规则；`dead_without_cast` 分母为死亡单位。上述数据包含现存规则缺陷，修复后必须重建，不能作为最终数值目标。
