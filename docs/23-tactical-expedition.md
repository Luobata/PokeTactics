# 23 · 战术远征：护卫、共享天气与奖励合同

2026-10-05，`tactics_v1` 可试玩原型。对应 [系统联动评审](22-system-interactions-and-playstyles.md)
的 D03、D06、D08、D14、D15 子集。[本批结果](../reports/system-optimization-batch-h-2026-10-05.md)
分别记录功能通过、数值未达标和后续工作；不代表四个设计批次全部交付。

第九批：**新开战术远征已使用 `tactics_v2`**，额外加入九尾日照、拉普拉斯降雨的入场天气。
已有 `tactics_v1` 存档继续本节原合同；下文的单一天气手名额和每队一次限制均指教学，
不会限制固定物种特性。入场相抵、教学共存及版本边界见 [24 号合同](24-evolution-builds-and-opening-abilities.md)。

## 1. 入口与资源

设备模拟页 `/device` 首页选择「战术远征 · 护卫与天气」，选择主搭档后出发。
它沿用远征的种族值预算、搭档、经济、卡池和行囊；第八批使用 `tactics_v1`，当前新开局使用 `tactics_v2`。
经典和原远征仍为 `base_v1`，已有对局不会自动升级。

野怪轮结算后，原本的一台技能机变为三选一；数量不增加。候选先写入存档：
固定包含护卫，另有一项与当前持有棋子相容的教学，第三项从其余教学中产生。
领取一项或明确放弃后才可开始下一场；取消、返回不会领取，也不会重抽。
每只棋子保留一个教学槽，替换、卸下、卖出和合并沿用现有返还与守恒规则。

| 教学 | 可学习对象 | 生效条件与代价 |
|---|---|---|
| 护卫 | 所有宝可梦 | 学习后上场，指定四向相邻队友；占一个教学槽、全队唯一护卫名额 |
| 晴天 | 火或草属性 | 学习后上场，指定为全队唯一天气手；首次原生大招后申请天气 |
| 求雨 | 水或电属性 | 同上；电属性可学不意味着电伤获得雨天加成 |

居合斩、冲浪、睡觉仍在候选池内。普通宝可梦也能承担护卫或天气岗位，
不要求主搭档身份。主搭档特性仍按原合同触发，教学不替换原生大招。
机器人使用同样的实体奖励、相容性、教学槽和有效名额，没有免费教学。

## 2. 两个天气队相遇

天气是全场共享状态。战斗开始时记录基础天气；新教学制造临时覆盖，双方同样受影响。
当前原型一次覆盖持续 **8 秒**，数值尚未完成平衡。

| 事件 | 权威结果 |
|---|---|
| 晴天先触发，求雨后触发 | 晴天先取得窗口；后一次求雨生效时改为雨天，重新计算自己的 8 秒窗口 |
| 同一模拟 tick 一晴一雨 | 统一收集后相抵，恢复基础天气；双方本场机会都已消耗 |
| 同种天气先后或同时触发 | 取较晚结束点，不把两段时长相加 |
| 覆盖到期 | 恢复基础天气；不恢复上一个已经被覆盖的教学天气 |
| 天气手施法前阵亡 | 本场不能发出天气请求；其他天气教学者不会自动接替 |
| 已请求后阵亡 | 已发出的请求仍按下一 tick 结算；已经生效的天气继续到期 |
| 基础天气本来就是晴或雨 | 冲突/到期回到该基础天气，不强制变成无天气 |

请求在原生大招结算后产生，下一模拟 tick 才统一生效；不能反过来加强发起它的那次伤害。
同 tick 冲突不按玩家/机器人席位或遍历先后判胜。每队每场至多请求一次，
多名棋子学天气也只有准备期选中的一名生效。

现有天气倍率继续作用于带属性技能：晴天火/草伤害 ×1.20、水伤害 ×0.80；
雨天水伤害 ×1.20、火伤害 ×0.80；无属性普攻不变。这是本项目规则，不照搬原作。
目前不增加雨天电伤加成、沙暴持续伤害、冰雹冻结或天气天赋。

这样会产生三类联动：

- 启动装备和回能搭档影响抢到第一段天气的时点；晚施法也可能覆盖对手，但要承受前一段压力。
- 护卫与站位可以争取天气手活到首次施法；选择天气会放弃该棋子的其他教学收益。
- 晴天可能帮助敌方草/火单位，雨天可能帮助敌方水单位；混合阵容与击杀天气手都是应对方向。

这些是规则允许的决策空间；固定阵容实验尚未证明各路线均有强度价值。

## 3. 护卫的精确边界

每队一名护卫，每场一次。准备期要求护卫和保护对象四向相邻；战斗中触发时也必须仍相邻。
只有敌方 `charge` / `blink` 实际发生非零位移、准备命中所保护队友时才可能拦截。
攻击者必须原本能合法攻击该目标，拦截者仍存活且距攻击者不超过两格。

一次拦截仅把这次主命中转给护卫，不增加伤害减免，不移动护卫，不永久改变敌方索敌。
普通普攻、无实际位移的突进、范围外目标、已死亡/走散的护卫都不能触发。
拦截机会在命中或闪避判定前消耗，闪避不会退回次数。

伤害、控制、受击回能、披带、死亡及主命中派生效果均按最终目标结算一次。
溅射可以继续波及原保护对象，因此护卫不等于整队免疫范围伤害。
表现事件记录真实攻击者、护卫、保护对象和当时位置；护卫连线与被转移的命中同步。

## 4. 三键完整路径

A/B 选择，C 确认，长按 B 返回。重要提交沿用先预览、再确认；重复松键不重复提交。

1. 野怪轮后进入「仓库与教学 → 待领补给」，选择一台技能机或明确放弃。
2. 「招式机器 → 教学 → 棋子 → 确认」完成学习；不相容对象给出原因。
3. 「棋盘与备战 → 棋子 → 战术配置」选择护卫对象或设置本队天气手。
4. 棋盘显示护卫关系和天气手标记。备战席棋子不能直接担任有效岗位。
5. 开战后观察护卫实际拦截，或天气的开始、覆盖、冲突、结束及剩余时间。

配置使用实例 UID。移动后仍合法则保留；卖出、替换教学、进入备战席、合并移除实例，
或护卫失去相邻关系时，关闭无效配置并提示重选。不会把原选中对象悄悄换成另一只棋子。
页面过期、确认期间存档序号变化时，旧选择失效，资源不扣除。

## 5. 存档与模块边界

存档 schema 为 4，保存规则版本、实例配置、已冻结的奖励、已领取状态和对手快照。
领取、学习、岗位配置与存盘处于同一操作事务；写失败回滚，恢复不重复发奖。

已识别的 schema 1–3 基线迁移到 `base_v1`。仓库保留真实 schema 3 固定样本，
其后续购买、移动、刷新、开战、下一轮的经济状态和 102 条战斗事件与旧代码一致。
这只证明已识别基线的兼容；未知规则指纹拒绝续玩并保留原档，也不能静默退到更旧备份继续。
未来修改基础数值时仍需明确版本处理器和迁移合同，不能只改版本名。

| 模块 | 职责 |
|---|---|
| `sim/tactics.py` | 显式规则版本、每队护卫/天气名额和索引校验 |
| `sim/weather_control.py` | 有界请求、同 tick 裁决、覆盖和过期；不计算伤害、不消费 RNG |
| `sim/combat.py` | 合法战斗触发、伤害归属与权威原因事件 |
| `tools/acceptance/demo.py` | 奖励与学习事务、UID 配置、机器人同规则参与 |
| `tools/mockups/animation_timeline.py` | 原始事件到演出时刻的映射；不反写战斗状态 |
| `esp32_runtime/` | 原有存储、备份、输入与有限轨道通用能力 |

宝可梦相容性、天气伤害倍率和羁绊留在游戏层。当前是 Python host 参考实现，
未新增 ESP32 GPIO/NVS/C 渲染后端，也没有硬件帧耗时或真人三键时长验收。

## 6. 验收与剩余范围

自动合同覆盖天气同刻冲突、覆盖、过期、阵亡先后、换边、护卫范围/闪避/派生伤害，
以及真实奖励、学习、配置、取消、重复确认、保存恢复和旧规则回放。
天气 HUD 只能依照已发生事件计时；相同事件前缀不能泄露未来覆盖。
护卫后的冲浪副包跟随主命中，后续独立普攻仍保持独立动作。

本批只认领可试玩原型的功能与兼容合同。反突进强度目标未通过；完整成型评估、
三键人工体验、训练、角色岗位与过渡卡表、小天赋池、机制羁绊、后期压力和体系挑战继续待办。
具体实验、通过项和未通过项见交付报告，不能以单元测试全绿代替玩法验收。
