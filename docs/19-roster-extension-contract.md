# 19 · 全上场池与新增物种合同

2026-10-05，第五批。当前上场池保持 84 只；本批没有增加商店人口或新世代素材。
新增物种不要求先制作专属部件，但必须具备可执行规则和有效精灵资源。

## 能力分层

| 层 | 当前能力 | 新物种的默认路径 |
|---|---|---|
| 战斗 | 8 专属、76 通用技能；全部可施法 | `skills.skill_of` 按定位和稳定物种 ID 分配六种通用原语 |
| 招式载荷 | `resolve_cast(piece)` 是施法入口 | 优先学习表伤害招；无伤害招且启用通用技能时，使用独立的无属性 40 威力载荷 |
| 身体 | 16 手编动作，其中 3 套已实现部件；68 程序化 | 呼吸、移动、准备、出手、受击与死亡；普攻服从统一演出时间轴 |
| 部件 | 每个物种自己的部件、支点、层级与挂点 | 无专属 rig 不影响出场；已有手编动作但缺切片 rig 时退整图变换 |
| 技能视觉 | 8 分层演出、16 手编招式视觉（含这 8 只） | 按技能原语使用通用特效，不自动获得专属美术 |
| 编辑器 | 84 只普攻/大招预览；8 只可调四参数 | 自动读取上场池，通用角色默认预览，未支持的参数不能提交 |
| 资源 | 151 只正面精灵及色板 | 缺失、截断、全透明精灵或缺色板明确报错，不标记为就绪 |

凯西和百变怪的原始 `move_id` 仍为 `None`，不会把自走棋通用技能写进学习表。
新载荷使用当前较强的物攻/特攻和对应防御，仍受正常伤害、装备、能量规则约束。
关闭档案功能时，无学习招单位保留历史仅普攻行为。有原始招式的单位不改伤害公式。

`character_catalog` 独立返回 `body/effect/resource_ready/resource_errors/actions/editable_controls`。
API、编辑器和资源清单读取相同资料；“能上场”“有专属机制”“有专属部件”分别统计。
画面和调参不回写战斗状态。通用附属伤害、治疗、击退继续读取真实战斗事件；编辑器
的专属效果记录栏只列 `skill_effect`，没有该标记不等于通用技能未触发。

## 新增物种步骤

1. **补规则数据。** `data/pokemon.json` 提供 ID、名称、属性、种族值、lineage 和学习表；
   所引用的招式必须存在。现有 17 属性采用 Gen2 分类；新属性、现代物理/特殊分类需另做规则迁移。
2. **决定是否入池。** `CURATED_FAMILIES` 选择进化族，`build_roster()` 自动展开所有已加载族员，
   并按物种去重。已有族新增进化会自动扩大池，例如给飞天螳螂族补 #212；发布时必须审查池分布，
   不能把图鉴数据更新视为不影响商店。仅存于图鉴的其他族不会自动入池。
3. **补素材。** FRNT 记录支持正 uint16 ID；PALS v1 仍是按 ID 的连续映射，要扩到最大新增 ID。
   精灵尺寸沿用 40/48/56、2bpp 与透明索引 3。新增中文名称/技能还需检查 FNT1 字形，
   当前精灵就绪字段只校验精灵和色板，不能替代文字覆盖验收。现有提取工具仍针对 Gen1，
   新增世代需要更新素材生产流程。
4. **先验收通用路径。** 不新增 `HEROES` 前端名单，不复制 75 份动画。验证真实普攻、施法、移动、
   受击、死亡、命中时序与资源错误；`character_catalog` 自动将入池角色加入页面。
5. **再提升特色。** 可单独补 profile 数值/射程、专属技能、手编整身动作、物种部件和挂点。
   partial profile 中未填字段使用中性缺省；只有提供 `ult.arch` 才判专属。
   强烈改变轮廓的动作仍要补帧或独立素材，不能靠切片获得被遮挡的身体。
6. **复测经济与阵容。** 现有三费档、商店概率、池份数不会因新 ID 自动扩展。
   增加第四档、新进化条件或通信进化名单时，必须同步相应规则与验收。

## 验收命令与条件

```sh
python3 -m unittest discover -s tests -v
python3 sim/experiment_profiles.py --games 20 --seed 31
python3 tools/mockups/animation_showcase.py --out .build/animation-e --species 1,2,10,12,31,75,63
python3 tools/mockups/roster_showcase.py --out .build/animation-e
python3 tools/acceptance/system_acceptance.py --demo --balance --presentation
```

自动用例覆盖全 84 只真实满能施法和演出阶段、同种子帧一致且不改事件；模拟层还覆盖
全 151 图鉴载荷、无学习招和注入新 ID。资源扩展用合成二进制验证，不冒充新增真实美术。
6v6 混编样本使用自然回能，部分角色会在施法前阵亡，这是正常战斗结果；不能拿预充能
靶场推断实际每只必定释放技能。

## 通用 ESP32 框架边界

资源索引与校验、动作时间轴、姿态采样、挂点、预算属于可复用运行时；宝可梦图鉴、
族谱、商店选择、技能原语和部件配置属于游戏内容。此批完善了 Python 参考实现和能力合同，
没有交付 C 采样器、ESP32 绘制/缓存后端或真机预算。存档/备份沿用此前抽出的运行时，
未增加存档格式版本。剩余部件轨、逐部件关键帧编辑与数值平衡继续单独验收。
